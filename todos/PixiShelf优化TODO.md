# PixiShelf 优化 TODO

这个文档只记录尚未完成、可逐项推进的优化任务。完成历史由 Git、测试和对应设计文档保留。

## P1：性能与可观测性

- [ ] 数据库写入热点排查
  - 目标：确认批处理里的 artist、tag、image、raw metadata 写入是否有明显瓶颈。
  - 验收：
    - 有一份简短结论：瓶颈在哪、是否值得改；
    - 如果不值得改，记录原因，避免反复讨论。

## P2：类型与质量门禁

- [ ] API response 类型统一
  - 剩余范围：设计并迁移 scan/rescan 和更广泛 API 的失败响应。
  - 验收：
    - 前端调用能拿到明确类型；
    - 错误 response 包含稳定的 `message`；
    - 迁移期间兼容现有前端对 `{ error }` 的依赖，不引入无计划的 API 行为变化。

## 建议执行顺序

1. 数据库写入热点排查
2. API response 类型统一

## 每项开始前的固定检查

- 先确认本项是否会改变用户可见行为。
- 如果改变行为，先写设计或验收标准。
- 优先补测试，再改实现。
- 每次只处理一个主题，避免“顺手优化”扩散。
- 完成后至少跑窄范围测试；核心扫描链路变更再跑 typecheck、lint、完整测试和 build。
