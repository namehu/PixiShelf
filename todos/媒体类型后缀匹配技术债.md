# 媒体格式与兼容判断技术债

## 当前状态

原始待办中的“结构化媒体类型”已经实施，不再把整项重构视为未开始：

- `Image.mediaType` 使用 `IMAGE / VIDEO / ANIMATION / UNKNOWN` enum，并建有查询索引；
- 主应用的 `inferMediaTypeFromPath` 已被扫描、批量导入、人工增换媒体和待替换发现复用；Worker 内部仍有独立推断实现，不能视为跨包规则已统一；
- 作品列表的图片/视频筛选已查询 `mediaType`，视频探测、章节预览等后台任务也优先使用该字段；
- `VIDEO_MEDIA_PROBE` 可分页处理历史 `UNKNOWN` 数据。是否已完成特定生产库的全量回填，应以部署记录和数据审计为准。

## 剩余 TODO

### 1. 统一跨包媒体推断契约

主应用、Worker 扫描、视频探测和待替换快照目前仍有多份扩展名推断。其中主应用会先把 WebP 写为 `IMAGE` 并等待内容扫描，Worker 待替换快照则会直接写为 `ANIMATION`。需要先定义可共享的粗分类与内容探测语义，再消除重复实现，并用同一组 fixture 覆盖 JPG、PNG、GIF、WebP、APNG、MP4、WebM 和未知扩展名。

跨包契约不应仅通过导入主应用内部模块共享；应放在 App 与 Worker 都能依赖的现有契约或共享包边界中。

### 2. 评估结构化格式字段

当确有按格式查询、索引或派生规则需求时，再评估为 `Image` 增加 `format`。字段不应和 `mediaType` 重复表达，需要明确至少以下取值与回填规则：

```text
mediaType = IMAGE,     format = jpeg
mediaType = IMAGE,     format = webp
mediaType = VIDEO,     format = mp4
mediaType = ANIMATION, format = apng
```

如果继续仅有管理页的低频扩展名筛选，现有后缀查询可以保留，避免为无实际收益的字段增加 migration 和写放大。

### 3. 有证据后退役 fallback

输出 DTO、封面和视频处理仍会在 `mediaType = UNKNOWN` 或旧数据缺失时按路径后缀 fallback。只有在下列条件都满足后才删除：

- 生产数据审计证明受支持媒体没有 `UNKNOWN`；
- 所有新增、替换、扫描、导入和恢复路径都写入正确类型；
- 回滚镜像不再依赖缺失或 `UNKNOWN` 类型。

### 4. 可选的模型命名调整

`Image` 实际承载图片、动画和视频。改名为 `Media` 会影响 Prisma relation、DTO、API、执行器与 UI 命名，只在能够独立迁移和回滚时开始，不与 `format` 字段改动合并。

## 验收标准

- 主应用与 Worker 对同一媒体 fixture 产生相同的初始类型和后续探测意图；
- 格式字段只在有明确查询或派生收益时引入，并具有分批回填、审计与回滚路径；
- fallback 的移除由生产数据证据驱动，不假设 migration 默认值等于真实类型；
- `Image` 表重命名保持为独立、可回滚的工作项。
