# 作品摘要浏览

实现位于本地分支，生产尚未部署；真实作品质量和目标 NAS 性能验收尚未完成。本文区分可验证的实现行为与发布门槛，不把合成样本或开发机结果当成生产结论。

## 产品与交互

大量连续差分图片可以按相似程度叠成组，以每组第一张代表连续内容。仅沿原顺序合并相邻静态图片；不跨组聚类、不随机抽取、不承诺十张选一张。姿势、服装和主要内容变化优先保留，允许微小表情和细节折叠。分组是可展开的浏览索引，不删除、重排或转码原文件。

每次进入详情默认完整模式。用户点击“生成摘要”后只为当前作品入队，页面继续阅读；完成后手动选择“摘要”。不扫描全库、不在导入时自动运行。单图组正常显示，重复组使用两道轻微叠页边缘、图下原序号范围及“展开其余 N 张”。图片保持原比例，点击图片仍打开预览。可同时展开多组；组首、组尾及现有媒体快捷导航提供收起入口。切换模式、展开和收起会暂停自动浏览并按媒体 ID 定位。

浏览切换采用现有工具条和页面阅读信息区；滚动后进入现有顶部栏，不增加悬浮工具栏。控件使用至少 44px 命中范围，支持键盘。详情、适应屏幕预览与自动浏览共享“代表图 + 已展开组”的同一序列。独立沉浸浏览器不改变。

“只看未读”冻结当前未读 ID，在原分组内取交集；不重新聚类。原代表图已读时，以组内第一张剩余未读图片作为临时代表。继续阅读定位到折叠组的内部图片时，自动展开该组。隐藏图片不挂载图像元素，不请求隐藏图像的像素；轻量分页元数据仍按现有阅读器窗口加载。

## 阅读记录

用户确认的规则：折叠组的代表图满足现有可见阅读条件后，整组计为已读。展开组按实际看到的图片记账；展开不会撤回以前已经授予的整组已读。

客户端 VIEW 可附带 `summary: { generationId, groupId }`，不接受客户端传来的成员名单。服务端在同一事务中锁定作品和摘要，核验当前源版本、发布版本、算法版本、实际观察图片属于该组，以及组成员仍存在，随后从已发布快照取成员授予已读。摘要过期时返回 `ARTWORK_SUMMARY_CONFLICT`，阅读器清除待提交投影并提示重新打开。

一次真实观察只记录一次阅读活动；隐藏成员不会伪造 VIEW、时间或最后位置。阅读次数继续按原有 30 分钟访问间隔计算。新增图片使快照失效，且不会继承旧组已读。第一版不提供撤销已读、手工拆组或灵敏度调节。

## 生成和算法

`ARTWORK_SUMMARY_GENERATE v1` 使用现有持久队列的 BACKGROUND_WRITER lane，手动优先级 90。该优先级只比默认手动任务低，不表示低于所有系统任务；公平性由批间延迟提供。后台任务页可暂停、恢复、取消及查看失败。

1. 入队时锁定 Artwork，复用活动任务与请求幂等键，记录 generationId 和 sourceRevision。
2. 按逻辑媒体原顺序处理。APNG/video 配对保持现有逻辑，动画、视频、解析失败或超限文件作为单独项保留。
3. 独立子进程读取原图，Sharp 并发 1、关闭缓存，取得 32×32 sRGB 图、64 位感知哈希、8×8 空间色块和方向修正后的比例。
4. 初始阈值：比例变化不超过 2%，哈希距离不超过 4，平均色块差不超过 8，任一局部色块差不超过 28。必须同时与前图和组首比较，阻止相邻小变化累积造成整组漂移。这些是待校准参数，不是已经证明的语义识别能力。
5. 每张特征保存后可恢复；每批至多 10 张或累计 5 秒，在当前图片结束后让行至少 5 秒。
6. 完成时在队列租约 fence 和数据库事务内核验 generationId、源版本及写入门禁后一次发布。不会展示半成品组。

`ArtworkSummaryFeature` 按 imageId 保存特征、算法版本及源证据；源证据包含路径、大小、mtime、ctime、设备与 inode。相同证据可复用特征。用户“重新生成”强制重新读取，即使文件属性未改变也不使用缓存。

## 针对目标 NAS 的资源边界

用户确认设备：i5-4210M，2 核 4 线程，12GB DDR3；原图通过 NFS 来自另一台 NAS 的 8TB 机械盘。当前没有该 NAS 的实测数据。

- 全局 writer lane 串行执行，摘要内部并发 1；不用 GPU、视觉大模型或额外模型服务。
- 每图最多 64MiB、40MP、10 秒；字节和像素限额是输入限制，不代表进程 RSS 限额。
- NFS realpath/lstat/open/read 和原图解码全部在子进程中，父进程继续处理队列心跳和取消。
- 到期终止子进程；若内核 NFS 等待导致进程未退出，禁止拉起替代子进程，任务进入需人工处理的暂停状态。
- 解码失败保留单项，不阻断整部作品；页面显示无法比较的数量。
- 页面读取已有摘要不遍历 NFS stat。外部直接修改文件需要重新扫描或强制重新生成。

## 失效、迁移和恢复

新增表 `ArtworkSummary`、`ArtworkSummaryFeature`，以及 Image insert/update/delete 触发器。图片归属、路径、大小、尺寸、顺序、类型或动画分类改变时递增摘要源版本；常规 updatedAt 刷新不失效。扫描复用已有 stat 证据检测同路径覆盖。上传及替换在写文件前设置持久门禁，完成或验证回滚后才清除；中断不按超时自动解除。

发布需先按[备份基线](../operations/backup-and-recovery.md)停写并记录同点数据库、媒体、配置、镜像；使用 generate/deploy，禁止 db:push。迁移仅加表与触发器，不改变原图和已有阅读行。源码在隔离空 PostgreSQL 上验证完整历史迁移，不能替代已有生产库升级演练。Worker 能力清单增加到 34 类 / 39 个 type-version 组合，App 和 Worker 必须同步更新。

摘要和特征可重建；组阅读结果属于用户记录，不随清除摘要自动撤销。恢复时摘要门禁、版本和原媒体必须来自同一恢复点。普通上传中断应完成原上传或按既有替换恢复流程核实文件；不要直接清除门禁以复活旧摘要。回退到旧版本时先停止新任务和新写入者；恢复需要保持新表、触发器与读记录的一致性，不能把删除派生表等同于撤销组已读。

## 发布验收

自动化覆盖顺序、非相邻重复、漂移、局部变化、未读投影、组已读版本拒绝、子进程超时、源失效、队列分批与最终发布。浏览器需验证桌面和移动端、展开/收起、切换定位、预览、自动浏览、继续阅读、未读筛选、任务状态和失败回退。

质量门槛：人工独立标注 20 部真实作品，固定 10 部调参、10 部保留；冻结参数后评估保留集。每部关键变化边界保留率 ≥95%，标注的长距离差异对不能被同组折叠。报告每部压缩率，不设最低压缩率，不以保留全部图片伪称“摘要有效”。标签包含 artworkId、generationId、split、boundaryBeforeMediaIds 和 distinctPairs：

```bash
DATABASE_URL=... pnpm --filter @pixishelf/next exec tsx scripts/artwork-summary-calibrate.ts labels.json > summary-quality.json
```

NAS 门槛：同一组作品、同一客户端网络、相同冷热缓存条件分别测空闲和摘要运行时的页面/首图 p95，退化不超过 20%，不增加失败；同时记录 CPU、RSS、NFS 吞吐与队列等待。至少分别覆盖 300 张和 1000 张作品以及暂停、取消、NFS 不可用。原始样本、时间区间和测量方法随报告保存。开发机合成样本不计入上述质量或 NAS 门槛。

## 本地验证记录（2026-10-21）

开发完成后由 `gpt-6.1-sol / xhigh` 子 agent 独立审查代码，并在隔离 PostgreSQL、合成图片和真实应用页面上完成桌面 1280×720、窄屏 390×844 的浏览器复验。发现并修复了折叠过程中误授予已读、末组无法顶对齐导致操作锁住、快照更新丢失位置、未读临时代表误展开、预览记账被详情可见性阻断、PNG 内嵌 APNG 识别、子进程超时/迟到响应、取消竞态和批量替换预写门禁问题。最终复验没有新增待修复缺陷。

实际浏览器确认：分组展开/收起保持位置且不误读后续组；预览键盘导航和自动浏览沿摘要序列运行；未读交集冻结；续读内部图片自动展开所属组；双标签重新生成后仍定位原媒体；界面没有溢出、遮挡或新增浏览器错误。真实手机触摸，以及后台任务暂停/恢复/取消/失败的逐项 UI 操作未在本轮浏览器测试中覆盖；相关队列状态由后端回归验证。

主应用 lint、类型检查与生产构建通过，400 个测试文件的 2746 项测试通过；默认测试命令中 210 项依赖环境的测试跳过。执行器 780 项、Worker 101 项测试通过，相关依赖包检查通过；隔离 PostgreSQL 额外验证摘要分批/发布/取消/异常暂停及替换门禁共 6 项，源失效触发器也已验证。完整历史迁移已在隔离空库应用。实际打包的 CJS Worker 启动为 READY，34 类 / 39 个版本能力审计通过，并真实解码两张合成图片、发布一个摘要组，失败单项数为零。

上述记录证明本地实现和回归结果，不代表真实作品边界保留率、目标 NAS 性能或已有生产库升级验收通过；这些发布门槛仍然待完成。
