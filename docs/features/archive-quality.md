# EH 归档画质

EH 发现扫描取得的文件大小是**原站整部作品**的字节数。发现列表从扫描快照读取该值，从发现入箱时携带，收件解析后以解析结果为准。来源缺值表示未知。作品详情另行统计当前本地媒体的实际大小。选“前 20 张”时，整部大小仍包括其余页。

新归档默认选择缩放展示版。任务的请求画质表示下载意图，逐页归档画质表示实际交付的文件版本。用户选原图时，下载器识别同源的新版及旧版原图入口，登录失效、额度不足或无法证实为原图时暂停。登录态管理见[权限边界](../security/access-control.md#凭据与剩余风险)。

## 根据归档记录核验

后台按批处理当前生效的 EH 修订，保存进度及逐页结果。核验只使用数据库中下载和发布时的记录，可离线运行。它不会请求原站、读取 NAS 图片或自动重新下载。核验时间指记录核对时间，磁盘文件的实际字节另在升级复用和清理前校验。

管理员从归档任务页的“历史画质核验”，或作品“保存的图片”下的具体原因进入系统设置中的“归档画质核验”；直达路径为 `/admin/setting?tab=system#archive-quality`。该入口可发起或继续核验，后台任务页可暂停、取消或查看进度。每批保存游标后让出 Worker；暂停和失败重试从已提交批次继续，取消保留已核验结果，后续可重新发起全库核验。新发布在同一事务写入逐页证据和活跃修订汇总，尚未执行识别时显示“尚未识别图片版本”。已经执行但证据不足时显示“无法确认”，不暗示仍有任务排队。

每页先对应同一修订中的成功下载项，核对最近下载地址所属尝试、文件字节数、SHA-256 和媒体快照，再核对当前 Image 身份、顺序与路径。只在成功交付的可信 H@H 节点地址中按规定位置解析文件描述。格式、尺寸和字节数须与实收记录一致。

早期发布快照没有 `imageId`，不因此视为损坏。只有当前修订可用同一作品的完整文件路径、页序和字节数唯一匹配当前 Image，再继续核对同一修订的成功下载记录。证据通过 `imageIdSource: CURRENT_IMAGE_PATH_ORDER_SIZE` 标明身份来自核验时的匹配，不补写历史快照。快照已有 ID 时仍严格核对该 ID，不能改用路径匹配掩盖冲突；非当前旧修订缺少 ID 时保留无法确认。原图升级复用仍要求原快照冻结的身份，不能仅凭这项兼容匹配放宽复用条件。

| 交付证据                                                     | 归档画质       |
| ------------------------------------------------------------ | -------------- |
| `/om/` 同时给出原文件描述和 `x`                              | 原图           |
| `/om/` 有不同摘要的原件与派生件描述，实收记录对应派生件      | 缩放展示版     |
| `/h/` 文件描述与实收一致，交付参数标明 `xres=org`            | 原图           |
| `/h/` 明确标注支持的数字缩放档，实收与描述和宽度相符         | 缩放展示版     |
| `/h/` 为支持的数字档位但宽度不同，同页原图说明与实收文件有差异，且实收 SHA-1 与交付描述吻合 | 缩放展示版 |
| 旧记录缺少地址、尝试不符、字段冲突、来源身份或当前页无法对应 | 待核验，附原因 |

数字档位须属于当前解析器支持的集合，且交付描述、实收尺寸和字节数通过核对；其中包含实际归档记录出现的 800 档。不支持的档位、交付宽度与档位不一致、重复参数和相互矛盾的参数分别保留原因。宽度小于档位本身不证明原图或展示图，缺少原件对照时仍待核验，不能把它描述成两个档位互相冲突。

普通阅读下载也保留同一次图片页返回的原图尺寸和大小声明，存入成功回执的 `sourceOriginalClaim`。它仅作原件对照，不充当原图下载成功的声明。图片页所选文件与最终响应地址相同，或两者可信文件描述的 SHA-1 相同时才携带该对照。对于支持档位但宽度不同的交付，必须再核对实收 SHA-1、字节数、尺寸和格式；原件声明与实收存在差异时可确认网页阅读版。原件大小按页面展示精度保存区间，因此不把四舍五入差异误当作压缩。尺寸或区间一致不足以证明原图，真正的参数冲突也不能被该对照覆盖。

对照信息随成功尝试写入下载记录，再进入发布证据，之后离线核验不需重新请求图片页。历史回执缺少此信息时不能从新版代码凭空恢复；后来重新访问原站获得的说明属于新的在线观察，不回填成旧下载时的证据。

核验规则更新会重新解释保存的原始交付事实。旧版曾把上述不同情况统称为 `CONFLICTING_HATH_XRES`；仅当旧规则能够从同一成功记录重现该结果时，允许按新规则重新判定。尝试、地址、摘要、字节数及发布映射的核对保持有效，其他凭据与分类不一致仍拒绝定级。

需要用新规则重新核验已经处理过的作品时，应先取消旧任务并确认已取消，或等待旧任务完成，再发起新一轮核验。暂停后继续、失败后重试都会保留旧游标，不会从头修正已处理的结果。新一轮核验覆盖画质证据与汇总，不修改媒体文件或历史发布快照。早期任务连最终下载地址与尝试关联都没有保存时，即使媒体身份匹配成功，也仍然无法确认文件版本。

历史复用页只有在能追溯到同一来源页和同一文件时才继承结论。旧任务中的 ORIGINAL、WebP 扩展名、单独的图片宽度以及整部大小差异都不足以判断单页版本。作品汇总分别统计各档页数，混合画质和待核验页可在详情核对。

已核验原图与展示图并存时显示两种图片版本；只要仍有未知页，数据库汇总为未知并保留各档页数。面向用户使用“原图”“网页阅读版”“无法确认是否为原图”：原图是上传到原站的原始文件，网页阅读版是原站用于在线阅读的版本，可能经过缩小或压缩。归档选项表示请求偏好，同一部作品实际可能收到两种版本。

已保存图片的版本判断与下载完成状态分别表达。新下载同样可能缺少原件对照，识别后仍无法确认；核验只能重新解释已有记录，不保证所有未知页都能变成已确认。界面在已有部分确认页时显示“部分版本无法确认”，全部未确认时显示“版本无法确认”。作品阅读区默认只展示一行可展开的“保存的图片”和简短状态；展开后用完整句子说明各版本数量、原站整部大小、判断依据和相关操作。具体原因再次按需展开，以日常语言解释，原始诊断原因仍保留在管理界面。相同原因按当前批次合并页码范围，每批最多 50 条记录，标明当前条数范围及总数。任务抽屉把请求偏好与实际保存版本分开。核验结果与本地验证范围见[本次记录](../records/features/archive-quality-2026-11-05.md)。

生产首次历史核验暴露的旧快照兼容缺陷与修复验证见[旧快照核验修复记录](../records/features/archive-quality-legacy-snapshot-2026-11-05.md)。

## 单部升级与退休

作品详情的“下载原图”升级当前归档范围。管理员提交作品、期望当前修订和幂等键，服务端冻结来源计划和本地页映射，并通过既有解析、下载、发布通道执行。重复提交可回到已有任务。已证实为原图的页经磁盘校验后可复用，其余页下载原图。升级只包含已归档页；若原覆盖范围为前 20 张，随后点[下载剩余图片](./archive-partial-coverage.md)再按升级后的原图画质扩页。

下载时旧修订可读。页面计划、媒体身份或源文件基线发生冲突时保留旧修订。全部目标页通过后，发布事务切换当前修订并更新原有 Image 的文件属性，保存每个账户在同一来源页上的阅读位置、书签和单图喜欢。作品评分按原作品 ID 保留。

新修订生效后，独立维护任务根据冻结的旧页映射与原图证据退休被替换的目录。分别校验两侧 manifest、文件和仍存引用；升级前后的文件摘要允许不同。清理失败保留现场，可查看维护任务并重试。恢复时保全数据库、对应的媒体目录、清理检查点和配套版本，遵循[一致性备份与恢复](../operations/backup-and-recovery.md)。生产原图升级由管理员在作品详情发起。
