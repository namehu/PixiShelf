# 标题来源精准匹配与人工复核

本功能在本地实现并验证；生产迁移、历史重算和历史绑定清理由管理员发布后显式执行，不在开发验证期间操作生产数据。

## 候选和规则

E-Hentai 仍只接收一个标题关键词和上传者限制。每轮最多检查 100 个远端候选，零命中继续推进游标。本地别名不扩大远端召回范围，未返回的画廊无法出现在复核列表。

规则分为 `any`（至少一条）、`all` 和 `none`，每组最多 20 条，每条文本最多 160 字符。支持包含、完整词、开头是、结尾是、整个标题相等和正则表达式。每条条件独立配置“忽略大小写”，默认勾选；取消后按原始大小写判断。英文或日文标题中的同一个标题必须同时满足任一接纳条件及全部附加条件；任一标题命中排除条件即过滤。标题解码 HTML 实体一次，去除首尾空白，保留内部空白与标点。

完整词的相邻字符不得属于 Unicode 字母、数字、组合字符或下划线。例如 `[RAG]` 的方括号可作为词边界，`Ragnarok`、`RAG_01`、`中文RAG` 不满足完整词 `RAG`。不做作者识别或模糊评分。

正则使用浏览器与 Worker 共用的 RE2JS 线性时间引擎，在标题中搜索匹配；需要限定整个标题时使用 `^…$`。直接填写表达式，不使用 `/…/flags` 包装；支持分组、分支、字符类、Unicode 类和重复，不支持环视、反向引用或内联标志，大小写由勾选项控制。输入时及服务端均校验语法，编译规模超过 4096 条指令时拒绝；编译缓存有界。表达式原文保留大小写与空白，不进行普通文本规则的转小写处理。空标题不参与匹配；零宽匹配可命中，但界面明确提示没有可高亮的字符。

例如远端搜索 `RAG`，本地 `any` 配置包含 `[RAG]` 或 `[r18AnimeGirls/RAG]`，即可拒绝仅因 `Ragnarok` 命中的候选。

远端条件变化需要另存来源；本地规则可以原地调整，不改变来源 ID、最新水位和历史游标。来源去重使用规范化远端条件和本地规则，同组条件排序与重复不影响身份；忽略大小写的普通文本条件保持原有身份，区分大小写的条件与正则保留原文参与身份计算。等价单条旧规则沿用旧 queryKey。应用后与另一来源重复则拒绝，不合并来源或历史。

## 复核

来源内显示“已接纳”和“已过滤”。已接纳继续使用待处理、处理中、已归档等工作流；已过滤默认显示未复核项，可切换已确认排除或全部。搜索、内容筛选和游标分页在整个数据库集合执行，不以浏览器已加载数量为搜索范围。

已过滤与已接纳共用“纯列表／首图预览／卡片”显示偏好。首图预览和卡片使用扫描时保存的安全缩略图，缺失或加载失败显示占位；切换显示模式保留勾选，不触发复核或归档。过滤标题解码 HTML 实体，标题、上传者、判断证据和图片沿用全局隐私遮蔽。手机使用页面滚动，卡片单列展示，复核操作可换行。

每项保留独立的机器判断、证据和 `AUTO / INCLUDE / EXCLUDE` 人工决定。人工决定按来源和 provider/gallery 身份保存，扫描和规则应用均不覆盖。手动接纳、确认排除、恢复遵循规则不会解析、下载或改变本地作品。上传者限制不能由手动接纳绕过；全局忽略仍隐藏该画廊并阻止入箱，来源内排除不写全局忽略。

`matchesQuery` 是当前有效接纳结果的缓存，统一供列表、统计和入箱资格查询使用；`ruleMatches` 是机器结果，`reviewDecision` 是人工决定，`matchEvaluation` 保存判断原因与证据。新扫描将原始双语标题保存到 `matchTitles`；历史候选只使用已有 comparisonSnapshot，并标注 HISTORICAL。缺少可用标题进入待复核，不根据展示标题猜测接纳。历史快照可能已规范化空白，界面明确提示此限制。

## 预览和原子应用

编辑后必须预览全部已保存候选。`ARCHIVE_TITLE_RULE_PREVIEW@2` 在 `ARCHIVE_RESOLVE` lane 中每批计算 250 条，评估明细、累计数和游标在 Worker fence 内同事务提交；让行不消耗失败重试次数。任务失败可由任务中心重试，暂停、取消和租约恢复沿用中央队列，重新打开规则弹窗可恢复查看最新预览。

预览显示接纳、过滤、新增接纳、新增排除和人工决定保留数，并提供分页明细与即时单标题试算。试算只针对输入标题，不替代上传者资格检查。应用前重新校验规则版本、目录版本、评估完整性和重复来源。同来源仍有活动扫描时不切换。

预览行以绿色勾号和红色叉号分别标记最终接纳、过滤结果，同时保留文字标签。列表、卡片与预览直接显示机器命中的标题，接纳片段用绿色高亮、触发排除的片段用红色高亮，不需展开。人工决定与规则判断分别说明；手动决定不会伪造规则命中。历史证据标明快照，全部参与判断的标题可用键盘展开；缺失标题使用待复核提示。标题解码 HTML 实体后仍受隐私遮蔽保护。新评估保存解码后标题的 UTF-16 高亮区间；旧评估依据已保存的命中标题和条件恢复高亮，不用当前规则改写旧判断。

应用事务持有来源锁与来源行锁，以一条批量 UPDATE 切换全部候选的机器判断及有效接纳结果，再递增来源规则版本并记录 APPLIED；失败整笔回滚。因此读者只能看见完整旧状态或完整新状态。目录 INSERT/UPDATE/DELETE 的语句级触发器递增 catalogVersion；扫描、复核或其他目录变化会使预览失效，必须重新预览。工作流状态更新也会保守地使预览失效。

重算不访问远端、不取消既有任务、不启动解析或下载、不修改本地作品或艺术家关系。规则修订和评估随来源保留；任务执行历史清理不删除已经完成的预览。复核逐项回执永久保留，未知网络结果重用原 requestId，已知冲突后重新检查并使用新 requestId。

## 固定艺术家和历史清理

标题来源在人工加入收件箱的事务内读取当前固定艺术家并追加，只有该次实际接收的 URL 会绑定；容量拒绝、重复和幂等重放不额外绑定。沿用创作者、发布、画廊身份锁、去重和手动抑制。扫描、规则预览/应用及手动接纳均不绑定艺术家。上传者来源仍使用扫描冻结配置、首次匹配追加的行为。

“清理历史艺术家标记”只列出当前有效过滤候选中、属于来源固定艺术家的待生效关系。管理员选择具体关系，再确认取消。关系跨来源共享，取消写入全局画廊/艺术家抑制，后续自动追加不会补回；显式手动绑定才能解除。执行时再次检查来源版本、过滤状态、固定艺术家配置和关系仍未生效。不会删除已生效作品关系，也不会根据旧记录缺少操作者来推断删除权限。保存规则不自动清理任何关系。

## 接口与升级边界

`archiveSearch` 新增 `latestRulePreview / rulePreview / rulePreviewItems / reviewCounts / creatorCleanupPreview` 读取接口，沿用会话认证；`previewRules / applyRules / cancelRulePreview / reviewItems / cleanupCreators` 使用管理 procedure。来源、修订与候选归属由服务端核验，操作者来自会话。新增筛选 `matchView`、`reviewFilter` 在服务端分页前执行。

正式迁移 `20261022000000_archive_title_rules` 和 `20261022001000_archive_title_review_commands` 添加字段、规则修订/评估表、失效触发器和复核回执类型。旧来源回填等价单条规则，不收紧旧接纳结果、不清游标、不自动删除艺术家关系。规则 JSON v2 增加正则与逐条大小写选项；旧 v1 缺少选项时继续忽略大小写，等价普通条件可规范化回 v1，不需要新增数据库迁移。

新扫描冻结 rulesVersion/titleRules，任务使用 `ARCHIVE_SEARCH_SCAN@5`，Worker 继续支持 v1/v2/v3/v4 和旧游标；预览任务使用 v2，继续执行旧 v1。新任务版本阻止旧 Worker 领取不支持的规则。App 与 Worker 应协调更新，产生 v2 规则后不得单独降级到不理解 v2 的 App/Worker，也不要把新任务版本手工改低。现有已保存规则、人工决定和接纳结果不自动变化，修改规则仍需预览并应用。

升级前按[备份恢复手册](../operations/backup-and-recovery.md)停写并保留数据库、配置和镜像检查点；先 generate/deploy 正式迁移，再协调更新 App/Worker，确认 Worker READY、Registry 的任务／版本／lane 能力审计通过。新增人工决定或 v4 任务产生后不得只换旧镜像回滚：旧代码会忽略人工决定、过滤列表和新绑定时机。优先兼容版本前向修复；完整降级需恢复一致检查点。迁移不执行生产重算，管理员发布后自行预览、应用和确认历史清理。

历史验证与限制见[标题规则验证记录](../records/features/archive-title-rules.md)和[大小写、正则与高亮增量验证](../records/features/archive-title-regex-2026-10-22.md)。
