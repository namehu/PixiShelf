# 同艺术家作品去重

系统检查**同一艺术家**的作品，找出完全相同、完整包含、部分重复及可选的疑似版本，交给用户对照和选择，再按明确确认的范围永久删除副本。支持本地创建、Pixiv 导入、本地导入、URL 归档四来源及混合组。检测不删除文件，预览不构成删除授权。

本文是当前行为入口。`current` 表示已按所列代码核对，**不代表某个 NAS 或生产实例已部署**；发布和实例验证须有对应记录，不能从版本标签推断。

2026-10-29 局部核验范围：多帧排除缓存、视觉完整子集关系复用、旧归档清单核验；其余章节沿用先前核验。

| 状态     | 范围                                                                                                                                            |
| -------- | ----------------------------------------------------------------------------------------------------------------------------------------------- |
| 已实现   | 四类关系、人工对照、一次确认直接删除、来源抑制；F01 部分重复闭环、F02 三层缓存；F03 已到第七批，包含持久分段、查询优化及比较工作量分轮继续      |
| 待完成   | 当前算法的 50 万规模完整验收、真实图片读取／解码及 NAS 并发测量、结构性硬上限后的扩展方案、提高公开范围上限；F04 真实有码／无码版本效果真值验证 |
| 明确不做 | 自动判断哪部无码、自动保留或合并图片、合并个人整理记录；隔离／移动／恢复副本、视觉批量删除及移动端专用去重适配均已取消                          |

去重管理以桌面为维护与验收目标，现有窄屏兼容保留；日常浏览和阅读的移动端支持不变。视觉检查当前每次最多 **10,000 个登记原件**，并有单作品、候选和单图限制；这不承诺 10,000 张静态图一定完成，也不限制 SHA 精确／包含／部分重复阶段。详见[处理上限](#处理上限与继续执行)。

## 用户完整流程

![从同艺术家检查、人工对照到确认删除和删除记录](../diagrams/features/artwork-deduplication/business-flow.svg)

[图源](../diagrams/features/artwork-deduplication/business-flow.mmd)。流程依据为[检测服务](../../packages/pixishelf/services/artwork-dedup-service.ts)、[审核服务](../../packages/pixishelf/services/artwork-dedup-review-service.ts)和[直接删除执行器](../../packages/pixishelf-job-executors/src/artwork-dedup/direct-delete.ts)。

艺术家页“检查重复”进入 `/admin/duplicates?artistId=…`，用户主动开始后冻结当时有效归属的活动作品；后来新增作品留待下次。同一艺术家只允许一个活动检测，暂停也占用资格。默认“快速检查”，可在“检查选项”选择逐一重查或开启“检查疑似版本”，后者默认关闭。关闭浏览器或离开页面不停止后台任务。

### 四类关系如何处理

| 关系     | 判定与对照                                                                                                          | 保留与删除规则                                                                       |
| -------- | ------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------ |
| 完全相同 | 全部登记原件的 `(大小, SHA-256)` 多重集合相等；忽略文件名和顺序，保留重复次数                                       | 可按组审核、批量选组；唯一有手工整理记录的副本优先推荐保留，多份有记录时须明确选择   |
| 完整包含 | 较少作品的每个原件在另一部中都有足够出现次数，另一部还有额外原件，如 80 个全部包含于 100 个                         | 只允许保留完整者；被包含者有任一账户的手工整理记录时，须显式选择完整者               |
| 部分重复 | 字节相同交集覆盖较短方至少 80%，且双方均有未配对原件                                                                | 默认参与 SHA 检查；无默认保留和推荐全选，手选整部版本，每次仅处理一对                |
| 疑似版本 | 可选；字节相同优先，再按整图和有界白边／裁剪视图做一对一页配对，较短方至少 80% 可对应，且至少一对原件不同但画面相近 | 仅完整通过静态视觉检查的作品参与；手选整部版本、确认内容损失、单对删除，不能批量处理 |

字节关系比较图片、动画、视频的全部登记物理原件；组合媒体不能只比较封面。部分重复的精确条件为交集 `I` 满足 `5 × I >= 4 × min(A, B)` 且 `I < A`、`I < B`，短作品也使用此整数条件。例如各 100 个原件、80 个相同，双方各有 20 个未配对，不称为完整包含。

图片对照区分“原文件一致”“画面相近”“未配对”。部分重复只有原文件一致与未配对，优先展示未配对内容；相同作品对已列为部分重复时，不重复列为疑似版本，视觉失败不能删除其字节证据。未配对不等于画面独有，视觉相近不保证无码识别，也不能保证没有误配或漏检。动画、视频及无法检查的原件不以封面代表整段。

结果分为“检查结果”和“删除记录”。组、长组成员和图片对照均分页；保留选择与要处理哪些组相互独立。跨页全选由服务器冻结完整范围。共同保留者只冻结一次，同一作品既保留又删除或被重复选删会拒绝整批选择；部分／疑似选择不能混入精确或包含批次。作品封面和名称可在新标签页打开详情，打开详情不会更改保留选择。

## 系统职责与持久边界

![App 短请求、数据库任务、三条 Worker 通道与受控文件子进程](../diagrams/features/artwork-deduplication/architecture.svg)

[图源](../diagrams/features/artwork-deduplication/architecture.mmd)。依据为[任务契约](../../packages/pixishelf-job-contracts/src/artwork-dedup.ts)、[维护契约](../../packages/pixishelf-job-contracts/src/artwork-dedup-maintenance.ts)及[后台执行机制](../architecture/background-jobs.md)。

App 只做短请求：校验 Session、账户一致性、版本和幂等键，保存审核或控制命令并入队；不遍历媒体、不执行删除。任务、缓存、结果和检查点落库，Worker 异步接续。既有三条执行通道为 `ARCHIVE_RESOLVE`、`ARCHIVE_DOWNLOAD`、`BACKGROUND_WRITER`；去重和正式发布只由 writer 通道执行，下载通道只写 staging。

原件属性检查、SHA 读取、视觉解码及文件动作使用受控子进程。每次提交继续核对执行权、根身份、目录代次、源版本、作品成员快照和冲突写入；缓存命中不能替代发布许可。数据库与文件系统没有共同原子事务，租约过期、任务失败或发出终止信号也不能证明子进程已经退出。

## 三层持久缓存

![文件 SHA、视觉特征和兼容关系缓存如何参与本次检查](../diagrams/features/artwork-deduplication/detection.svg)

[图源](../diagrams/features/artwork-deduplication/detection.mmd)。实现依据为[视觉特征准备](../../packages/pixishelf-job-executors/src/artwork-dedup/visual-pipeline.ts)、[视觉分段检索](../../packages/pixishelf-job-executors/src/artwork-dedup/visual-batches.ts)与 [F02 关系契约](../design/artwork-deduplication/matching-extension.md)。

| 层次          | 复用什么                                                                           | 仍要做什么                                                                                 |
| ------------- | ---------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------ |
| 文件 SHA 缓存 | 属性、源和算法兼容的已验证字节哈希，缺失或失效时补读原件                           | 本次属性检查、完整成员和源快照复核；精确组由本次多重集合重建                               |
| 视觉特征缓存  | 完整成功特征或已核验内容的多帧排除结论；也可按 SHA、大小、算法和规范化版本共享     | 每条媒体仍独立核验路径与身份，保存目标自己的记录；排除结论仍为 UNCHECKED，不能借用删除授权 |
| 作品关系缓存  | 同艺术家兼容已完成检查中的包含／部分关系、视觉页配对，以及完整阶段得出的无匹配结论 | 核对两端内容与精确组代表资格；重建本次索引和候选，重新计入处理上限，保存本次独立证据       |

快速检查不等于零读取、零计算或零数据库写入。文件属性仍须核对；每次视觉检查仍构建当前任务的全局索引并查询全部参与图片，复用比较也计入当前轮工作量。新增作品使候选变密时，旧“无匹配”不能跳过检查或绕过上限。标题和排序不要求重读内容，图片对照按当前顺序显示。

源、文件成员、归属、代表资格或算法版本变化会使对应缓存失效。失败、取消、旧版本和未完成阶段不能提供该阶段的负证据。`FULL` 逐一重查绕过全部三层缓存，包括跨媒体及同批 SHA 共享；删除前的完整读取始终绕过缓存。

单媒体多帧排除只在稳定读取后确认 SHA 与属性匹配、解码元数据确定多帧时保存；瞬时读取失败、不可读和其他解码异常不缓存。排除对象有独立类型与版本，不能作为成功特征进入索引。历史检查只有 `UNSUPPORTED_MEDIA` 缺口、其余完整作品已走到 `PUBLISH` 并最终 `COMPLETED / DONE` 时，可复用有完整签名的作品对；预算耗尽、错误或未到发布阶段仍不提供视觉负证据。旧代码将不识别的排除对象视为缓存未命中。

视觉准备每批最多 50 条，先查自身，再按缺失内容键有界查供体，每键最多一个；同批相同内容只处理一次。命中不重复解码或写回相同持久特征；新算／共享特征、任务结果和游标一起提交，失败不推进。目标保存后不依赖供体继续存在，历史清理也不能使新结果依赖被删检测。旧缓存无内容键时只按自身身份使用，不猜测或批量回填。

扫描 v5 起将特征准备、索引、查询和配对分段落库：全局索引完成后才查询，因此跨批次作品仍可对应；每次只载入当前批次或一对作品，已提交比较不重复计数。第五批目录描述缓存只在单次扫描调用内有界复用，**不缓存“校验已通过”**；第六批候选 SQL 使用既有索引按 run 和 key 有界定位。两者都保留每次提交和最终发布复核，详见 [F03 契约](../design/artwork-deduplication/visual-batches-f03-contract.md)。

## 处理上限与继续执行

此前文档里的“预算”指**允许处理的工作量**，与模型额度、费用无关。它保护本机内存、CPU、数据库和原件 I/O。短批只是“这小段做完，稍等再做下一段”；新检查的比较工作量则按轮授权，用满后保存进度，等用户点“继续检查”。文件总范围、单图和候选大小等结构性硬限仍不能靠继续绕过。

![短批自动继续、比较分轮等待和结构性上限的区别](../diagrams/features/artwork-deduplication/processing-limits.svg)

[图源](../diagrams/features/artwork-deduplication/processing-limits.mmd)。数值依据为 [VISUAL_LIMITS](../../packages/pixishelf-job-executors/src/artwork-dedup/visual-matching.ts)、[通用执行限制](../../packages/pixishelf-job-executors/src/artwork-dedup/limits.ts)及[扫描任务契约](../../packages/pixishelf-job-contracts/src/artwork-dedup.ts)。

| 遇到什么                            | 当前行为                                                                                                    |
| ----------------------------------- | ----------------------------------------------------------------------------------------------------------- |
| 正常短批／时间片让行                | 在完整文件或已提交批次边界保存检查点，让出执行槽，随后自动继续                                              |
| 用户暂停，或 Worker 正常退出后重启  | 从持久检查点继续未提交部分；已有定向及真实 Worker 证据，覆盖范围见下方记录                                  |
| v6 本轮比较工作量用满、仍有后续比较 | 保存准确进度后 `PAUSED`，视觉仍为 `PENDING`；用户点“继续检查”才能开启下一轮。当前未完成结果不能审核或删除   |
| 结构性硬上限耗尽，或旧 v5 比较超限  | 视觉标为 `INCOMPLETE`，不发布被截断的本次疑似版本结果；有效字节关系保留。原样重试不保证完成，不自动提高上限 |
| 部分作品不支持视觉或原件未完成      | 整体视觉状态可为 `INCOMPLETE`，仍可发布其他完整合格作品对；缺口须明确显示                                   |
| 根、环境或执行权等整次异常          | 按失败或失效收口，不把旧／迟到结果当作完整成功发布                                                          |

**未完成不能解释为“没有重复”。** v6 的分轮继续只适用于候选比较工作量，实际比较与关系复用共同计数。它不清零累计进度，不自动授权下一轮；普通暂停、时间片或 Worker 重启也不增加轮许可。页面不提供任意调高上限的参数。单图超时、候选过密、单对匹配边过多等结构性缺口仍明确收口，不通过无限续跑掩盖。

## 运行状态怎么看

检测支持暂停、继续、取消和原范围重试；重试会清空本次包含／部分／视觉工作状态，保留可复用持久文件和视觉缓存；v6 的轮次、轮起点和等待标记随重试重建。任务 `COMPLETED` 只表示流程结束，界面须分别显示有效完成、已处理、变化、失败、跳过及视觉未完成；`checked` 是有效完成作品数，`processed` 是已处理数。历史任务结果不回写，判断范围须读对应检查的分项计数。

暂停／取消在服务器按执行通道、任务、检测记录的顺序加锁后校验。后台自动领取、分段等待等状态切换导致页面版本落后时，只要当前仍允许该动作，且页面版本之后没有其他已提交控制命令，就接受该暂停／取消；不能越过其他账户的控制命令或原范围重试。继续／重试仍要求版本完全一致，所有动作保留账户校验和幂等重放。页面将 `RETRY_WAIT` 显示为“等待继续检查”，不把正常分段等待称为失败；操作错误区分状态冲突、登录变化与结果未知，未知响应仍需查询当前状态，不自动重复提交。

缺失、不可读、零字节、读取中变化或根异常不能形成完整作品证据；正常无结果、局部未完成和整次失败分别显示。最终分组、审核、预览和执行前复核沿用底层内容快照的初始版本规则：当前 `ArtworkContentSource` 缺失时源版本／媒体代次可按 0 核对，历史快照和作品指纹仍须存在且匹配；不能据此放过真实版本变化或写入占用。

新检查要求 READY Worker 支持扫描版本 6；Worker 继续兼容旧 v5，旧任务不会自动升级或获得分轮许可。v1 只有精确，v2 无视觉，v1–v3 未检查部分重复；v3/v4 保留原有界视觉路径，v5 保留原比较超限收口行为。界面通过能力标记提示重新检查，不能把旧记录未执行的能力显示成已排除。视觉状态独立区分未开启、等待、完成和未完成及原因。

## 预览、一次确认与实际删除

“核对并删除”异步创建 `DIRECT_DELETE` 准备操作。READY 预览展示服务器冻结的保留者、副本、保留文件、待删文件和整理影响。共享路径、硬链接、符号链接、未知附件及未验证的归档历史原件会阻断对应作品，不能静默缩小已确认范围。

归档清单优先使用已封存并排空的发布哈希。仅对封存哈希、generation token 和 generation 记录都不存在的旧归档，允许核对完整清单映射：唯一当前修订和来源身份一致，导入项、当前图片与本次扫描 SHA／大小一一对应，清单的全部真实 index、路径、SHA 和大小也须一致；数据库分页覆盖全部成员。部分缺失或损坏的新封存记录不能降级走旧路径。核验失败保留原始原因和已读取的属性证据，目录复查不把缺少读取基线改报成文件变化。

同一面板完成一次明确确认：永久删除不可恢复，整理记录不合并，且所选目录的外部同步和编辑须持续停写。部分／疑似还须确认版本不同、删除方未配对图片和整理记录也会丢失。没有口令、第二次删除弹窗或隔离步骤。服务端授权绑定操作者、账户、操作版本、冻结摘要、协议和幂等键；浏览器不能提交或扩大文件路径。旧隔离预览不能补签为删除授权，客户端也不能开启独立删除能力。

确认后 Worker 同时认领保留者与副本，阻止应用内冲突写入，等待相关执行实际退出。随后**绕过缓存完整读取所选全部组的原件，全部通过后才允许首个删除意图**。完全相同复核多重集合；包含复核足够出现次数及方向；部分复核冻结交集和数量；疑似和部分均复核两部各自原件快照，人工取舍不免除身份、范围和写保护要求。部分／疑似不承诺保留方含有删除方全部内容。

只删除冻结清单中的逐个文件，不移动、不清空艺术家目录、不顺带清理空目录。每步先持久化意图，核对文件身份，再删除、同步父目录并提交回执；所有文件回执齐全后才删除副本业务记录。保留作品不接收副本的个人整理数据。去重专用删除绕过回收站，普通 URL 归档删除继续原回收流程。

<details>
<summary>确认协议、个人记录和会话边界</summary>

精确、包含、疑似、部分分别使用确认协议 1／2／3／4，新维护任务均为版本 5；历史任务按原版本兼容。包含方向和数量、部分／视觉证据版本与双方快照均进入冻结摘要；旧确认不能改用于其他关系，确认请求使用服务端返回协议。

标题、来源、创建时间和文件范围来自持久快照。评分、阅读、书签和喜欢仅展示当前账户的实时记录，并明确执行前复核；已删副本标为“已随副本删除”，不把缺失的历史明细显示成零。标签、系列、章节及派生记录的删除影响须说明。其他账户只显示必要保护资格，不公开标记、数值、数量或时间。

提交期间禁重复操作。网络响应未知时查询同一操作，原输入重放复用幂等键；切换账户会清空选择、确认和待提交状态，旧会话迟到响应不能更新新账户。

## 删除停止、失败与原范围续行

![预览、授权、删除、停止与续行的业务状态](../diagrams/features/artwork-deduplication/lifecycle.svg)

[图源](../diagrams/features/artwork-deduplication/lifecycle.mmd)。图中是业务阶段，不是另一套数据库枚举；实际状态和动作以[维护契约](../../packages/pixishelf-job-contracts/src/artwork-dedup-maintenance.ts)为准。

首个删除意图之前可取消，确认子进程退出和来源状态安全后解除占用；若副本已进入隐藏阶段，也会恢复可见。首个意图之后只能请求停止，等待安全文件边界，已删文件不可撤销。界面依据真实持久意图区分取消和停止。

开始删文件前的校验失败不代表已经隐藏或删除副本。进入删除阶段后的失败／停止会保留副本的隐藏状态、冻结清单、保护和日志；后续只能复核保留者并继续原授权未完成文件，不能换保留者、扩大范围或恢复已删文件。

![持久删除意图、文件回执与异常现场核对](../diagrams/features/artwork-deduplication/recovery.svg)

[图源](../diagrams/features/artwork-deduplication/recovery.mmd)。依据为[直接删除执行器](../../packages/pixishelf-job-executors/src/artwork-dedup/direct-delete.ts)与[文件执行契约](../design/artwork-deduplication/file-execution-contracts.md)。读取进程未证实退出时保留占用，禁止启动替代进程；未知现场不能按文件名盲删。删除日志不是媒体备份，文件恢复只适用独立的[一致备份流程](../operations/backup-and-recovery.md)。

删除记录先展示处理结果、作品去留、已删和待删数量；文件清单、来源和核对统计按需展开。已删作品不提供失效详情链接，计数按文件去重，不因重试回执重复增加；停止或失败保留处理入口。成功后不再显示执行前提示或零值进度。

## 来源、权限与运维

可再次发现的来源留下独立抑制记录，防止重扫和迟到任务重新发布副本。“允许重新导入”只解除选中的真实来源并推进重叠来源代次，允许未来的新输入；不恢复文件，也不使旧任务有效。它是删除记录中的折叠次级动作，没有可发现来源的本地创建作品不显示伪造来源。

所有入口校验 Session 与 `expectedUserId`。检测结果是共享管理事实，发起者用于审计；DTO 不返回绝对媒体路径、根身份、原始哈希、执行租约或他人私有明细。对照媒体继续核验账户、图片所属作品和根路径。部署顺序、外部持续停写与部分失败处置见[去重运维手册](../operations/runbooks/artwork-deduplication.md)；认证边界见[权限说明](../security/access-control.md)。
