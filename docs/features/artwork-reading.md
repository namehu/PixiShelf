# 作品阅读记录与进度

本文维护当前实现的用户语义与恢复边界。分页、观察采集和上报协议见[阅读架构](../architecture/reading.md)；既有隔离验收和未覆盖项见[验证记录](../records/features/artwork-reading.md)。实现核验不代表整套浏览流程已完成生产验收；Pixiv 默认已读的专项生产结果独立记录。

2026-10-29 局部核验范围为详情完整模式的图片区域观察，包含尚未取得媒体详情的占位区域。

## 用户行为

- 阅读记录按账户隔离，同账户跨设备共享。详情长图、自适应预览、独立原图预览和沉浸阅读共用逻辑媒体计数与保存机制；原站外链不计入；站内原站预览已退役。
- 详情完整模式的图片和动图，只要对应区域进入前台页面视口即计为已读，不等待媒体详情、图片下载或解码，也不要求停留时长；占位区域和加载失败区域同样计入。同屏多个图片区域分别计入，快速滑过已进入视口的区域也保留记录。预加载、弹层遮挡、离屏和后台不计入；跳页不会补记未进入视口的图片。隐私遮罩不停止记录。
- 自适应预览、独立原图预览和沉浸阅读仍要求图片或动图加载成功且前台可见；堆叠按下述整组规则计入。视频使用下述播放位置规则。
- 有效阅读使本地预测进度从未完成变为已看完时，立即在底部居中显示 2 秒的轻量「已看完」提示，不等待 3 秒合并或接口响应。同一账户、作品和媒体版本在当前应用会话中只提示一次；切换预览、离页返回、保存失败后重试或重新阅读都不重复提示。打开已看完作品、服务端确认和心跳不触发该提示。提示表示本次阅读已完成，不表示进度已落库；最终无法保存时另行显示全局未保存提示并撤销未确认的进度。
- 有效阅读立即预测本页已读进度，自动保存使用共享阅读契约定义的合并窗口；离页尽力补交。短暂失败会重试，最终失败撤销未确认进度并显示全局未保存提示。刷新、关闭标签或进程终止可能丢失未确认事件，不提供持久离线队列。
- 同一作品的有效阅读活动间隔超过 30 分钟才增加一次访问次数。刷新、切换浏览模式和短时间回访沿用同一次访问；有效心跳只延长已有活动，不能创建首次访问。
- 进度按完整作品的不同逻辑媒体计数。既有 APNG/视频分组的成员共同代表一个展示项；跳读只增加实际看过的项，不把最大序号前面的项推定为已读。零媒体作品不判为已看完。
- 作品整体完成采用 ≥90% 的容错阈值，由[共享阅读契约](../../packages/pixishelf-db/src/reading-contract.ts)定义，按 `总数 > 0 && 已读数 × 100 >= 总数 × 90` 精确判定，不四舍五入、不要求看到最后一张、不设固定遗漏上限。100 张记录 90 张、50 张记录 45 张、20 张记录 18 张即完成，少于 10 张仍需全部记录；1000 张可遗漏 100 张。整体完成不补写逐张已读记录，遗漏项仍可通过“只看未读”补看。卡片、筛选、完成提示及首页续读采用同一阈值。
- 普通进入详情停留在页面顶部；首次媒体索引加载不自动跳到第一张图片。进入详情时存在第二张及以后的恢复位置，才在底部提示「上次看到第 X 张，是否继续？」并显示 8 秒倒计时进度条。点击「跳转」回到本次进入时捕获的位置，点击「从头开始」回到第一张；超时仅关闭提示，不自动跳转。提示每次进入只出现一次，离开、账户切换或媒体失效时撤销，不因自动阅读更新再次出现。最后媒体已不存在时沿用服务端恢复位置回退规则。
- 卡片阅读标识为贴住封面左上角的 12px 小三角：未看用红色，阅读中用蓝色，已看完不显示；不显示书签图标或环形进度。不额外提供阅读状态悬停提示或具体进度描述。偏好标签固定在原位置，不因阅读标识移动，且与三角不重叠。详情显示完整阅读数据；最近阅读按最后阅读时间排序。阅读状态筛选与原有筛选、排序组合时使用稳定游标。列表里已显示的卡片只原位更新标记，刷新后才重新套用筛选顺序。带阅读状态条件的列表在同一应用会话内保留已加载页；进入阅读后返回、窗口重新聚焦或断网重连不重新过滤这些卡片。快捷筛选的本轮列表标识随 URL 保留，返回时恢复同一列表及滚动位置；整页刷新或重新应用筛选创建新查询结果，已不符合条件的作品此时才移出。未加载页仍按请求时的条件查询，缓存按账户隔离。

### 首页继续阅读

- 首页标题下、最新作品上方展示单排横向“继续阅读”，最多 6 部，按本账户最后真实阅读时间降序排列，同时间按作品 ID 降序。手机横向滑动，其他首页模块保持现有顺序。
- 候选必须有真实 VIEW 历史、非空最后阅读时间、逻辑媒体总数大于零且尚未达到整体完成阈值，并且作品仍为 ACTIVE、未删除。已开始但零已读项的视频属于候选；默认／手工标记不会单独制造真实阅读活动。服务端先过滤再取上限，不先截取历史后在客户端过滤。
- 没有候选时隐藏整块；加载中显示卡片骨架，失败在模块内提供重试。数据按当前 Session 账户获取，`expectedUserId` 只用于拒绝过期账户请求；返回首页和重新聚焦时重新查询，已完成作品移出并补足后续候选。
- 点击本区卡片通过一次性的 `resume=1` 表达明确继续意图。详情等待当前账户的最新阅读上下文后定位到服务端恢复位置，消费参数并保留其他查询参数和 hash，本次不重复显示普通续读提示。加载失败可重试，账户切换或媒体失效取消原意图；定位完成前不把经过的首屏媒体记为阅读。
- 位置优先使用仍存在的最后媒体，失效时复用服务端第一个未读逻辑项／首项回退。恢复的是媒体位置，不持久化或恢复视频播放秒数。普通入口仍从头开始并按上文提供 8 秒续读提示。
- 卡片沿用既有隐私遮罩、简约模式与阅读三角标记，不增加精确进度徽标。此增量不包含收藏首页其他模块的调整、不新增数据库结构。

本次实现与验证见[首页继续阅读记录](../records/features/artwork-reading.md#2026-10-22-首页继续阅读)。

### 堆叠浏览

详情「完整／堆叠」采用全量索引的确定性连续分组。堆叠画框至少一半可见且加载、翻页稳定后，实际观察图片授予原始整组已读；从堆叠打开的适配尺寸预览同样授予整组；独立原始文件阅读器保持全量逐图规则。完整模式维持逐图观察。隐藏成员不产生 VIEW、活动时间或最后位置；未读筛选取冻结交集且保留原组边界。

源变化或凭据失效会要求重新打开，保留历史已读；显式重新打开可恢复本账户和作品的真实图片锚点，普通新进入仍从完整模式开始。旧摘要请求兼容保留，完整规则见[作品堆叠浏览](./artwork-summary.md)。

### 加载、保存与状态冲突

大作品按目标批次加载，选页直接定位目标，未知媒体先保留尺寸占位；详情完整模式按图片占位区域的可见性记读，其余入口仍执行各自的加载或播放门槛。进度区在加载、错误和成功期间保持稳定布局。未读筛选、预览与原始页码保持一致，不把过滤序号当成完整作品位置。

本地预测只代表本页正在保存的进度，跨设备以服务端确认结果为准。切换账户清理旧账户队列和提示，迟到响应不更新新账户。媒体变化导致分页或阅读版本失效时，必须重新打开并重新获取媒体与阅读上下文，不能使用新版本重放旧事件。技术参数以[阅读架构](../architecture/reading.md)及共享契约为准。

### 补看与手动完成

- 详情媒体区的顶部和底部显示同一份轻量阅读记录及已有的阅读次数。全部记录后显示「已读完 · 600 张」，达到容错阈值但仍有遗漏时显示「已读完 · 已记录 540 / 600 张」。未读筛选刷新为空后仍保留真实记录，并显示空态说明与一个查看全部入口。图片上不显示阅读角标或状态条；长按菜单只显示「第 X 张」，不展示已读／未读状态；仅加载失败且尚未记读的图片提供单张「标记已读」。详情预览仅沿用原有页码导航。加载失败不阻止手动标记。
- 底部阅读记录以紧凑单行随内容自然排列，不额外分隔成大块区域，仅发生错误时展开错误文字。其操作区以双勾图标提供「标记全部已读」，保留悬停提示、可访问名称和至少 44px 点击区域；右上角作品操作菜单仍提供原有阅读操作。达到整体完成阈值但存在漏记时，底部入口仍可补齐；全部记录后禁用。提交期间显示加载状态并禁止重复点击，失败时顶部和底部同步撤销预测、提示错误并允许重试。上下文加载或失效期间不能提交旧操作。
- 未读筛选进入时冻结本轮候选 ID，列表与自适应预览共用该集合。自动或手动读完只更新状态，不移除图片；显式刷新后才移除。全部读完仍可回看，刷新为空后提示「没有未读内容」。筛选或刷新会暂停自动浏览并定位列表开头，重新打开作品默认查看全部；独立阅读器不增加筛选入口。
- 手动标记只有正向操作，不支持改未读、重置或多选。整部标记由服务端选择当前作品的全部逻辑媒体，不受浏览器懒加载或筛选范围限制；后续新增媒体仍为未读。
- 进度与次数独立。手动标记不增加阅读次数、不更改实际阅读时间、恢复位置或最近阅读排序；从未访问的作品也能处于部分已读或全部已读。自动 VIEW 继续按原有活动窗口计次，不因手动操作而延长窗口。滚动到底不会自动标记前面的遗漏。
- 未读为零已读项且没有有效观看访问；阅读中为已有已读项或有效观看访问、但尚未达到整体完成阈值，包含已经开始观看但未完成的视频。最近阅读只包含实际产生过 VIEW 的作品；不将手动完成解释为一次阅读活动。
- 手动标记立即更新本地预测并提交，失败撤销预测并提示重试，提交期间禁止重复操作；媒体版本冲突要求重新打开，不能对新版本自动重试旧操作。

### 视频观看状态

- 详情和独立原图预览的播放器、沉浸浏览采用相同规则：视频实际开始播放后计入访问及最近阅读，状态为阅读中；有效播放位置达到有限正数总时长的 90% 时，该逻辑媒体才计为已读。快进到 90% 也算完成，回拖及循环不撤销已读。播放器的 `video:ended` 事件以有效总时长补交完成证据，避免短视频末尾进度事件稀疏或循环先重置到零导致漏记；仍要求已实际开始播放及满足前台、在屏门禁。
- 仅显示封面、加载元数据、自动播放被拒绝不算开始观看。时长未知或无效时可以记录已经开始观看，但不能自动完成；现有手动标记全部已读仍可使用。图片和独立动图维持原规则，APNG/视频分组遵循视频主项规则。
- 暂停或缓冲时不发送视频活动心跳；前台、在屏和未被面板遮挡的门禁继续适用。快进发生在开始播放之后时，可在暂停状态下完成判定。原有已读数据保留，不重算旧视频。
- `VIEW` 和 `HEARTBEAT` 可携带临时 `playback: { currentTime, duration }`；两值必须是有限非负数。服务端按数据库中的逻辑媒体类型判定，视频缺少播放证据的旧客户端上报被忽略，不能因显示封面而完成。完成比例只影响已读集合，开始观看仍正常建立访问；心跳仅延长已有且未超时的访问。
- 沿用现有摘要的访问次数和已读集合，不新增表或迁移、不持久化视频秒数，也不新增跨次或跨设备断点续播。列表筛选与摘要统一将有观看访问但零已读项识别为阅读中。发布时刷新旧客户端；回滚旧代码会恢复旧视频判定，建议用前向修复保留新语义。本次不修改已有业务数据，无需数据恢复操作。

## 数据变化与恢复

迁移 `20260924130000_add_artwork_reading_tracking` 为现有 `Artwork` 增加默认值为 1 的 `mediaRevision`，新增账户作品摘要与已读媒体集合；不回填过去的阅读。没有记录的旧作品显示未看，不代表过去从未阅读。软删除保留记录；永久删除通过外键级联清理。

普通媒体增删、排序保留仍存在的已读媒体，下次打开时校正进度快照。[部分归档显式补全](./archive-partial-coverage.md#详情与阅读)保留已验证旧媒体身份和阅读，新增页未读，分母从本地部分数扩展到补全后的本地数。完整替换、恢复或全量重建在同一事务中递增版本并清空该作品所有账户的阅读摘要、次数、已读集合与恢复位置；迟到的旧版本上报被拒绝。媒体写入与阅读上报统一先锁作品，再处理媒体或阅读状态。客户端的待发送事件不构成持久离线队列，强制关闭或持续断网可能丢失最后尚未提交的一批。

整体完成状态按现有计数派生，无新增数据库字段或历史回填；重新查询即按当前阈值判定，已读集合、访问次数、时间和最后位置不变。普通新增图片仍未读，但不必使整体状态回到阅读中：100/100 新增 11 张后为 100/111，仍满足阈值；新增 12 张后为 100/112，回到阅读中。视频单项继续采用上述播放证据规则，作品汇总不增加按媒体类型区分的完成阈值。部署后刷新客户端以统一前后端规则；回滚本次阈值代码只恢复旧的完成判定，无需恢复或补造阅读数据。

版本冲突后的“重新打开”会完整刷新当前阅读页面，同时重新获取展示媒体与阅读上下文；刷新完成前旧采集器保持失效，不能用新版本重放旧媒体事件。跨设备心跳只延长已有、未超时的活动：图片要求已看过该逻辑媒体，视频要求有效播放证据但不要求已完成；心跳不依赖其他设备修改的最后位置，也不改写恢复位置。客户端摘要以按账户隔离的查询缓存为准，使用 `(mediaRevision, stateVersion)` 比较版本，后续查询和上报仅能用较新快照替换已确认状态（包括重建后的零进度）；逐项已读 ID 与汇总原子更新，旧响应不能使进度倒退。路径迁移发布同样先锁 Artwork，再更新 Image，避免与手动重排、删除及阅读写入形成反向锁序。

发布前应建立数据库、原媒体、派生媒体、配置和镜像的一致检查点，随后使用 `db:generate` 与 `db:deploy`，禁止 `db:push`。回滚代码时保留新列和表，并暂停旧版本的完整重建写入者；若旧版本已经重建作品，重新升级前须核对受影响作品、清空其旧阅读数据并递增版本。影响范围无法确认时不得直接恢复阅读功能。详见[备份与恢复](../operations/backup-and-recovery.md)。

迁移 `20261009090000_reading_manual_progress` 将摘要的 `lastViewedAt`、`lastActiveAt` 改为可空，增加默认 0 的 `stateVersion`，保留现有值。首次手动标记的次数为 0、阅读时间与恢复位置为空；`firstSeenAt` 表示首次记为已读的时间，包含手动操作，不是实际观看证据。服务端在作品锁内随状态变化递增版本，幂等重复标记不增加版本。

**该迁移不能直接回退到旧应用**：旧代码对空阅读时间调用 `toISOString()` 会失败。优先部署兼容空时间的修复版本；必须回到旧代码时，按一致检查点恢复数据库、媒体、配置与镜像，不反向补造日期或仅强制改回 NOT NULL。

## 验收条件

自动验证须覆盖详情图片加载前短暂入屏、加载失败、媒体详情占位、离屏与遮挡门禁、堆叠和视频门槛保留，以及账户隔离、真实观察与预加载区别、视频开始／90%边界、逻辑分组、手动零访问进度、未读冻结集合、版本冲突、失败预测撤销以及重建后的迟到请求。浏览器验收另核对四个入口、后台／离屏／遮挡、关闭前补交和大作品跳页；模拟事件与设备尺寸不能替代真实手机、网络和生产验收。

整体完成另覆盖 0/0、8/9、17/20、89/100、899/1000 不完成与 9/10、18/20、90/100、900/1000 完成；详情、筛选、计数和续读一致；较新完成作品不挤占续读候选上限；容错完成后遗漏项可补看、保存失败撤销预测、补看及重试不重复提示，以及新增图片后的重新判定。详情顶部、底部记录在完整、堆叠及未读筛选模式保持一致；底部整部标记不受已加载或过滤范围限制，覆盖忙碌禁用、失败重试和全部记录后的禁用状态。

历史验证与限制见[阅读隔离验收记录](../records/features/artwork-reading.md)。

## 范围外

本功能不自动推断历史阅读，不提供改为未读、重置、多选批量修改、访问流水、统计仪表盘、视频秒级进度或持久离线队列。针对用户明确确认已经阅读的 Pixiv 导入作品，提供独立的[默认已读与历史回填](./pixiv-import-reading.md)维护流程；专项生产执行结果见该功能的独立验收记录。访问次数不用于权限判断，也不改变原媒体的备份责任。
