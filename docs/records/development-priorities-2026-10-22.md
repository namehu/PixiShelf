# 开发重点审查与首批实施决定

本文保存 2026-10-22 对当前仓库的审查结论及用户授权的第一批工作，不声明未来功能已经实现。对照范围为 `26b35442` 至 `f064bd4a`，主要新增提交是文档重构 `f634893b`。审查采用代码、文档与 Git 差异，没有连接生产或重新执行历史验收。

## 判断与优先级

项目已具备导入、归档、来源维护、后台任务、系列、组合筛选、阅读进度和沉浸浏览。下一阶段主线是让已有收藏更容易找回、继续阅读、整理和长期维护。

1. 补齐当前账户“我的喜欢”筛选，并统一标签原名、中文和英文的搜索匹配。
2. 组合已有能力形成个人收藏首页：继续阅读、最近入库、我的喜欢与常用筛选。
3. 按限定范围建立只读收藏健康检查与重复候选，提供人工复核。
4. 后续按需求评估以图搜图／语义检索、单图书签和个人备注、可携带元数据导出，以及单个新来源或新格式。

安全访问、可验证恢复和关键业务自动化与产品增量并行推进，具体发布遵循现有门禁。没有证据支持为此重构 Worker、增加并行消费者或立即扩展多租户、原生客户端。后续候选不是本批实施授权。

## 文档重构带来的校正

- `current` 表示当前实现已核对，不等于生产已部署；缺失生产证据也不等于未部署。阅读已是当前实现，后台退役和 WebP 等已有的发布确认不能被旧段落覆盖。[文档状态](../README.md#如何判断一份文档可否作为依据)
- Pixiv 默认已读及历史回填已有专项生产验收；默认已读、手动完成与真实阅读活动必须区分。[生产记录](./features/pixiv-import-reading.md#最终验收2026-10-21)
- 首页保留“最近入库”，允许切换未读条件，不把“最近入库未读”作为唯一新收藏入口。“继续阅读”依据真实阅读活动与未完成状态，视频已开始但零已读项也属于阅读中。[阅读规则](../features/artwork-reading.md)
- 普通打开作品仍遵循现有续读提示；明确点击“继续”才表达恢复位置意图。媒体位置恢复不承诺视频秒级续播。
- 快捷筛选当前保存固定日期；“最近 30 天”等动态时间属于后续新增契约，不能改变已有预设的含义。[快捷筛选](../features/artwork-quick-filters.md)
- writer lane 只串行 Worker 的 `SystemJob`，不覆盖 App 直接文件写入，数据库事务也不回滚文件 I/O。健康检查先只读；未来修复或去重需单独明确写入协调与恢复。[架构边界](../architecture/current-architecture.md#数据边界与发布不变量)

## 第一批实施范围

用户已授权先持久化本结论，再由子 agent 实施第一项。当前范围是“我的喜欢筛选＋多语言标签检索”，不包含首页改版、推荐算法、标签别名模型、自动实体合并或数据迁移。

### 我的喜欢

- 复用 `ArtworkLike`，提供清楚标注的当前账户喜欢条件，与现有关键词、标签、来源、阅读、媒体及排序条件组合。
- 沿用筛选草稿／应用、URL、列表与沉浸浏览传递、快捷筛选保存恢复的现有链路；旧链接和旧预设未提供该条件时仍显示全部。
- 账户身份来自服务端会话，不允许通过客户端指定任意账户读取喜欢集合；缓存和游标继续遵守账户隔离。
- 普通及随机分页、清除筛选、无结果、取消喜欢后的刷新均保持一致，不因分页漏传条件扩大集合。

### 多语言标签搜索

- 补齐标签建议和相关标签检索入口对 `name`、`name_zh`、`name_en` 的匹配，保留稳定标签 ID、现有权限和有界结果数量。
- 保留既有作品关键词与标签筛选的职责，不顺带把普通作品关键词改成全域内容检索。
- 译名只用于查找和展示，不改写原名、来源归属或人工整理，不新增同义词合并规则。
- 保持空查询、大小写、中文、英文、仅译名匹配和重复命中的一致行为；用户选择命中后仍筛选正确的标签 ID。

## 验收与证据

聚焦回归覆盖喜欢集合的账户隔离、组合筛选、URL／预设往返、普通与随机列表／沉浸传递，以及多语言标签命中和选择行为。界面沿用现有组件，验证桌面与移动布局、可访问名称和草稿应用。最终按[测试策略](../development/testing-strategy.md)执行主应用 lint、typecheck、test、提升权限 build，及文档和路径检查。

代码和当前规格在实施完成后更新，实际验证结果另行保存到功能记录。不能将本次审查、单元测试或本地浏览器验证当作生产验收。
