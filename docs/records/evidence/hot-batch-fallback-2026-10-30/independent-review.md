# 热批回退修复独立审查

审查者为未参与实现及测试编写的独立 Sol/xhigh agent。基线为 `main / f2b7e20f`，审查对象为 `codex/dedup-hot-batch-fallback` 当前差异及本目录证据；没有修改实现、运行数据库写入或重复执行测试。最终结论：**没有未解决的 P1／P2 阻塞项**。初审提出的一项 P2 日志进度缺口已修复并复审。

## 实现核对

- 预载资格、提交时作品来源比较，以及逐成员的作品 media epoch 比较均沿用既有缺 `ArtworkContentSource` 行等于 revision／epoch `0n` 的规则。真实存在的非零值直接参与比较，写入 token 仍拒绝；没有新增来源行、迁移或缓存版本。
- 提交仍先核对执行权、创作者目录及目录／写者，再锁作品和成员，复核冻结成员版本、作品指纹、成员路径／来源／目录／epoch／属性及完成数量。媒体、游标、作品状态和计数仍在同一事务提交；既有最终发布校验没有移除。
- `saveArtworkDedupHotRunBatch` 改为判别结果后，唯一生产调用点已按 `status` 处理；拒绝批次不调用成功批次遥测。相关 mock 已更新，DB／执行器类型检查通过。
- 回退原因使用有限枚举，按执行片内阶段／原因去重。payload 仅包含相关 ID、批次上下文、数值采样及已提交进度，不包含文件路径、异常原文、连接信息或 token。目录校验只返回布尔值时，字段明确叫 `batchFirstArtworkId`／`batchArtworkCount`，没有把批次首项冒充精确失败项。
- 事件写入复用下一次已有 telemetry 事务；事务成功后才移除待写队列，回滚会保留，失去执行权不会绕过围栏补写。没有新增逐图片事务。事件可能晚于实际回退落库，失权时可能仅保留 Worker 日志，此限制已在正文和查询模板说明。
- 复制阶段没有资料采样时不再传默认 `0`；已有峰值保留，尚未采样保持未知。真实预载／回退值才进入峰值汇总。

## 已关闭的 P2

初版回退事件没有观测时的已提交进度。若在后来保存事件时从当前 run 回填，普通路径已经提交的工作会被误读成回退前热批前缀。

最终实现只在 telemetry 所属事务成功后更新进度 watermark；回退发生时捕获该对象，Worker 日志和待持久事件使用同一快照。后续普通进度及回滚不能改写该快照。生命周期专项分别覆盖后续进度前进、事件去重、后续热事务回滚和未知资料值；该项已关闭。

## 测试及对照证据

静态核对了三个修改的测试文件及[专项说明](./validation.md)、[结构化结果](./validation.json)和实际日志：

- 热核对及生命周期遥测最终 [28／28 通过](./unit-telemetry.log)。涵盖缺行零版本成功、缺行非零 revision／epoch 拒绝、写者、混合来源、提交拒绝和 502 原件数量／延迟／让行边界。
- PostgreSQL 共有 32 个不同场景。使用编译 reader 的[完整覆盖运行](./postgres-full-coverage.log)通过 30 项，仅两个新增断言错误地期待未知计数为 0；改为 null 后，[两项最终定向运行](./postgres-final-targeted.log)通过，且在真实事件上执行运维 SQL 模板。这里是 30＋2 组合覆盖，不能描述为单次 32 项全绿。
- 新增正例在新建合成作品冷预热前构造缺源状态，随后断言冷预热自然生成零版本指纹，再测试缺源／混合源的热提交；没有通过改哈希或放宽实现来制造命中。负例在属性检查后、提交前插入真实非零来源 revision 或 epoch，确认热批拒绝并保存具体原因。
- 既有取消、失租约、事务回滚、目录／成员变化、跨批续跑及最终发布变化场景在上述 30 项中通过；本次没有重做全量应用测试或浏览器／删除流程审查。

[首轮失败日志](./postgres-initial.log)保留了新增 fixture 零版本假设错误、事件 null 数据断言，以及直接 TypeScript 视觉线程超时后共享队列 claim 的连锁失败。后续使用相同源码的编译入口复验；两个未知计数断言的后续修正也有独立失败／通过输出。没有把搭建失败算作通过，也没有因这些问题重跑基准。

[输入证据](./fixture.json)明确说明原暖 dump 来源版本为 1，两份新克隆都将作品指纹和历史完成快照的 revision 映射为 0，并移除对应非写入、epoch 为 0 的作品源行。已核对两克隆的映射、计数及全部记录的域摘要一致，图片级缓存与内容／成员签名保留。这是同一原样本经相同条件构造后的对照，不能声称原 dump 天然缺源。

核对了私有原始结果、[测量摘要](./measurement.json)、[源码摘要](./source-hashes.json)及[原件保留核验](./preserved-input.json)：同一 driver SHA，双方 native／reader／视觉线程产物一致；修复后四个核心源文件 SHA 与最终测量快照完全一致。原 dump 和 2,000 张媒体的内容／物理属性摘要前后不变。

唯一串行 A/B 为墙钟 8,065.031 → 3,090.967 ms，实际 SQL BEGIN 471 → 24，SQL 7,724 → 704，API 5,588 → 593；热批 0 → 4、作品复用 0 → 50。两端规范化结果摘要相同，原图读取／哈希／解码／候选／精比均为零。SQL、API、驱动事务和持久遥测事务的口径已分列；旧资料峰值 0 保留为旧采样缺陷，没有作为有效零内存或性能增幅的依据。

## 范围限制

本结论覆盖当前修复和证据的一致性，不证明生产已发布，也不把一次本机合成暖缓存测量换算成 NAS 秒数。生产根因依据是运行结束后的只读快照，旧代码没有原因日志，不能补造历史回退事件。桌面验收由另一 agent 单独记录，本审查未声称完成该部分。没有运行全量测试、生产查询、部署或删除操作。
