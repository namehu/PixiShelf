# 疑似版本最小闭环验收

## 基线与授权范围

基线 `main` / `9eb09d72`，开始时工作区干净。用户批准将离线视觉匹配接入现有检查、图片对照、人工选版本与单对删除；相关测试、独立审查与桌面/手机浏览器验收后提交暂停，不重复全量验证。

复杂内核由 GPT-6 Astra / high 实施；App/界面及 Worker 注册由 GPT-6.1 Sol / xhigh 实施；独立审查另起 Sol / xhigh，新上下文，不由实现者自审；浏览器 Sol / medium。两位实现者按文件边界协作，主 agent 负责契约、文档、隔离样本及集成。没有创建新的用户任务或恢复自动开发。

视觉结果是疑似建议，不识别哪份无码，也不承诺无误配。生产非原视图增加局部支持条件，保持原实验代码和记录不变。首版视觉范围上限 10,000 个登记原件/艺术家检测，超预算明确未完成；不是已支持 50 万图视觉检测。精确与包含流程保持现有边界。

## 隔离环境与恢复依据

使用已有隔离 PostgreSQL 容器 `pixishelf-dedup-postgres` / `127.0.0.1:55432` 下全新 `dedup_visual_test` 与 `dedup_visual_browser`，已全部正式 migrate deploy 成功，不使用 db:push。App 5480、Worker 健康端口 55813；对照图片直接使用受保护媒体路由。独立运行目录 `/private/tmp/pixishelf-visual-product-b1/source` 避免与用户 F5 共用 `.next`。环境和临时账号只保存在私有目录，不纳入 Git。

浏览器使用同一艺术家的合成几何图：A10/B12 有 6 张原文件相同、2 张经白边或轻遮挡后视觉相近，其余 A2/B4 不同；C10 是独立内容。仅授权浏览器删除 B，手动保留 A，验证明确舍弃未配对图片。逐文件 SHA 清单是可重建样本与完整性核对依据。真实开发库、真实媒体和用户服务不参与迁移或删除。

## 已知误配修正与代价

生产匹配增加固定条件：非原图视图至少有一个有效局部区域支持。用原有冻结报告及缓存特征核对 135 个案例，读取和解码原图均为 0 次，没有搜索阈值。已知模板误配（全局距离 12、局部支持 0）被拒绝，真实缓存特征加入回归测试；离线实验结果保持原样，未改写成生产成绩。

这个条件损失 4 个原端到端非对称裁剪命中，该项由 6/9 降至 2/9；直接比较由 8/9 降至 2/9。其余此前接受类别保持。它是减少弱证据误配的取舍，不能据此宣称已解决所有误配，亦没有真实有码/无码对的生产识别率。

## 独立审查与修复

独立 Sol / xhigh 首轮指出两项 P2：视觉单图超时不应清除已经完成的精确/包含结果；视觉发布的目录/作品锁顺序不得与写入协议相反。修复分别引入确认子进程退出后的视觉阶段未完成处理，以及统一目录先于作品的锁顺序；失租约和子进程无法退出仍阻断。复审继续指出目录锁工具每批最多 100 项，发布必须在先取得根锁后分批锁目录，不能将视觉范围上限直接当作单批容量。

端到端定向测试另外发现协议 3 在 claimScope 中被旧白名单安全拒绝，以及 PREPARE 恢复尚未接纳维护 v4；均补齐。审查者只复审这些修复，不重新展开全量审查。

最终差异复审通过，无剩余 P1/P2。图片确认清单中重复的左右全局配对摘要也已去除，仅在删除方显示一次明确的保留/删除未配对数量；该展示改动独立复审通过，对应组件 7/7、单文件 lint 通过，不改变确认声明或删除逻辑。

## 浏览器验收

在独立 App 5480、合成库上，通过真实 UI 登录和发起检查。桌面 1200×900、手机 390×844 初始选项默认关闭疑似；实际检查只产生 A/B 一对，8 张配对、A2/B4 未配对，C 未进入结果。没有默认保留者或视觉批选。对照四种筛选与前后翻页正常，桌面显示真实两张图片，手机左右切换保持当前页；明确选择保留 A 并保存后才可准备单对预览。

首次登录后跳转曾出现账户防护刷新提示，按提示刷新消失；未绕过校验。截图与后续删除结果以最终证据为准。

确认页保留 A10、待删 B12；三声明均未勾选时禁用，单独缺少内容损失声明时仍禁用，三项齐全后启用。浏览器首次最终点击被自动审批拒绝，要求用户在动作前直接确认这一个合成作品的永久删除；没有重试或改用其他渠道执行。用户随后明确回复“确认，仅删除隔离测试 B”，浏览器再次进入原预览，获准并仅点击一次删除。Worker 完成后刷新清单并整页重载，仍显示 A 保留、B 已删除，双方未配对 A2/B4 的冻结计数和损失说明保持。

## 最终结果

实现、定向检查、独立复审与浏览器完整闭环均已完成：检查→图片对照→选择→确认门禁→单对删除→刷新记录。代码与此验收记录一并提交后暂停，不自动开始下一批。没有将本轮新迁移部署到用户实际开发库，也未重建或重启用户 Worker；用户实际环境使用前仍需按运维手册正式迁移、重建配套 Worker 后再启动 App。

文档校验 271 个 Markdown 通过；图示检查 33 个图源及 23 个嵌入 Mermaid 块通过，已更新检测流程 SVG；只保留本轮图源对应的 SVG 变化。`git diff --check` 与主应用大写路径检查通过。

操作证据保存在合成库：run `be07dd79-25c0-4fc2-b01a-1d41c60446d6` 为 COMPLETED / visual COMPLETE；operation `0e0d7101-a36d-42f5-b212-2141aa89961b` 为 DIRECT_DELETE / DELETED / 协议 3，已删 12 文件。删除前 32 文件全部核对未变，删除后由 `/private/tmp/pixishelf-visual-product-b1/verify-result.cjs` 独立核对 A/C 未变、B 文件和业务记录消失。没有为后续验收重新扫描或重复此前套件。

隔离启动脚本为同目录 `start-app.sh`、`start-worker.sh`；环境和凭证在私有 `browser.env`、`manifest.json`，不纳入提交。原 IAB 后续连接丢失，最终截图复核允许新建 Chrome 的 5480 测试标签；禁止访问或关闭用户已有 5430 标签。

等待用户确认时曾停止测试服务；取得确认后复用原样本和预览重启，没有重建产物。验收完成再次停止本轮 App 5480（PID 10986）和 Worker 55813（PID 10994），两个启动会话均正常退出。仅保留隔离数据库、A/C 合成文件和证据；未停止用户服务，所有子 agent 已收口。
