## 独立审查中发现并修复的问题

1. 同一作品对超过 1,000 条图片证据时，跨批期间调整顺序可能使新的 ordinal 与已复制行冲突，从而漏条目。隔离 TEMP 表复现为源 1,001 行、目标 1,000 行，见[复现 SQL](evidence/hot-run-reuse-2026-10-30/order-copy-pre-fix-repro.sql)。改为保存对照顺序／分类摘要并在复制与最终发布重核，变化则重建本轮复制。
2. 复制终态附近修改媒体分类，旧终态标志残留可能让正常回退进入错误分支；回退现在一并清理本轮复制状态，不清持久有效缓存。
3. 重建复制后，已废弃的复制不能重复算作最终复用量。`copiedRows`、`reusedRelations` 按持久检查点纠正；`discardedCopyRows`、`discardedReusedRelations` 单列已提交后废弃的工作。废弃不代表一定已重放。最终重置的修正合入现有一次遥测保存，不增加写事务或同事务重复采样。

上述三项已在 PostgreSQL 定向复验通过（17.33 秒），覆盖跨批暂停改序、最终发布前改序、最终发布前分类变化及净计数／废弃工作分账；完整热检查专项和独立审查最终结论另行记录。测试中一次大批量改序触发既有 Image 更新逻辑耗时，随后失败 fixture 残留根身份导致下一次 warmup 被拒绝；仅重置本轮 core 测试库，保留失败现场备份，A/B 样本库不受影响。这些环境失败不算作修复通过。

## 同样本热检查结果

使用保留的同一批 2,000 张图片、50 部作品、同一暖缓存 dump；各版本只测一次，按 v0.55.2 → v9 串行执行，期间没有其它本轮 App／Worker／数据库测试竞争。原媒体属性和内容摘要、备份 SHA 前后不变。原始口径见[测量说明](evidence/hot-run-reuse-2026-10-30/measurement-notes.md)、[测量 JSON](evidence/hot-run-reuse-2026-10-30/measurement.json)、[源码与驱动摘要](evidence/hot-run-reuse-2026-10-30/source-hashes.json)。

| 同一口径                              |    v0.55.2 |    本轮 v9 |
| ------------------------------------- | ---------: | ---------: |
| 完整执行墙钟                          |  12.448 秒 |   3.475 秒 |
| 实际 SQL BEGIN（含队列／围栏）        |        666 |         24 |
| 执行器 mutation／finalization 事务    |        659 |         21 |
| 专用客户端实际 SQL 条数（含控制语句） |     12,741 |        704 |
| 专用客户端 Prisma API 调用            |      9,811 |        593 |
| 定时采样的整个基准进程 RSS 峰值       | 163.83 MiB | 161.61 MiB |
| 实际睡眠的调度等待                    |          0 |          0 |

墙钟下降 **72.085%**，SQL 事务下降 **96.396%**，执行器事务下降 **96.813%**，达到本轮 60%／80% 目标。两侧均为 25 个精确组、2,000 原件缓存命中；语义结果摘要完全一致。v9 实测读取字节、哈希重算、解码、候选、精比和索引节点访问均为 0；50 个作品指纹直接复用，4 个热批次，复制 2,125 条必要明细。任务资料估算峰值 6.69 MiB，不等于整个进程 RSS。

v9 持久汇总分别记录属性核对约 0.307 秒、指纹复用提交业务约 0.445 秒、整轮复用判定约 0.156 秒、结果复制约 1.899 秒。这些是对应代码段，不应与包含它们的事务总耗时相加。运行时成功提交的 20 个 mutation 事务另拆出获取 23.7 ms、前置围栏 27.1 ms、业务 2,647.0 ms、后置围栏 22.8 ms、提交收尾 29.1 ms；最终事务拆分未采集，快照明确标记截止时间与 `complete=false`。

本机单次暖缓存对比没有统计置信区间，也不是 NAS 实测；不能将 72% 直接套到生产 175 秒。生产侧仍须发布后按同一输入与缓存条件采集日志。

测量后发现整轮快速通道的日志 `inputDigest`／`searchVersion` 保留了初始 null，已仅从持久复用检查点补填这两个身份字段；没有改动查询、算法、事务或计时。补丁生命周期专项 12 项通过，独立复审另记。原 A/B JSON 保持测得的 null，不回填、不重复整批测量；正式服务验收构建使用补丁后的独立源码快照。
