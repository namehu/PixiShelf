# F03 第二批：数据库往返优化

2026-10-27，基线 `ea0a140b`，分支 `codex/dedup-visual-batches-f03`，沿用独立 worktree。用户授权完成相关验收、提交后暂停；不合并主目录，不升级当前开发库，不操作真实媒体或用户服务。

## 范围与执行顺序

先定位持久视觉检索的重复事务、重复守卫查询及小批次提交开销，再只优化主要热点。复杂实现由 Astra / high 负责；独立审查 Sol 6.1 / xhigh；桌面浏览器 Sol 6.1 / medium。主 agent 维护契约、集成和记录。

维持既有匹配算法、所有源与执行守卫、锁序、预算、持久检查点语义和 v5 兼容性；公开上限仍为 10,000。不得通过减少必要校验、扩大无界事务、提高预算或忽略失败来获得性能改善。不扩展 UI、删除协议、100,000／500,000 测量或真实图库实验。

## 同样本比较要求

复用第一批确定性合成特征分布，重点验证 10,001 条的跨批关系。优化前后使用同样的媒体 ID、SHA、特征及源快照，保持计量器、数据库环境、应用工作状态起点和测试配置一致；分别保存输入摘要、实现版本及结果证据摘要。计时范围为已准备特征的检索内核，不能冒充原媒体读取、解码或完整 Worker 性能。两轮顺序为基线后优化，不强制清空操作系统或 PostgreSQL 缓存；SQL／事务减量是主要确定性指标，单次耗时仅报告本机观测，不据此承诺稳定加速比。

记录 SQL、写入语句、事务、耗时、候选比较、posting、结果证据、特征查询上界及内存计量边界。先小样本正确性，再各一次必要的代表性规模运行；不重复全量应用验证。若复用历史完整基线，明确其环境和样本差异，不作为严格同现场 A/B。

## 验收与收口

定向覆盖恢复／回滚、取消、失租约、源或目录变化、历史缓存生命周期、冷／热／FULL；只重跑被本批影响的范围。独立审查通过后使用最终 Worker 产物验收桌面检查、对照、选保留和删除确认，不实际删除。浏览器仅报告实际完成的操作，未覆盖项单列。

方案已固定为 QUERY 的 5 → 2 事务合并：主循环与候选读取共用事务，比较保持事务外，事件循环让出后由完整提交事务重新验证。其他阶段和通用 DB helper 不改。取消、执行状态及源／目录／写入声明的变化注入覆盖读取结束至提交之间的边界。

隔离样本生成与测试脚本作为恢复依据，数据库仅使用独立 55432 服务的任务专用库，私有凭据不入仓库或报告。

唯一代表性规模测试及清理完成，1 passed／11 skipped，套件耗时 939.03 秒。其余测试按名称或 opt-in 门禁排除，不将 skipped 计为通过。没有重新运行第一批的两档长测。

四次输入摘要（两轮各前后）均为 `e2277cfd8452d73c96a6265c4fa00295ee3ceaa14e53bfc6a3b0f48e0e23fd13`；两个完整结果摘要均为 `4262425b15acf9150d0506fdf512e1d1dca99b784faaac5a4672657899ba7503`。断言逐项比较完成状态、原因、计数、全部候选 key、每个作品对的逐页 kind 和左右媒体 ID，不只核对数量。优化实现文件 SHA-256 为 `d422096c91ad292fd4ad96b2fd7516b603efdaf2f42dbf94212243b768567a06`。

SQL 包含 BEGIN／COMMIT 和守卫的 no-op 写入；写入数是语句数，不是修改行数或 WAL 字节。两轮共用进程累计 max RSS 为 377,290,752 bytes；20ms 采样 heap 峰值分别为 176,366,088／136,498,328 bytes。fixture、Prisma、先后顺序和 GC 均影响内存，不能据此宣称产品内存下降或独立峰值。计时排除建 fixture、digest 查询、工作态重置及清理，不包含队列调度、原图解码、NAS 和并发使用。

往返减量明显，但实际单次耗时改善较小，剩余约 38 万 SQL 仍是成本。本批不表示数据库性能问题已全部解决，也不开放大于 10,000 的检查；10 万／50 万另批推进。
