## 实现与定向证据

只在 QUERY 提交中使用 `QueryDirectoryScope`，其余阶段和最终 PUBLISH 保持原路径。缓存只保存冻结目录描述；每次先检查执行围栏，读取当前 item 完整身份（含 null／零版本、成员快照和 updatedAt），再按原锁序核对当前双根、目录及祖先写入声明和作品源快照。miss 使用一次有界 Media DISTINCT，不重复 JOIN Item、根 DISTINCT 和空尾页；描述超出 128 作品／2,000 目录／1 MiB 时按契约回退，不能截断范围后通过。

Astra / high 的两个测试文件合计 28 个不同用例通过：第一次 batches 19 项通过；新 scope 六项因 fixture 错用 priority 100，在准备阶段被 `system_jobs_dedup_policy` 拒绝，修为规定的 900 后仅重跑六项通过；最后补 mediaEpoch、null 快照及已命中缓存后的回滚三项通过。不把这些分轮结果写成单次全绿。

实际覆盖取消、旧 executionVersion、真实过期 lease、源 revision／mediaEpoch、成员变化、根／目录变化、写入 token、祖先目录 writer、双根锁序、缓存容量回退、51 作品批边界、合法前缀和事务回滚。首次缓存填充后立即回滚的安全性由静态不变量审查说明，没有额外直接测试；回滚动态用例覆盖已命中阶段。20 页小样本连续调用目录推导 1 次；每三个 checkpoint 让行、四次 scan 调用共推导 3 次，完整边、证据和计数一致。这不是实际 Worker 十秒时间片的吞吐测量。

## 5k 探针与数据库计划异常

保留同一 5,000 条特征的 FULL 探针完整通过，冷轮分两个进程从持久检查点续跑。输入／全部候选含负证据／完整发布结果与原 oracle 一致：20,340 次比较，0 次复用。两段耗时 224,232 + 223,612 = 447,844 ms，SQL 87,589，事务 5,451，写语句 14,091；采样 heap 峰值 65,028,056 B、RSS 173,850,624 B。旧 5k 冷轮为 58,521 ms、42,517 条 SQL、2,069 个事务、7,484 条写语句。此轮显著变慢，不能作为性能通过。

归因显示目录优化已生效：首段 QUERY 目录推导由旧 984 次／1,912 ms 降至 11 次／18 ms；瓶颈转为未改动的 posting 查找，完整 5,000 次累计 329,903 ms，平均约 66 ms，而旧首段约 1.6 ms。慢读取又使现有 100 ms 软批次缩小，增加事务及检查点写入。

只读执行计划和统计表明，保留旧规模运行后 posting 表已有约 860 万行，新 run 的约 20 万行不足以触发自动统计更新。规划器把新 run 估为 1 行，只将 runId 放入索引条件，将 key 留在过滤条件，每个查询重复扫描该 run 的索引段。历史 5k 测量时表规模不同，因此当前耗时不是仅由本次源码变化形成的受控 A/B。完整异常轮和诊断保存在 `harness/probe-summary.json`、`harness/probe-runtime-diagnostics.json`，不丢弃异常数据。

两个进程退出后，仅授权专属规模库对 `ArtworkDedupVisualPosting` 刷新一次统计并复核同 SQL 的计划及有界计时；没有修改生产配置、源码、匹配参数或缓存寿命。后续是否执行完整规模轮，由复核结果决定。人工刷新统计不能冒充生产已自动解决新 run 的查询计划问题。

该单次诊断已完成：相同 SQL 与 43 个绑定参数摘要不变，前后均返回相同 85 行。刷新前执行计划过滤 199,915 行，命中 202,362 个缓冲块；刷新后 runId 与 key 同时进入索引条件，命中 248 个缓冲块，只排序返回的 85 行。各五次同 SELECT 的实际 wall 耗时从 65.8–73.3 ms 降至 2.64–3.60 ms；EXPLAIN ANALYZE 自带测量开销的耗时单列为 136.634 → 1.177 ms，不能与普通调用混用。两侧 Shared Read 均为零，结果 SHA 完全一致。详细证据 `harness/posting-statistics-recheck.json`。

此次未改 autovacuum 设置。当前表自动统计阈值约 860,046 行，未来 100k 检索会新增 400 万 posting、超过阈值，但不能据此保证 QUERY 开始前已刷新。生产新 run 在积累大量历史 posting 后的计划稳定性仍是独立待办；不会重跑已被分析过的整个 5k 来替换异常轮，也不会在正常规模测量中手动刷新统计。

冷轮 INDEX 末段已自然触发自动统计，首次 QUERY 的索引条件同时包含 runId 与 key，未触发退化中止条件；人工 ANALYZE 计数仍为诊断时的 1，没有在规模轮中刷新。原始观测在 `harness/scale-cold-index.json` 与 `scale-cold-query.json`。
