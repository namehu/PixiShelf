## 结果

### 密集候选与恢复专项

新增 `visual-dense-resume.postgres.test.ts`，只通过 `ARTWORK_DEDUP_DENSE_TEST_DATABASE_URL` 显式启用，限定专属 `f03_dense_resume_*` 数据库及 loopback 55432。空库正式部署 125 项迁移。99 条预制特征包含 9 条无 posting 页与三部各 30 页的密集模板，已知输出为三对，每对 29 EXACT + 1 SIMILAR，2,700 次比较。

- 同一 fixture 连续运行与每次提交后重建上下文运行，经过 174 次持久让行，完整匹配边、图片 ID、配对证据、计数及终态逐项一致。覆盖 8 查询边界与同查询 90 候选跨 50 槽内页；也核对一次性匹配器及独立已知配对。
- 四类预算在已经提交密集前缀后施加压力，合法前缀保留，最终为 `stage=DONE / visualStatus=INCOMPLETE`，未发布半成品视觉对。原样重入不擅自升额或转为完整成功。预算压力含受控累积计数／posting 行注入，不声称 99 页自然产生 20,000 posting 或 200,000 次比较。
- 旧执行版本零提交，新版本继续；真实队列租约在读取后随可控 clock 到期，旧提交拒绝、持久进度不变，实际过期恢复及新 token 重领后完成。该测试不等同操作系统强杀或 NAS 故障演练。
- 七个不同场景通过。首轮六项通过，比较预算用例修正了“同作品候选不计比较但仍能合法推进游标”的错误测试预期后，仅重跑该项通过；生产代码未改。

首次清理遗漏发现 891 条合成 Image 因 Artwork 删除而被置空归属；已改为保存 imageIds 并在删作品前精确删除。本专属库旧孤儿在核对路径前缀与数量后清理，最终最短 smoke 后艺术家／作品／媒体／运行／索引／候选／配对／任务／租约／目录记录均为零。默认无专用变量时七项跳过；这不是七项执行通过的替代。独立审查确认修复及零残留，未扩展生产清理。

### 规模前置探针

5,000 条预制特征已完成冷 start、不同进程 resume、热轮；完整冷轮 58,521 ms，热轮 51,633 ms；SQL 分别 42,517／42,309。冷轮实际比较 20,340 次，热轮 0 次比较、20,340 次关系复用，全部边与配对、图片 ID 及发布摘要一致。前后输入摘要一致，恢复初始检查点与前段保存值完全相同。

本测试绕过特征准备，冷仅指没有可复用作品关系，不是数据库 buffer cache 冷启动；热轮仅证明关系与比较复用，不代替自身或同 SHA 特征缓存验证。原图读取／解码均为零。SQL 和内核 wall 排除生成及审计；进程 max RSS 包含 fixture、oracle 与测试框架，不能称纯内核内存。

### 首次 10 万准备的环境故障

第一次生成至 66,000 条媒体／66 个 item 时，Docker 虚拟磁盘仅余 7 MB，PostgreSQL 报 `53100 No space left on device`；运行仍为 VISUAL/PENDING、检查点为空，尚未进入内核。失败日志和只读状态已保留，不将这次准备失败当作 10 万完成。

主 agent 仅回收可重新生成的构建缓存：先按已核验 PixiShelf 闲置非共享 ID 释放约 2.7 GB，再按项目描述过滤释放 5.525 GB，虚拟磁盘恢复 8.5 GB 可用。中间一次按超过 30 天过滤的调用经自动审批超时后重试，实际释放 0 B。没有删除镜像、容器、卷、旧数据库或媒体。仅清除本次失败的部分 fixture 后按原算法、样本和源码重新准备；原 5,000 探针保留。

### 首轮内核的测试额度不一致

完整 100,000 条特征已生成、4,000,000 条 posting 已提交。Vitest 私有预算提高了文件、posting 与比较上限，但正式迁移的 `artwork_dedup_relation_cache_bounds` 仍限制两种视觉比较计数各不超过 200,000；下一次拟提交 200,003 时 PostgreSQL 拒绝并回滚，最后合法计数 199,955 与 QUERY 检查点保留。该约束保护按预期生效，生产无需修改。

失败进程只留下每 10 秒进度，精确末尾 profile 未保存，不能将它拼成完整冷轮性能结果。已授权仅专属规模库把该 CHECK 两个视觉计数上界改为 10,000,000，其他条件原样保留；先保存原定义和失败现场，补失败 profile 落盘，再复用相同输入重跑失败冷轮前缀。普通库、迁移文件和生产预算保持原样；超过 200,000 的测试结果仍在时，不能直接恢复原 CHECK，必须先清掉本次合成范围或删除整个专属测试库，恢复依据随证据保存。

### 10 万完整冷轮

100 部作品各 1,000 条预制特征，共 100,000 条；全部原始 SHA 不同，建立 4,000,000 条 posting。独立 oracle 预计 2,789,280 个候选槽、1,344,456 次跨作品比较、29 个候选作品对及 2 个发布对。全部匹配边、证据、配对图片和摘要逐项一致：首／末作品配对 1,000 张；另一组配对 800 张，双方各 200 张未配对，展示清单共 1,200 项，不能误读为单作品有 1,200 张。

冷轮在预设持久检查点退出 PID 43317，PID 54223 精确核对初始检查点和 1,013,777 次前缀计数后继续，最终 `COMPLETE` 且无未完成原因。两进程合计内核 5,489,728 ms（91.50 分钟），SQL 2,120,299 条、111,909 笔事务、396,414 条写语句；写语句数不等于写入行数。实际比较 1,344,456 次，关系复用为零。输入 SHA 保持 `b19735b712c996b45339eb90a85e4ba3c07395fbe1368d314052b31074cea60a`；发布摘要 SHA 为 `e6a782c7cedcca80356dbf51a79e588d289f1089cf2dba58a41b98cd60ca4e9e`。

采样 heap 峰值 73,562,496 B、RSS 峰值 190,201,856 B；进程值包括测试框架、Prisma 和内核测量前的准备，不包括 PostgreSQL 服务内存。QUERY 一批最多 8 张查询图／50 个候选槽／58 条合计特征，实测最多 48 个作品参与批校验；单作品读取上限实测 1,000 条。结束时专属库 1,294,963,503 B，包含 schema、探针和 fixture，不作为本轮新增写入字节数。

累计 Prisma SQL event duration 为 2,872,923 ms，其中 `ArtworkDedupMedia`／`ArtworkDedupItem` 联查 223,547 条、2,584,788 ms，约占 90%。最重查询是从指定作品媒体中 `DISTINCT` 推导根身份及分页目录清单。QUERY 事务 wall 合计约 5,308,542 ms，包含 JavaScript、数据库等待和往返，不等于纯数据库 CPU 时间。本批仅定位成本，未减少安全校验或更改生产查询。

该样本比较数是 5,000 探针的约 66 倍，候选槽约 60 倍，不能只按特征条数 20 倍解释耗时，也不能与第三批不同的 10,001 条 fixture 当成优化前后 A/B。热轮结果见下节，不据此宣称缓存吞吐达标。两段冷轮及先于结果审计保存的内核统计见 `harness/scale/cold-start*.json` 与 `cold-resume*.json`。

同一输入、媒体 ID 和冻结源码完成热轮，PID 74671。内核 5,276,663 ms（87.94 分钟），整个 Vitest 阶段 5,312,346 ms（88.54 分钟），在原定 90 分钟边界内正常结束，runner 退出 0。最终 0 次新视觉比较、1,344,456 次关系复用；4,000,000 posting、29 个候选对和两组完整发布结果与 oracle／冷轮一致，输入及发布摘要不变。

热轮 QUERY 特征上界仍为 8／50／58，guard 最多 51 部作品，单次媒体查询最多 1,000 行；结束时专属库 2,017,948,463 B。热轮进程 max RSS 包含进入内核前的克隆等准备，不能与内核采样 RSS 混称；两者均不包含 PostgreSQL 服务内存。

独立复核发现热轮 SQL 总事件计数为 2,119,612，但归因 profile 的 statement 合计为 2,119,611：BEGIN 为 111,962、COMMIT 为 111,961，没有 ROLLBACK；归因中少收录一条 COMMIT，具体时序未证实，不补造该事件。事务及写语句数与独立计数一致；冷轮不存在该差异。

本样本热轮仅比冷轮少 687 条 SQL，内核耗时低约 3.9%。关系缓存避免了比较与重新配对，但仍重建索引、查询当前候选及执行必要的提交校验；因此本批证明缓存正确性，未证明 10 万场景已有可接受吞吐。原件读取／解码仍为零，不把预制 READY 特征实验称为真实图库全链性能或特征解码缓存验收。完整热轮与先行落盘内核统计为 `harness/scale/hot.json`、`hot-kernel.json`。
