## 已修复发现

**P2：最终围栏与来源释放形成锁序反转。** 初稿在执行器完成事务中先锁目录根，再调用 `buildArtworkDedupGroups` 获取 catalog 锁。并发 App“允许重新导入”的 `lockSources` 使用 catalog → 双根顺序，可能出现一侧持根等 catalog、另一侧持 catalog 等根的死锁。此外按目录 ID 分页可能先锁 source 根、下一页才锁 archive 根，与统一双根顺序冲突。

最终实现的 `assertArtworkDedupCacheDirectories` 先获取 catalog 锁，读取至多两个参与根并核对每根唯一身份，一次按既有全局顺序锁定全部根，再分页核对目录，随后最终作品快照核验获取 Artwork 锁。真实 PostgreSQL 用例覆盖 102 个目录跨页、catalog → 双根的并发来源释放，以及 archive → 双根的独立竞争；修复后通过，见 `migration-and-locks.log`。已复审实际生产修复及测试，不以仅调整测试关闭问题。

迁移测试另增加 exclusive opt-in 门禁，避免普通 `QUEUE_KERNEL_TEST_DATABASE_URL` 套件被专库名称限制误伤；只有明确开启 `ARTWORK_DEDUP_RELATION_UPGRADE_EXCLUSIVE=1` 才重建旧列并执行非空升级探针。
