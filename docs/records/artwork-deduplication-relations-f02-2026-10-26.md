# F02 第二批：作品关系复用

## 范围与环境

基线 `4ea9de96`，独立 worktree `/Users/namehu/.codex/worktrees/artwork-deduplication/PixiShelf`，分支 `codex/dedup-relation-cache`。实施 Astra/high、独立审查 Sol 6.1/xhigh、桌面浏览器 Sol 6.1/medium。第一批已合回 main 并升级开发 Worker，见[本地升级记录](./operations/artwork-deduplication-cache-local-upgrade-2026-10-26.md)；本批新代码和迁移不自动进入主目录及开发库。

复用同艺术家兼容完整历史检查中的包含、部分重复和可选视觉关系。精确组、当前索引及候选仍重建，预算包含复用项。新增或内容／代表资格变化重算相关候选；排序按当前页码投影，重复同 SHA 页允许保留等价的一对一映射。不复用审核选择和清理授权，不改变当前视觉上限、图片算法或删除规则。

新增正式迁移 `20261026000200_artwork_dedup_relation_cache`，仅为检测表增加关系版本、视觉输入摘要、候选证据及计数，不扫描媒体、不新增缓存服务。旧记录缺少版本时 miss；完整检查绕过关系缓存。worktree 与主目录生成客户端路径及 inode 独立，主目录客户端和 122 个已应用迁移保持不变。

验证使用既有隔离 PostgreSQL `127.0.0.1:55432` 中新建专用库和合成临时媒体，禁止连接开发 `5432/pixishelf` 或真实媒体。恢复依据为隔离样本生成脚本、manifest 和文件摘要，失败可重建合成数据；本批不构造生产恢复承诺。

这些数字只证明受影响范围与比较复用，不代表零 SQL、零写入、稳定耗时提升或 50 万规模。文件属性、源与租约检查、本次证据写入和当前索引／预算仍有成本。最终锁序修复后的 SQL 计数如下；包含完整检测的源／属性／租约检查及任务写入，不是单独的 matching 微基准，也未与旧版同样本比较总耗时。

21 个不同用例通过：4 个 Executor 矩阵、4 个最终发布围栏、8 个单元（4 个新缓存／预算用例与4个既有视觉匹配）、2 个 DB 迁移／锁序用例、1 个 App retry、2 个既有 F01／52 原件批量兼容用例。重复运行用于修复后确认或刷新测量，不重复计数。DB 和 Executor typecheck 通过，App 两个相关文件 oxlint 通过；没有全量 App lint/test/build。

- 新增作品与旧负例形成关系、内容变化仅重算关联项、代表变化恢复曾被 PARTIAL 抑制的 VISUAL；标题／排序投影当前页码，旧审核选择不复制。
- 缓存物化后取消、失租约、源或目录变化均不能完成发布；FULL／参数版本不符不使用关系缓存，retry 清空摘要、候选和计数。
- A~B、B~C 不传递合并；新增密集候选仍触发当前预算；未达到80%的候选作品对也计入上限。
- 历史 GC 等待读取共享锁，新结果自含证据；旧历史删除后可完整重算当前候选，不因旧游标跳漏。
- 非空升级测试在隔离库事务内还原122迁移时的列形态，写入旧作品、检测项、关系及视觉缓存，再运行新增 migration SQL；记录保留且新字段默认 miss。该测试不冒充一次正式非空 `db:deploy` 演练；完整正式 `db:deploy` 另在新空库完成。
- 独立审查发现 final 新目录守卫先锁根、后锁创作者协调锁，与来源释放顺序相反。修复为创作者协调锁→全部参与根→目录分页→作品；真实 PostgreSQL 102目录跨两根／两页竞争通过。

唯一一次必要 Worker 构建通过，保留既有3项 CJS/import.meta 警告。开发服务未重启，本批浏览器环境与最终审查结论另见下文。
