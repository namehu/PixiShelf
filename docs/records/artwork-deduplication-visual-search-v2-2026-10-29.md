## 识别效果与指标使用边界

[实际图片特征 oracle](./evidence/artwork-deduplication-visual-v2-real-feature-oracle-2026-10-29.json)使用已有隔离副本中的9个输入、共90张变体，来自3个来源组，不是9个独立作品家族。生产特征提取器解码后穷举4,005对图片，301条精比通过的边与新索引完全一致。JPEG缩放、白边、2.5%和5%轻裁剪、白色遮挡各9/9；黑色遮挡8/9。此处“无检索漏边”不等于画面语义无误配。

小样本中2对构图相同、内容不同的真实模板图仍误配，旧算法也会检出；本轮没有调整精比阈值。这些样本在实验后人工检查标注，不能冒充盲测生产识别率。疑似版本仍需要逐张核对，不自动决定删除。

正式5k性能测量发生在后续进度/遥测修复之前。证据中的sourceBefore/sourceAfter记录该次源代码摘要；后续没有改变检索阈值、索引和配对规则，但追加了精比计时及缓存原因观测。表内数值代表被测版本，未另行重跑整套性能基准，更不等同于生产NAS承诺。

## 收尾审查与续跑补证

独立复审发现并要求修复：读取心跳延迟覆盖结构化进度、活跃时间重复累加、检索版本缺失、旧记录未知数量误写零；随后补齐检查页自动调度等待文案、最终事务DB测量及后置清理失败时释放内存索引。详情由[独立审查记录](./artwork-deduplication-visual-search-v2-review-2026-10-29.md)维护。

真实PostgreSQL专项 `v8 new executor instance resumes a PostgreSQL file checkpoint without recounting committed media` 已通过：32-byte读取片保存HASHING游标和ORIGINALS/SCHEDULER进度，新 `createArtworkDedupExecutor` 实例及真实读取子进程从同一数据库续跑，最终6原件、6条media记录、192字节，无重复累计。执行该用例时1 passed、69 skipped是测试名过滤，不能理解为70项全部验证；本项没有实测操作系统SIGKILL。视觉阶段的中途恢复另由2,000比较后更换计算线程的持久游标专项覆盖。

复审另发现立即让行的队列时间边界：计算阶段取消固定冷却后，构造的availableAt在最终事务检查时可能已过去1ms，旧时间验证会回滚让行。该项使用真实队列finalize路径专项修复与复核，不以mock scope.retry的单测替代。修复仅对显式schedulingYield在最终提交取max(requestedAt, finalizedAt)，保持未来时间和同attempt。真实PostgreSQL先复现两处1ms漂移失败，再7个新增用例通过；最小相关围栏/控制/让行回归28 passed、58因范围过滤未选中，runtime typecheck通过；独立审查者另用实际源码bundle复验3个场景通过。

最终遥测口径维护在[当前功能规格](../features/artwork-deduplication.md#性能取证)，DBX模板字段改名为lifecycle_complete以避免“全部采集完整”的误解。该轮没有为测量最终COMMIT耗时再追加回写事务。
