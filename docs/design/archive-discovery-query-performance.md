# 发现来源查询性能

## 生产基线与问题

用户提供的 PostgreSQL 15.14 执行计划：目录 4,182、收件 1,383、来源 37、忽略 191 条。
状态统计参与记录 3,861 条；收件表 Seq Scan loops=3,861，每轮过滤约 1,383 条，
Execution Time=2496.682 ms，shared hit=531897，其中收件扫描 shared hit=509652。
没有共享磁盘读取或排序落盘证据；缓冲命中次数不是节点耗时。

Chrome 实测：包含 listSources 的批量请求 2.75/4.23 秒，等待响应 2.67/4.13 秒；
详情批次 365 ms，单独 listItems 349 ms，单独收件摘要 67–178 ms。
浏览器 TTFB 包含网络和服务处理，不能当作 SQL 独立计时。

## 已实现方案

- 两个收件 URL 非唯一 Hash 索引，SQL 原有候选选择和状态判定保持不变。
- 兼容的 includeCounts 选项和独立认证 catalogCounts 接口。
- 来源及作品请求跳过统计，统计单独传输；全来源计数共享，未绑定筛选按来源缓存。
- 数量加载与失败不阻止内容呈现；刷新、轮询和写操作后的缓存失效覆盖独立统计。

## 本地 PostgreSQL 15 合成基准

仅在临时测试数据库运行。37 个来源、4,182 条目录，其中 130 条不匹配、191 条忽略，
剩余 3,861 条参与聚合；1,383 条收件。没有复制生产作品引用、归档任务分布或敏感内容。
在同一个事务中分别移除/重建新增索引，对当前源码统计 SQL 的全范围和显式来源 ID 范围
各预热一次、测量五次，使用 EXPLAIN (ANALYZE, BUFFERS, TIMING OFF, FORMAT JSON)，最后回滚。

| 范围             | 无 URL 索引中位数 | 两个 Hash 索引中位数 |  降幅 |
| ---------------- | ----------------: | -------------------: | ----: |
| 全来源           |        807.597 ms |            25.624 ms | 96.8% |
| 显式来源 ID 列表 |        806.634 ms |            26.047 ms | 96.8% |

无索引计划中，收件 Seq Scan loops=3,861；加入索引后改用 Bitmap Heap Scan 和两个 URL Hash
索引的 Bitmap Index Scan。外层候选循环仍为 3,861 次，但每次不再全扫描收件表。

这是同机合成对照，不是生产数据副本结果，也不承诺生产会达到 26 ms。

## 本地验证记录

- PostgreSQL 15 隔离库从空库部署完整迁移链成功；另一个隔离库先部署旧迁移、写入合成数据，
  再应用新增迁移，1,383 条收件和 4,182 条目录保留，两个 Hash 索引均有效。
- 匹配测试覆盖 ID、来源身份、两种 URL、NULL 字段、长 URL、多条件命中、候选优先级和时间边界。
  在可回滚事务内移除新增索引，逐项比较统计和作品查询结果，与有索引结果一致。
- 接口测试覆盖默认统计兼容、跳过聚合、认证、来源范围、空来源和未绑定输入约束。
- 组件和真实 tRPC transport 测试覆盖统计未完成/失败时内容可用、缓存数字保留、局部重试、
  独立 HTTP 传输、分类及分页统计键稳定、真实扫描完成转换和标签停用后的轮询停止。
- Prisma validate/generate、数据库包全部 173 项测试、主应用 lint/typecheck/build 通过。
  主应用全量单测的五项本地 socket 测试初次受沙箱限制，提升权限重跑后通过；
  PostgreSQL 专项测试单独在隔离库运行，默认全量命令跳过的其他环境测试不视为已验收。
- 真实浏览器验证尝试两次均因浏览器工具无法加载请求头策略而未执行；不将组件/传输测试
  等同于 Chrome Network 验收。生产数据副本、生产发布与同网络复测尚未执行。

## 发布与恢复

遵循现有备份恢复和停写升级流程，记录数据库备份检查点和 App/Worker 原镜像 digest。
通过 migrate deploy 部署 `20261003120000_index_archive_intake_url_matching` 后发布应用，禁止 db:push。
应用回滚保留新增索引与迁移历史，旧应用兼容；无业务数据修改或媒体文件操作需要撤销。

生产验收仍需使用实际数据复测：全范围和应用显式 ID 条件都保存执行计划，预热后各测五次，
中位数相对原 2.50 秒降低至少 80%，确认不再出现每条目录驱动一次收件全表扫描。
浏览器同网络复测，并验证统计故障不阻塞内容。未完成生产验收不能声称生产已修复。
