# E-Hentai 上传者人工扫描

本文定义上传者发现能力。它维护一个长期画廊目录，并把管理员选中的公开画廊交给归档收件箱；它不是订阅、爬虫调度器或自动下载系统。

## 用户问题与范围

管理员希望保存常用 E-Hentai 上传者，通过人工操作发现其最新或更早的公开画廊，确认后把选中 URL 加入现有归档收件箱。

第一版支持：

- 按上传者名称或数字 UID 保存来源，UID 优先；
- 人工“扫描最新”和“继续扫描更早作品”；
- 在来源页直接取消等待中、重试等待、暂停或运行中的扫描；
- 单次最多返回 100 个画廊，后续扫描使用持久游标；
- 将扫描发现 upsert 到长期目录；30 天扫描运行只作为审计记录，不再承担结果列表；
- 固定展示待处理、处理中、已归档、异常、全部和全局已忽略视图，并实时反映收件、下载和发布状态；
- 分别展示最新覆盖和历史覆盖，并说明本批因达到 100 条、水位或远端结尾而停止；
- 使用去噪的稳定字段标记新发现、已归档、可能更新和版本替代关系；
- 批量勾选后加入现有归档收件箱，或按 Provider/GID 全局忽略并随时恢复；
- 在纯列表和首图预览之间切换，视图偏好保存在当前浏览器；
- 归档或重新启用上传者来源，保留身份与游标；
- 扫描由 PostgreSQL 持久任务执行，可在 Worker 重启后安全重试。

第一版不支持：

- 定时或自动扫描；
- 自动加入收件箱、自动选择质量或自动下载；
- ExHentai、Cookie 或登录凭据；
- 标签、语言、页数和任意搜索表达式过滤；
- 把 Uploader 转换为 Artist；
- 因远端画廊消失而删除、回收或改写本地归档。

## 用户流程

```text
保存上传者来源
  -> 人工扫描最新 / 继续扫描历史
  -> 查看并勾选结果
  -> 加入现有归档收件箱 / 全局忽略
  -> 等待 ARCHIVE_RESOLVE_ITEM 解析
  -> 人工选择 ORIGINAL / DISPLAY 并入队
  -> ARCHIVE_IMPORT 下载和发布
```

上传者扫描只产生候选 URL。归档身份、完整元数据、媒体计划、质量决策、revision 发布和下载恢复仍由现有收件箱链路负责。

## 持久模型

### ArchiveUploaderSource

保存一个公开 E-Hentai 上传者来源：

- Provider、身份类型、规范化身份值和显示名称；
- `ACTIVE` 或 `ARCHIVED` 生命周期；
- 最新扫描已完整覆盖的水位；
- 未完成的大批增量扫描游标与头部水位；
- 历史向后分页游标；
- 最近成功/失败扫描摘要。

归档来源只停止新的人工扫描，不删除游标、运行记录或已归档作品；重新启用后从原水位继续。

### ArchiveUploaderScanRun

每次点击创建一个运行，模式为：

- `LATEST`：从最新结果开始，首次建立最新水位，后续在旧水位处停止；
- `HISTORY`：从历史游标继续向更早结果推进。

运行与一个 `ARCHIVE_UPLOADER_SCAN@v1` System Job 一一对应。只有完整成功才推进来源游标；失败、取消、租约丢失或响应结构不完整不得推进。成功运行明确保存停止原因：

- `LIMIT_REACHED`：本批达到 100 条，当前方向仍可由管理员继续；
- `WATERMARK_REACHED`：最新扫描已经追到此前确认的水位；
- `REMOTE_END`：已经到达上传者最早的公开记录。

运行记录是任务状态和审计边界，不是结果浏览导航。来源页只显示当前活动运行和最近运行摘要；重复点击扫描不会新增需要用户手动切换的结果 tab。

### ArchiveUploaderScanItem

每个画廊保存本次运行看到的 GID、canonical URL、标题、缩略图、上传时间、轻量元数据指纹、替代关系和分类，作为可追溯的扫描审计快照。

终态运行与逐项审计记录保留 30 天。清理只处理扫描操作历史，不删除长期目录、归档结果、来源引用或媒体。

### ArchiveUploaderCatalogItem

长期目录按 `(sourceId, providerKey, externalId)` 唯一。每次成功扫描在保留 Scan Item 审计记录的同时 upsert 目录，更新标题、服务端 canonical URL、缩略图、发布时间、上传者、版本关系、稳定比较快照以及首次/最后发现时间。扫描时的 `ACTIVE` 只写入本次 Scan Item 审计；目录始终保存去除工作流瞬态后的 `NEW`、`ARCHIVED`、`POSSIBLE_UPDATE` 或 `REPLACEMENT`，并关联当时匹配到的活动 Intake/Import。

目录长期保存最近收件项、归档导入和终态摘要。扫描 upsert 会在共享的 Provider/GID（以及待解析 URL）事务锁内读取最新 Intake、Import、本地来源引用事件和其他来源保留的目录摘要，并按事件时间写入权威摘要；Import/Intake 发布、失败或取消使用同一锁域向所有已发现来源传播。无论终态先于某个来源首次发现、扫描与终态提交交错，还是短期工作流已清理后才发现另一个来源，后提交方都会观察并保留终态。即使 30 天收件、Import 或扫描历史已被清理，页面仍能说明项目曾成功归档、失败、取消或重复。canonical URL 只供服务端入箱和身份关联；客户端只得到脱敏地址。

结果读取长期目录，排除全局忽略画廊，再按远端发布时间和最后发现时间通过服务端游标分页。前端使用同一个虚拟列表，只渲染可视区域并在接近底部时自动加载下一页。存在扫描、解析或下载活动时，每 3 秒刷新数据库状态；所有相关工作进入终态后停止高频轮询。

### ArchiveUploaderIgnoredItem

忽略是长期用户决定，不挂在会随保留任务删除的 Scan Item 上。记录按 Provider/GID 全局唯一，保存忽略来源名称、标题、缩略图、上传者和发布时间快照，但不保存包含 gallery token 的 canonical URL。重复忽略使用唯一约束幂等复用；删除忽略记录即恢复，之后仍在扫描保留期内的结果会立即重新出现，否则等待下一次扫描重新发现。

## 稳定分类与实时工作流

| 分类              | 含义                                           | 默认操作           |
| ----------------- | ---------------------------------------------- | ------------------ |
| `NEW`             | 本地、活动收件和活动归档任务均不存在           | 可勾选             |
| `ACTIVE`          | 仅 Scan Item 审计：扫描当时已有活动收件或归档任务 | 目录保留稳定分类，由实时状态接管 |
| `ARCHIVED`        | 已存在本地来源引用，稳定比较未发现变化         | 不重复提交         |
| `POSSIBLE_UPDATE` | 已存在本地来源引用，但稳定字段发生变化         | 可勾选重新解析     |
| `REPLACEMENT`     | 当前远端画廊明确替代了本地已有的旧画廊         | 明确提示，人工决定 |

稳定比较只包含标题、分类、上传者、发布时间、页数、文件大小、标签、expunged 状态和版本关系；标签、别名及关系先按集合规范化。评分、缩略图 URL 和集合顺序不参与比较。页面返回具体变化原因，例如“页数 24 → 27”或“标签变化”。旧记录没有有效稳定快照时显示“已归档 · 无法比较”，不误报更新；下一次扫描会补齐快照。

目录展示状态在读取时与当前数据库关联：

| 固定视图 | 实时状态                                               | 含义                                                 |
| -------- | ------------------------------------------------------ | ---------------------------------------------------- |
| 待处理   | 新归档、可能更新、替代版本                             | 可以加入收件箱或忽略                                 |
| 处理中   | 等待解析、解析中、等待确认、已入下载队列、下载中、暂停 | 去收件箱继续现有流程                                 |
| 已归档   | 已发布本地归档且没有稳定字段变化                       | 可进入作品页                                         |
| 异常     | 最近解析或下载失败、取消、重复/身份冲突                | 记录仍在时去收件箱处理；记录已清理时可重新入箱或忽略 |
| 全部     | 上述全部                                               | 管理与追溯                                           |

扫描分类只帮助人工选择。最终 `NEW/UPDATE/UNCHANGED/ACTIVE_TASK` 仍以现有收件解析器的完整 metadata hash 与领域状态为准；加入收件箱后项目立即离开默认待处理视图，发布成功后进入已归档。

## 结果处置与首图预览

实时处于新归档、可能更新或替代版本的目录项目可以单项或最多 100 条批量加入收件箱或忽略；处理中和已归档项目不可从上传者页重复提交。异常项目的权威 Intake 仍在保留期内时必须去收件箱处理；该短期记录清理后，长期目录会明确提供重新入箱和忽略入口。入箱服务会再次检查全局忽略表与当前 Provider/GID 状态，避免旧页面绕过恢复步骤或制造竞态重复。

忽略与加入收件箱接收目录项目 ID，按排序后的 Provider/GID 获取同一组事务级 advisory lock，并在锁内重新读取忽略和入箱状态。新入箱尝试的检查、Intake 创建及目录关联处于同一事务；因此并发处置最多一方成功，批量中任一项冲突会整体回滚。浏览器先通过管理员接口向服务端申请 submission attempt ID，再把这个服务端签发值随目录 ID 一同提交；浏览器不生成 UUID。网络层重放会复用同一 attempt ID，容量拒绝后的新点击则申请新 ID。

结果区使用固定的“待处理 / 处理中 / 已归档 / 异常 / 全部 / 全局已忽略”切换，不按扫描运行创建动态 tab。所有范围都支持虚拟无限滚动，并共享“纯列表 / 首图”显示偏好：

- 默认纯列表，不创建远端图片元素；
- 首图模式只加载虚拟列表可视行中扫描阶段已保存的缩略图，点击后用 Dialog 放大同一资源；
- 切换显示模式不重新查询、不清空勾选或跳回列表顶部；
- 视图偏好保存在浏览器，旧版偏好升级时默认补为纯列表。

首图不是媒体解析或下载。它不会访问 gallery 图片页、消耗原图额度或新增 Provider Governor 请求。

## 任务与资源边界

新增 `ARCHIVE_UPLOADER_SCAN@v1`，payload 只包含 `scanRunId`。任务：

- 只能由管理员人工创建；
- 固定进入 `ARCHIVE_RESOLVE` lane；
- 每个任务只处理一个来源，最多发布 100 个结果；
- 没有父任务、子任务或自动续跑；
- 搜索页面和批量 gdata 请求都在数据库事务外执行；
- 通过 execution fence 提交运行终态和游标；
- 取消或 Worker 停止后不提交旧执行结果。

Provider Governor 增加 `SEARCH` 请求类。E-Hentai 搜索请求最小间隔固定为 3 秒，可以与活动媒体下载并行，但仍与其他请求共享持久请求间隔和 Provider penalty；`RESOLVE` 和 `DOWNLOAD` 保持现有治理语义。

## 分页与水位

首次 `LATEST` 从最新页开始：

- 结果不超过 100 时保存首个 GID 为最新完整水位，并保存更早结果游标；
- 达到 100 且仍有更新结果时，保存增量续扫游标和本轮头部 GID；下一次“扫描最新”继续该增量段；
- 后续增量到达旧水位或远端结果结束后，才把暂存头部 GID发布为新水位。

`HISTORY` 只推进历史游标，不改变最新水位。Provider 返回的游标必须重新校验为公开 `https://e-hentai.org/` 搜索 URL，不能接受任意远端地址。

来源摘要将两条覆盖状态分开表达：最新覆盖为“未扫描”“还有未完成批次”或“已追到上次水位”；历史覆盖为“未扫描”“仍有更早内容”或“已扫描到最早记录”。它们只描述扫描覆盖，不再与“可能更新”等项目状态混用。

## 收件箱衔接与幂等

扫描结果批量提交复用 `createArchiveIntakeSubmission()`，仍受单次 100、活动容量 1000、URL/身份去重和管理员权限约束。

每次用户点击提交时，页面先调用管理员 mutation 由服务端生成 submission attempt ID，再把来源、目录项目 ID 和该服务端签发值交给入箱 mutation。幂等键由来源、目录项目指纹和 attempt ID 共同生成：同一请求重放返回原提交，新点击才取得新 attempt，因此容量不足后能够再次明确尝试。Provider/GID advisory lock 与锁内状态复核保证重复请求不会创建并行活动项目。随后按 URL 把目录项目关联到实际 Intake Item；未生成 Intake Item 的容量拒绝项保持可操作。扫描层不直接创建 `ArchiveImport`。

## 权限与敏感数据

- 来源读取需要登录会话；创建、归档、恢复、扫描和加入收件箱使用管理员 procedure；
- 全局忽略列表需要登录会话；忽略和恢复决定使用管理员 procedure；
- 仅允许公开 HTTPS E-Hentai 搜索、API 与现有媒体 allowlist；
- 不保存 Cookie、Authorization 或 ExHentai 凭据；
- 普通列表只展示脱敏后的 gallery URL，完整 canonical URL 只在服务端入箱衔接中使用，错误与事件继续使用归档脱敏规则；
- 缩略图仅向客户端返回通过 HTTPS、标准端口和 E-Hentai 图片域名 allowlist 校验且已移除 query/hash 的 URL；浏览器请求使用 `no-referrer`；
- Uploader 是来源账号，不证明 Artwork 的 Artist 身份。

## 验收标准

1. 名称和 UID 来源都能创建，规范化身份不能重复。
2. 每个来源同一时间最多一个活动扫描运行。
3. 单次最多保存 100 个去重画廊；历史扫描从持久游标继续。
4. 增量扫描到达旧水位后停止，不重复制造收件项目。
5. 新发现、活动、已归档、可能更新和替代关系分类可解释。
6. 搜索与 gdata 请求遵守 Provider Governor 的三秒间隔和 penalty，但不因活动下载而让行。
7. 活动扫描可从来源页直接取消；失败、取消、响应不完整和 lease 丢失都不推进水位。
8. 已完成发现 upsert 到长期目录；30 天审计清理后目录和终态摘要仍保留，通过虚拟无限列表自动分页，不生成运行切换 tab。
9. 选中结果只进入现有归档收件箱，不自动下载；一次选择可以包含不同运行产生的结果。
10. 容量拒绝的结果保持可操作；释放容量后的新提交尝试可以入箱，同一次网络重放仍保持幂等。
11. 归档来源后不能新建扫描，重新启用后保留原游标。
12. 新页面复用现有 shadcn/Radix 组件并满足键盘、标签和空状态可访问性。
13. 全局忽略跨来源和后续扫描持续生效，30 天扫描清理不删除忽略决定；恢复后可以重新处置。
14. 默认纯列表不加载远端图片；首图模式只加载可视行缩略图，并可通过可访问 Dialog 放大预览。
15. 最近运行明确显示 `LIMIT_REACHED`、`WATERMARK_REACHED` 或 `REMOTE_END`，来源分别显示最新与历史覆盖。
16. 默认只显示待处理；入箱后实时进入处理中，发布后进入已归档，失败或取消进入异常。
17. 评分、缩略图及集合顺序变化不产生“可能更新”；有效稳定字段变化返回可读原因。

## 发布与回滚

使用 expand migration 新增长期目录、停止原因枚举、关系和回填。正式迁移前暂停活动上传者扫描并建立一致性检查点；部署顺序为 migration、重建并重启 Worker、重建并重启 App。Job payload、type/version 和 capability inventory 不变，但旧 Worker 不会写目录和停止原因，因此不得在 migration 后继续作为唯一消费者。

回滚 App/Worker 前应停止新扫描并等待活动 `ARCHIVE_UPLOADER_SCAN` 终态。新表是附加数据；回滚旧版本时可以保留，不影响现有 URL 收件和归档读取。删除新表与 enum 值属于后续独立 contract migration，不与功能回滚绑定。

回滚 App/Worker 前停止新扫描并等待活动扫描进入终态。新目录是附加持久数据，可以在代码回滚期间保留；删除目录表或枚举属于后续独立 contract migration，不与功能回滚绑定。
