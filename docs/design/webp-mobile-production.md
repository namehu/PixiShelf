# WebP 独立帧播放生产接入

状态：实现、客观验证及当前样本手机人工观感验收完成，未发布；2026-10-08。

## 实现边界

- 保守快速路径仅接受全画布、不混合、不清除的独立 VP8 帧；每帧检查，不预下载全文件判断。其他语义留给现有 libwebp 动画合成器。
- 维持一个原媒体请求。快速路径按输入预算保存压缩数据，供循环与中途顺序重建使用；不缓存整段 RGBA。回退重建时已输出帧只用于恢复合成状态，不重复显示。
- 快速路径按 RIFF 声明尺寸、压缩长度和 WASM/输出/临时空间预算选择；不满足时原路径处理，不扩大总体预算。
- 独立帧双 Worker 四额度；Worker 输出附带媒体时间。播放时钟与解码吞吐分离；实际输入不足暂停时钟，落后才省略可安全跳过的解码，首帧和末帧必须显示。
- 原生 ImageDecoder 仍是后续候选，本轮不同时引入第二套生产后端。
- 保留旧调度诊断作为对照，不把实验阶段的测试文件或 profile 产物作为生产依赖。

## 实现细节

- RIFF/VP8X/ANIM 标准前缀、每个 ANMF 的完整画布/无混合/无清除、VP8 编码尺寸及边界逐项检查。VP8L、ALPH、局部、混合、清除和非标准块布局退回现有动画合成器，未扩大像素/文件总预算。
- 预算：两个各 128MiB 的 WASM 堆 + RIFF 声明压缩长度 + 8MiB 输入块余量 + 六个 2MiB 帧临时余量 + 五幅 RGBA（四输出与可见 Canvas），总和必须在 maxManagedBytes 内；maxHeapBytes 至少容纳两个堆。否则原路径。
- 单压缩帧超过 2MiB 时转顺序路径；快速路径实际输入块超过 8MiB 时报告预算错误。压缩预读最多四帧，累计达到 2MiB 停止继续读取。已收原媒体以 64KiB 块保留，防止小网络块造成无界对象数量；这部分用于循环和顺序重建，不是整段 RGBA 缓存。
- 只在待解码帧已过期时根据实际媒体时钟和解码 EWMA 省略安全帧，预测最多 100ms。已有输入中的过期候选继续扫描；不为了等待未来预测帧而停住当前解码。
- 原生 C 合成器未改，只在固定构建中导出 libwebp 已有的 WebPGetInfo / WebPDecodeRGBAInto；预编译及原生 ASan/UBSan/差分检查已重建通过。独立子 Worker 纳入内容版本 hash 和应用资源复制。
- 诊断增加 pipeline、fallbackReason、decodeOmittedFrames；legacy 调度仍使用顺序路径，decodeStrategy=sequential 可用于内部对照。普通 UI 不增加缓冲/loading 提示。
- 中途依赖回退需要重放解码已收帧以恢复画布，可能短暂等待；不输出已交付帧，也不重发媒体 HTTP 请求。回退预留压缩与输出内存，可能比直接走原路径更早触及内存门禁，不承诺所有依赖链都实时。

## 发布与剩余边界

构建已将独立子 Worker 纳入资源 hash 并复制进应用静态资源目录。应用更新后刷新页面会使旧协议缓存失效并使用新资源；当前正在运行的实例不会被升级中途替换。回退应用版本即可回到旧路径，无数据库或媒体迁移。

一般 WebP 的播放正确性仍由原合成器兜底，不保证所有帧都进入快速路径、不保证任何设备实时。依赖链中途恢复可能耗时；第二轮及以后的子 Worker 异常会停止并报告错误，避免错误重建循环次数。浏览器真实进程内存、温控和完整部署反代环境未用此单机实验代替验证。ImageDecoder 尚未作为生产首选，本轮也未增加第三个解码 Worker。

已登录作品详情地址加 `webpDiagnostics=1`，刷新并打开 WebP 弹窗，可运行旧调度、新调度及新调度不绘制对照。开始测试会停止正常播放及自动浏览，完成不自动切图或恢复，不计为正常观看；停止、切图、关闭、后台及 120 秒超时保留部分结果。普通播放不显示 loading。

报告支持复制、下载及手动复制回退，只在页面内存保留最近十份，不上传；移除参数并刷新关闭入口。诊断默认关闭，开启后每类耗时最多采样 4096 项。仅记录匿名运行编号、环境、资源版本、尺寸与性能，不包含媒体路径、标题或凭据。

`playbackWallMs` 从首帧到结束，包含暂停和缓冲；输入完成时间从尝试开始计算，两者不能直接相减。`pipeline` / `fallbackReason` 标记路径和回退原因；`decodeOmittedFrames` 与绘制后省略分开计数。流读取等待不等于纯网络耗时，跨线程交付包含消息排队，Canvas 调用耗时不等于屏幕呈现。首次与后续运行分开分析，不假设重复运行一定命中缓存。
