# F01：部分重复最小闭环

基线为 `2b184aca`（已发布代码 `v0.54.10` 加发布记录），在独立 worktree 的 `codex/dedup-partial-overlap` 分支实施。用户批准本批完成检查、图片对照、确认与删除，定向验证、独立审查和浏览器验收后提交暂停；不实施 F02 缓存重构、F03 规模扩展或新视觉调参。

## 判定与完整性

默认检查增加 `PARTIAL`，不依赖“检查疑似版本”。每个 `(文件大小, SHA-256)` 的配对数为两边出现次数的最小值；总配对数为交集大小 `I`。仅当 `5 × I >= 4 × min(A, B)` 且 `I < A`、`I < B` 时发布部分重复。阈值固定为较短作品的 80%；短作品同样按整数阈值计算，不另加调参门槛。完全相同和完整包含继续使用原结果，不重复展示为部分重复。

例如双方各 100 个原件、80 个完全一致，结果显示 80 个相同、双方各 20 个未配对。按全部登记物理原件比较，支持图片、动画、视频及四来源；未配对仅表示没有字节相同的对应原件，不等于画面独有。缺失、读取失败、变化或不完整快照不能形成该作品的证据。

复用既有有效 SHA 与冻结媒体清单，部分匹配阶段不读原媒体、不生成视觉特征。标题和顺序不影响判定；重复页次数不可丢失。旧缓存失效和完整检查绕过缓存的行为不变。

## 候选、分页与断点

沿用精确代表作品和 `(runId, size, sha256, artworkId)` 倒排索引。每个较短作品取按 posting 稀有度排序的多键前缀，使其累计原件次数大于 `floor(N / 5)`；合格作品最多缺少这么多页，故必共享至少一个前缀键。禁止仅取最稀有一页，那一页可能恰是未配对页。

候选限定同艺术家本次冻结的完整作品，文件数不少于本方；等长仅比较稳定 ID 的一个方向。倒排查询按候选 ID 分页（每页至多 100），逐对聚合完整多重集合交集；不构建全部图片两两矩阵，不把高频桶静默丢弃。数据库中间排序允许落盘，应用不一次加载整艺术家原图或所有页证据。

新增 `partialAfterArtworkId / partialAfterCandidateId` 检查点，接在 `MATCH` 阶段原包含关系后。每批持久化结果与游标，沿用租约、取消及让行；不套用视觉 1 万文件限制，也不据此承诺 50 万性能已达标。页证据按 tuple 与稳定页顺序一对一生成，包括所有未配对页，接口继续分页读取。

## 跨包与持久契约

- 新扫描任务定义版本 4 执行部分重复；旧 1/2/3 扫描保留原行为，不把旧结果当作已排除此类关系。新开始入口要求对应 READY 能力。RunDto 的 `includesPartial` 由任务定义版本是否至少为 4 派生；旧记录简短提示未检查部分重复，沿用重新检查入口。
- `relationKind` 增加 `PARTIAL`。复用 `ArtworkDedupVisualPair/Page`，作品对增加关系判别列，旧行默认 `VISUAL`；正式增量 migration 保留现有数据与历史确认。
- 继续沿用 DTO 的 `visual` 字段名和摘要形状，内部历史名不出现在产品文案。PARTIAL 的 `evidenceVersion='sha256-multiset-overlap-v1'`，`pairedCount=exactCount`、`similarCount=0`、双侧 unchecked 为 0、双侧 unmatched 均大于 0，数量满足上面的整数条件。单独严格校验，不能放宽 VISUAL 的既有约束。
- `listComparisons` 复用现有接口、分页和媒体权限；PARTIAL 只产生 `EXACT / UNMATCHED` 页证据。双方 ID、原件数量、页数及摘要必须一致。
- 视觉清理、失败和重算仅处理 `VISUAL`，不能删除 PARTIAL。开启视觉检查时，相同作品对已有 PARTIAL 则不重复发布 VISUAL。
- 维护任务定义版本 5、PARTIAL 确认协议 4。旧协议 1/2/3 和旧任务语义保持；旧 Worker 不能领取新任务。协议和关系、配对摘要纳入服务端范围摘要，不复用旧授权。

## 页面与人工删除

沿用当前紧凑布局和字体色系：检查结果单独标“部分重复”，摘要说明相同/未配对数量；对照页优先展示未配对内容，桌面并排、手机左右切换。图片/视频按现有媒体入口核对，不用动画封面暗示动画原件完全对应。触控目标至少 44px，底部操作避开安全区。

PARTIAL 无默认保留、无批量选择框，始终排除 `ALL_RECOMMENDED`。用户可选择任一方保留；保存显式选择后才可准备。`EXPLICIT` 只要含 PARTIAL 或 VISUAL 就必须恰好一对，不得与其他结果混批，保存过选择也不能加入推荐全选。

复用一次删除确认面板和 `differentContentLossConfirmed=true`。明确被删作品及其未配对原件、个人整理记录都会删除，不承诺保留者包含全部内容；持续外部停写声明不变，不加第二次弹窗。删除记录保留 PARTIAL 标识、双方数量与人工决定。

执行前完整重读双方各自的冻结原件，验证身份、范围、内容和 PARTIAL 多重集合证据；任何变化使旧确认失效。仅允许已保存并确认的单对人工取舍，不绕过共同认领、路径/硬链接/附属文件检查、租约、逐文件回执和来源墓碑。文件系统与数据库间不假设原子提交，无隔离、恢复或自动合并。

## 验收与交接

- 定向匹配：100/100 共享 80、最稀有页位于未配对区、80/100 完整包含、相等、重复次数、改名重排、低于 80%、短作品、动画/视频原件、无关作品、分页/重启无漏对。
- 服务/数据库：正式空库和非空升级、历史视觉行/协议保留、无默认选择、批量和混批拒绝、缺失内容损失声明与旧协议拒绝、切账户/归属校验、改内容后旧预览零删除。
- 真实隔离闭环：新库、新媒体根、独立 App/Worker/端口，默认检查生成 A100/B100 的 PARTIAL，C 不出现；桌面/手机对照、显式保留 A、确认删除 B、记录刷新。删除后 A/C 文件 SHA 不变、B 文件及业务记录清除；恢复依据为可重建合成样本与初始 SHA 清单，真实图库不参与。
- 有效热缓存重查核对原件读取字节为 0；不以该样本证明 F02 的关系缓存或 F03 的 50 万性能。

复杂实现 Astra/high，App 与独立审查 Sol6.1/xhigh，浏览器 Sol6.1/medium。只跑受影响测试、类型检查和必要 Worker 产物构建；不重复全量 App lint/test/build。结果与未覆盖项写入 `docs/records/`，提交后暂停，不自动推送发布标签或升级开发/生产库。
