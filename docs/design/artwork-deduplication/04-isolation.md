# 第四阶段：可恢复隔离与恢复

本文是尚未实现的开发规格，依赖[第三阶段](./03-review.md)审核与冻结计划。第三阶段已开放维护任务 PREPARE 与 `getOperation`；本文复用 READY 计划的稳定业务 ID，开放 ISOLATE/RESTORE 模式、`isolate`、`listOperations` 和 `restore`，永久清理仅在[第五阶段](./05-purge.md)验收后开放。公共权限、图示和阶段门槛见[总计划](../artwork-deduplication.md)。

## 持久操作与写入协调

数据 agent 负责操作/文件清单/声明/来源抑制及共享事务守卫；执行器 agent 负责文件预检、移动、恢复和崩溃重放；主 agent 接入所有 App/扫描/归档写入口，界面 agent 接入审核确认、隔离区及恢复反馈。不能循环调用现有先 unlink 后数据库删除的普通删除接口。

| 对象          | 强制语义                                                                                                 |
| ------------- | -------------------------------------------------------------------------------------------------------- |
| 操作与分组项  | 稳定 ID、操作者、版本、计划证据、保留者/副本、执行关联、状态和必要展示快照；不跟随检测历史过期           |
| 文件 manifest | 逐文件保存角色、受信根身份、原相对路径、隔离相对路径、大小/身份/内容证据、阶段与收据；不能只记录作品目录 |
| 全局作品声明  | 按 Artwork ID 唯一协调保留者和所有副本；不能只按艺术家锁定，声明必须绑定操作、角色与执行版本             |
| 来源抑制      | 根身份及稳定来源身份/规范路径绑定本次操作，在扫描最终发布和归档交接处生效；作品隔离期间不得再发布同来源  |

`isolate` 接收 operationId（READY 计划的同一业务 ID）、expectedVersion、expectedUserId、幂等键，以及对应计划版本的外部停写确认和备份检查点确认；备份确认包括 `backupCheckpointRef`（1–200 字符的人工可识别名称/ID）及 `backupCheckpointConfirmed: true`，用于记录管理员声明；服务不读取这个值指向的路径或 URL，也不声称已经自动验证备份。界面提供恢复准备区域，展示/填写引用并明确确认适用本批次；新计划版本必须重新确认。路径、文件清单、作品 ID 集合来自服务端 READY 计划。PREPARE 未取得维护声明，因此此处必须重新核验全部版本并全局认领，过期 READY 拒绝执行。无法提供稳定来源身份或经验证恢复检查点的项目保持待处理。`restore` 接收 operationId/受限 itemIds、版本、账户及幂等键，不接受目标路径。列表与详情分页，不能一次传出全部 manifest。

在统一 Artwork ID 升序短事务中认领整组的保留者和副本，重核活动状态、全部账户整理保护、计划版本、来源声明和在途写入。开始后，副本拒绝评分、书签、喜欢、阅读及结构变更；保留者仍可阅读，但原媒体、归属和审核所依赖的结构不能变。声明不能仅靠数据库过期时间释放。

上传、替换、单图/整作删除、扫描/审计发布、本地导入、来源同步、归档下载/封存/发布和普通回收恢复都检查同一守卫。来源声明还需拦截“新建同来源但尚无 Artwork ID”的迟到发布，不能仅检查现有 Artwork 行。`ARCHIVE_DOWNLOAD` 在独立 lane：先阻止关联任务领取/交接，再取消并确认已登记 generation 的执行者 drain，最后才能处理有关目录。lease 过期不是 drain 证明。

隔离完全成功后释放保留者的短期保护；副本隔离状态、来源抑制及 URL hold 持续到恢复或永久清理完成。不冻结保留者整个隔离期限。部分文件移动失败时保留必要声明和现场，先恢复或完成该组，不能自动解除仍在使用的锁。

## 精确隔离协议

1. 取得声明后，仅对所选组保留者与副本绕过缓存完整计算内容；同组保留者在该受控窗口读取一次。重新核对精确成员和批准的附属范围，任一变化使计划过期。
2. 用户已确认目标目录的外部同步和编辑停写；应用守卫不能阻止系统外写入。保留者与副本证据都通过后才允许移动。预检不得改变原媒体。
3. 每个文件检查普通文件、无符号链接、根范围、独占路径、无其他数据库引用、link count 为 1、隔离路径同文件系统。共享路径、硬链接、未知所有权、跨设备或未审核附件均拒绝自动执行，不隐式复制后删除。
4. 冻结 manifest 到数据库并写入同版本、同摘要的持久磁盘恢复副本；确认文件及所在目录持久化能力后，先将副本标为不可正常浏览，再开始首个 rename。清单无法落盘、DB 不可写或空间不足时不动原件。
5. 非 URL 隔离使用原受信媒体根内专用 `.trash/artwork-dedup/<operation>/<item>` 树，路径由服务端生成；扫描、来源发现和媒体枚举均明确排除此树。不移动整个艺术家目录。
6. 独立目录与 Pixiv 平铺目录均逐条执行清单：登记媒体、关联章节文件、已确认归属的 metadata 以及审核通过的附属文件。平铺目录相邻作品和未知文件绝不由 glob 或递归目录删除纳入。
7. 每次移动前核对当前位置/身份，执行同文件系统 rename，按验证过的文件系统持久化策略同步必要目录，再提交文件收据。FS 与 DB 之间无原子事务；重启以实际文件位置和冻结证据重放。
8. 全部文件确认已隔离后标记项目 `ISOLATED`，批次由项目汇总。非 URL 保留 Artwork/Image/来源/个人数据，用 `deletedAt` 隐藏，`archiveLifecycleState` 保持 ACTIVE；使用独立去重状态表示处理中和隔离。

逐文件恢复判定必须覆盖：原位置匹配且隔离目标不存在可继续移动；原位置不存在且目标匹配可补记已移动；两处同条目冲突、身份不符或两处都缺失进入 `RECOVERY_REQUIRED`。不能因两个目录同时存在就判断冲突，部分移动时这是正常现场。重放必须绑定当前操作版本，旧进程不得向后续版本写收据。

`retryOperation` 接收 operationId、受限 itemIds、expectedVersion、expectedUserId 和幂等键，原动作由持久记录决定，客户端不能切换模式。`RECOVERY_REQUIRED` 按原动作提供入口：ISOLATE 可继续原隔离，或通过 restore 安全归位；RESTORE 只继续恢复；PURGE 只能在原授权仍有效且重新校验通过后继续原清理，不能恢复已经删除的文件或创建新 purge。所有重试先确认旧执行退出，再复核原范围和现场。

首个文件移动前可安全取消并解除声明；移动开始后“取消”只停止推进并转恢复处理，不能假装批次从未执行。界面提供继续恢复或完成操作，不能用重试重新生成更大的文件范围。

## URL 作品与恢复

URL 作品使用现有归档回收/恢复文件协议，但仅在当前及历史 revision、章节/来源/附属范围都审核完成后参与。当前展示原媒体相同不证明历史归档全部相同，未经审核的额外内容使项目保留待处理。

去重 hold 由未终结的操作项判定，不能改全局回收期限、把 `purgeAfter` 写到无限未来或先删除 hold 再复用普通清理。到期候选查询、任务物化、已有队列任务和执行器实际文件删除前均检查 hold。普通回收站列表、恢复资格和服务入口识别 hold，使隔离的 URL 作品超过普通 7 天期限仍可恢复。

若复用现有归档任务，去重业务项与归档任务使用持久唯一关联及授权版本；交接后释放 writer 槽，不能让父任务占槽等待同 lane 子任务。归档子任务终态回写业务操作，任务重试不更换业务操作 ID。普通回收站发起的恢复也进入同一去重恢复状态机。

恢复先认领隔离项并核对当前 manifest、根身份和原路径。原路径被新文件占用时停止，不覆盖、重命名或删除新文件。逐文件恢复完成、数据库指针核对通过后，才清除 `deletedAt`、释放来源抑制与 hold；保持原阅读、评分和媒体标记。恢复不要求保留者仍存在，因为隔离副本自身就是恢复目标。

## 验收案例与开放门槛

| ID     | 场景与必须证明的结果                                                                | 证据                     |
| ------ | ----------------------------------------------------------------------------------- | ------------------------ |
| D4-01  | 同作品属于两艺术家，两计划分别保留/移除对方；只有一个成功认领，不能互删             | PostgreSQL 并发测试      |
| D4-02  | 同时新增标记、替换、普通删除及扫描发布与操作串行；来源级迟到新建被拒绝              | 全写入口集成矩阵         |
| D4-03  | Pixiv 平铺目录只移动清单文件，相邻作品/未知文件不动；独立目录同样逐项操作           | 文件 fixture             |
| D4-04  | 共享路径、硬链接、符号链接、跨设备、未知附件和根变化拒绝自动隔离                    | 边界 fixture             |
| D4-05  | 每个 rename 前后、目录同步前后、收据/业务提交前后强制退出，重启不丢件不覆盖         | 故障注入矩阵             |
| D4-06  | reader/下载执行未 drain、旧 generation 迟到交接不进入文件移动和重新发布             | 跨 lane 并发测试         |
| D4-07  | URL hold 拦住自动/已排队 purge，超过 7 天仍可恢复；多 revision 未审范围不得自动回收 | URL 生命周期集成         |
| D4-08  | 恢复路径冲突保留两侧证据；完整恢复才重新可见、解除来源声明并保留个人数据            | 文件 + DB 集成           |
| D4-09  | 清单无法持久化、低空间、DB 断线与部分批次失败均不扩大范围、不自动解锁现场           | 故障注入                 |
| D4-B01 | 桌面/手机从审核确认到隔离，刷新可追踪；正常列表隐藏，隔离区可恢复，冲突反馈可操作   | 按总计划指定的浏览器记录 |

临时 fixture 和隔离数据库完成上述门槛后进行独立代码审查、修复复审，再执行 D4-B01。阶段记录必须包含目标文件系统目录同步与断电边界的验证范围；未验证的平台不得写成已保证。永久删除按钮仍保持未开放，直到第五阶段验收。
