# 去重识别：版本收口与后续计划

用户决定先发布已验收版本观察实际效果，未完成项留待后续逐批推进。本页替代原扩展草案的执行清单；原方案和实验过程保留在 Git 历史及下方验收记录中。登记待办不代表授权立即开始下一批。

当前行为唯一依据为[功能规格](../../features/artwork-deduplication.md)，最小疑似版本接口见[闭环契约](./suspected-versions-contract.md)。前一版发布收口见 `v0.54.10` 的发布记录。F01 已验收并合回主目录，开发升级见[F01 本地升级记录](../../records/operations/artwork-deduplication-f01-local-upgrade-2026-10-26.md)；镜像发布与线上部署须分别登记，不以本地验收代替上线成功。

## 本版交付与明确缺口

| 能力               | 当前交付                                                                                    | 仍未完成                                                |
| ------------------ | ------------------------------------------------------------------------------------------- | ------------------------------------------------------- |
| 精确重复、完整包含 | 同艺术家、四来源；SHA 多重集合保留重复次数，80/100 完整包含只允许保留完整者                 | 新版包含算法的 50 万规模完整吞吐证明                    |
| 疑似版本           | 可选开启；静态图整图＋局部、有界白边/裁剪视图、一对一配对；图片对照、手选版本、单对确认删除 | 真实有码/无码版本的识别效果验证，不自动判断哪部无码     |
| 纯字节部分重叠     | F01 默认检查：较短作品至少 80% 相同、双方均有未配对；图片对照、人工单对删除                 | 50 万规模性能                                           |
| 内容缓存           | SHA、视觉特征及有效作品关系可复用；同内容共享视觉计算；完整检查绕过全部缓存                 | 大图库规模验收                                          |
| 视觉规模           | 每次最多 10,000 个登记原件，单作品/配对另有限额；超预算明确未完成                           | 可续行的大规模检索，不能只调高上限；50 万图片端到端验收 |
| 删除保护           | 原文件快照复核、人工内容损失确认、逐文件回执和来源抑制继续有效                              | 不新增隔离、恢复、自动合并或视觉批量删除                |

此前 50 万登记媒体的精确检测、50 万合成特征索引探针，均不等于当前包含／视觉算法完成了 50 万真实图片检测。当前视觉缓存按媒体身份保存，可通过相同内容键共享计算结果；每次检查仍重建任务索引与候选。F02 各批交付及部署边界见对应验收记录。

## 发布观察：先记录实际问题

线上先选原件数量在当前上限内的少量艺术家，人工核对结果；没有建议不等于没有重复。记录三类问题：目标作品未出现、不同作品被配在一起、作品关系正确但页配对错误。记录双方页数、相同/相近/未配对数量及变换类别即可；原图、实际路径、账户信息留在用户控制的私有位置。

只有用户明确确认同作品版本关系的样本才作为真值，不用 Pixiv/E-Hentai 来源替代标注。已批准可销毁样本可验证删除；真实图只读观察，额外删除由用户逐次选择。当前安全或数据完整性缺陷优先修复，功能扩展按下列顺序单独授权。

## 后续批次与完成条件

### DEDUP-F01：已完成部分重复闭环

默认 SHA 检查已增加部分重复，复用图片对照、手选保留、单对确认和删除记录；无默认选择，不加入推荐全选。候选前缀、短作品边界、任务版本和删除证据详见 [F01 契约](./partial-overlap-contract.md)，定向测试、审查、浏览器和文件审计见 [F01 验收记录](../../records/artwork-deduplication-partial-overlap-f01-2026-10-26.md)。交付后暂停，未附带 F02 缓存重构。

### DEDUP-F02：减少热缓存成本，复用有效关系（已实现）

**目标：** 重查不重新解码有效图片；新增/修改只补算失效特征、更新受影响关系，减少逐图数据库往返。

1. 批量化已在 F02 第一批实现：批量取媒体身份与视觉缓存，命中不重复写回相同缓存，有界提交失效项和任务进度，保留租约、源版本与取消检查。见[本批证据](../../records/artwork-deduplication-cache-batch-f02-2026-10-26.md)。
2. 第二批实现关系增量：保存可核验的作品成员/内容/算法摘要，复用有效关系；新增、修改、删除、艺术家归属变化时使受影响证据失效。只有能够证明范围未变才复用，不能让旧“无匹配”阻止新作品进入候选。
3. 第三批实现相同 SHA 媒体共享兼容的视觉计算结果；每条路径的身份与有效性仍独立核对，规范化或特征算法变更会失效。参数调整可用已有特征重新匹配，不沿用旧关系。见[第三批验收记录](../../records/artwork-deduplication-shared-visual-cache-f02-2026-10-27.md)。

**验收：** 冷轮、未变热轮、改一张、新增一部、删除/改归属、标题/排序、算法版本变化、并发替换及失租约。记录原图读取字节、解码数、缓存命中、查询/写入数量和候选重算范围；不以“没有重读图片”代替数据库性能证据。批量化与关系增量各自定向验证，不要求一起大改。

#### F02 第一批：视觉缓存批量读写（已完成）

本批只改变视觉特征准备阶段的数据库访问方式，不改页面、匹配算法、关系种类、检测上限或删除证据。跨次关系复用及同 SHA 特征复用分别由下方第二、三批实施。

- 每次沿既有游标取得最多 50 条登记媒体，批量读取这些媒体的身份与视觉缓存；完整检查继续绕过缓存。缓存必须同时满足文件身份、算法版本、归一化版本及完整特征校验。
- 有效命中不重读、不解码、不更新持久视觉缓存；任务自己的媒体结果与游标仍须持久化。仅把失效或缺失项的完整解码结果写回，限制在当前批次内，不积累整个艺术家的图像或待写结果。
- 写入按目录／根守卫、作品快照及执行租约重新核验；批量预取不能成为发布许可。游标只能与已提交结果一同前进。取消、失租约、根变化、并发替换或事务失败不得发布过期缓存／结果。
- 到让行边界时提交已完成的前缀后退出；支持不满批次、混合缓存命中、不可解码媒体、重启续行及完整检查。沿用读取子进程和现有三条执行 lane。
- 用隔离样本分别报告冷轮、未变热轮、改一张的实际内容读取／解码次数、缓存读写和数据库访问；增加取消／失租约／源变化的定向测试。桌面浏览器验证检查及结果查看；不重复全量验证，不宣称完成 50 万性能验收。

实施：Astra / high；独立审查：Sol 6.1 / xhigh；浏览器：Sol 6.1 / medium。完成定向验证、审查和桌面验证后记录证据、提交并暂停。

#### F02 第二批：跨次比对结果复用（实施契约）

本批以已完成检测作为关系缓存，不新增缓存服务或通用关系表。仅调整原字节包含／部分重复及可选视觉阶段的重复计算；精确组仍由本次 SHA 多重集合重建，检测上限、人工选择和删除保护不变。本批当前行为见[功能规格](../../features/artwork-deduplication.md)，验证与交付状态见[第二批记录](../../records/artwork-deduplication-relations-f02-2026-10-26.md)。

- **缓存来源：** 同艺术家最新的兼容已完成 run，必须有本批完成时写入的版本标记、全部原字节 item 完整。原字节阶段可独立复用；视觉阶段另须完整成功。失败、取消、旧版本和未完成阶段不得作为该阶段的负证据。完整检查不读取旧关系。
- **原字节关系：** 两端作品 ID、成员数及完整内容 SHA 与旧 run 一致，且均为新旧精确组的代表，才复用既有包含／部分重复和经完整检查得出的无关系结论。新增或替换作品、代表变化、删除／改艺术家归属仅影响相关端点；不能把旧代表的关系转移给新 ID。图片对照依据当前媒体及排序重新投影。
- **视觉关系：** 两端完整视觉输入摘要一致，且新旧精确组代表资格一致，才可跳过视觉距离比较及配对。摘要包含按媒体 ID 排序的 ID、大小、SHA、完整视图特征和特征／规范化／匹配参数版本，排除标题及排序。特别覆盖旧视觉结果曾被原字节关系抑制、代表变化后应重新出现的场景。 同一 SHA 重复出现的等价页允许保留旧的有效一对一媒体 ID 配对，但必须刷新当前页码；不要求与完整重算选择完全相同的重复页 occurrence。
- **候选与预算：** 每次仍重建当前有界索引、查询全部参与图片，重新判断文件、作品、posting、查询候选、比较与作品对预算；潜在比较包含复用项。持久保存旧视觉候选作品对（含未达到发布阈值者，受现有 1,000 对上限约束），与本次新候选合并后重新核对预算。新作品使候选变密时仍须明确未完成，不能用旧负结果绕过。
- **持久数据：** 正式新增可空 run 关系版本、视觉候选对及 item 视觉输入摘要；增加有界原字节关系复用／重算和视觉比较跳过／执行计数。默认值兼容旧数据，不回填、不扫描媒体。每次重试清空本次证据与计数，旧输入或参数不兼容即 miss。
- **提交与生命周期：** 复用不能代替本次文件属性／SHA／特征准备和源校验。最终缓存版本发布须核对所有参与原件（包括无匹配项）、当前艺术家范围、根身份、源代次和执行租约。旧结果中的审核选择、保留建议和清理授权不复用。
- **历史清理：** 不建立跨 run 长期依赖。读取旧证据的事务对旧 run 加共享行锁，检查点或有界视觉快照读完后释放；历史缺失按 miss 完整计算当前候选，游标不得跳漏。新结果保留自身完整证据，删除旧历史不影响新结果。
- **验收：** 冷／热结果等价、改一张、新增作品命中旧负例、删作品／改归属／精确组代表变化、改标题／排序、算法版本和完整检查；当前密集候选超限、取消／失租约／源变更、旧历史并发清理。测试证明实际跳过的比较量，不能把缓存命中写成零数据库访问或零索引开销。新增迁移只在独立空库及非空测试库验证，暂不升级正在使用的开发库。

实施 Astra / high，独立审查 Sol 6.1 / xhigh，桌面浏览器 Sol 6.1 / medium。只运行定向测试、必要 Worker 构建和文档检查，完成后提交并暂停；不包含同 SHA 跨媒体特征复用、50 万规模验收或放大视觉上限。

#### F02 第三批：相同内容共享视觉特征（实施契约）

本批只减少重复内容的视觉处理，沿用按媒体保存的缓存及现有检查／对照／确认页面，不新增缓存服务或共享文件存储。相同内容可以跨作品复用计算结果，但不能借用其他媒体的文件身份、路径、源状态或删除授权。

- **复用键：** 已核验的原件 SHA-256、文件大小、视觉算法版本及规范化版本。为现有 `MediaVisualFingerprint` 增加可空内容键及索引；旧行保持可用的单媒体缓存，不推断或批量回填内容键。只从完整且格式有效的成功特征复用，不缓存失败／不支持结果。
- **有界读取：** 每页最多 50 个媒体，先读取自身有效缓存，再按缺失的唯一内容键有界查询已有特征；同页相同内容只计算一次。查询不能将某个热门 SHA 对应的所有缓存载入内存。提交后下页、续跑及后续任务都能复用；内存只保留当前批次，不新增无界全局缓存。
- **独立核验：** 每个目标仍经过自身原字节／属性检查，提交核对执行租约、根／目录／作品快照、媒体路径和源版本，最终发布复核原件。共享结果写成目标媒体自己的缓存记录，与任务结果和游标一同提交；供体删除或历史清理最多造成缓存 miss，不破坏已完成目标证据。
- **完整检查：** `FULL` 同时绕过自身缓存、跨媒体缓存和同批内容复用，逐文件执行受控视觉处理。不修改匹配参数、关系兼容版本、候选预算或媒体支持范围。
- **迁移与交付：** 正式加法迁移，不读取媒体、不回填旧行；在独立空库及非空旧 schema 库验证升级与旧数据保留。本批不迁移当前开发库，不触碰真实图库或运行中的用户服务。
- **验收：** 两部各 100 张、共享 80 个相同文件时，冷轮视觉处理为 120 次（原字节读取仍独立）；热轮为 0。另测同页与跨页、跨次新增副本、修改一个文件、版本／大小不兼容、无效缓存、供体删除、让行续跑、并发替换／取消／失租约及 FULL。报告处理调用数、字节和数据库读写；处理调用数不冒充解码库内部次数。复用前后关系结果保持等价。

实施 Astra / high；独立审查 Sol 6.1 / xhigh；桌面浏览器 Sol 6.1 / medium。只做本批定向验证和一次必要 Worker 构建，验收后提交并暂停；F03 规模与上限调整另行授权。

### DEDUP-F03：解除小范围限制并完成规模验收

**依赖：** 先完成 F02，保持既有资源上限直到新的实现验证通过。

当前视觉检索已使用持久检查点及有界 QUERY 批次：最多 8 个查询／50 个候选槽共用读取与完整提交校验，保留源身份、目录代次和执行租约保护。公开 10,000 上限不变，具体协议见[F03 契约](./visual-batches-f03-contract.md)；前期同样本优化与真实暂停／Worker 重启证据见[第三批记录](../../records/artwork-deduplication-query-batching-f03-2026-10-27.md)。

第四批以独立测试预算和专属数据库约束验证 100,000 条预制特征，详细冷热结果及限制见[规模验证记录](../../records/artwork-deduplication-scale-f03-2026-10-27.md)。第五批在单次扫描调用内有界复用冻结目录描述，减少反复从媒体推导根身份／目录清单的查询，每次提交仍校验当前身份、代次、写入声明及执行权；同一保留 fixture 的完整冷热结果、重启续跑及历史基线比较见[目录查询优化记录](../../records/artwork-deduplication-root-scope-f03-2026-10-28.md)。这些测量不覆盖 10 万原图读取／解码、实际 Worker 十秒时间片吞吐或 NAS，不能据此放开生产上限。

下一项先处理新 run 的候选查询计划稳定性：历史 posting 积累较多、小型新 run 未触发自动统计时，查询可能只按 runId 扫描，再过滤 key。一次隔离库 ANALYZE 已证明统计会影响计划，但尚未修复生产路径。应选择最小稳定方案，用未被人工分析的新 run 验证，不能把大 run 自然触发自动统计的成功泛化为小 run 已解决。

以下仍是待完成目标。当前硬预算耗尽会明确收口为 `INCOMPLETE`，原样重入不会绕过预算；“原范围暂停／重启续跑”已验证，不等于“耗尽硬预算后继续完成”。

- 使用有界特征批次、紧凑索引和持久检查点；分批仍须能发现跨批作品对，不能把艺术家切成互不比较的孤岛。
- 高频桶、候选、配对计算均受预算控制；超预算保留未完成范围并允许领域入口续行，不静默丢结果。暂停、取消、重启和失租约仍可收口。
- 依次测 1 万、10 万、50 万登记媒体/特征，包含普通分布和公共封面/模板密集分布；每档仅在前一档通过后执行。
- 分开报告合成特征吞吐与独立真实图片的读取/解码成本，再完成数据库、Worker 和同时浏览/下载的组合测量。真实图库仅作有界只读测量，不用实际删除压测。
- 必须记录总耗时、实际读取字节、解码数、冷热命中、峰值内存、数据库读写、事件量、候选数、未完成范围及并发业务延迟。不能沿用旧精确检测或 100 次查询探针宣称 50 万全流程通过。

**完成条件：** 50 万规模检查正确收口、跨批关系不遗漏、预算/重启可续行，有可复核资源报告；才调整当前 1 万上限和产品说明。性能不达标时先记录瓶颈，不提前承诺 NAS 耗时。

### DEDUP-F04：真实版本效果与有针对性的修正

可与线上观察并行收集，不阻塞本版试用，不要求立即新增实现。

- 收集经人工确认的真实版本对及不同作品负例，覆盖局部遮挡、压缩、白边、轻裁剪、同模板和多页差分。
- 按作品图族区分调整集和留出集，分别统计作品漏检、作品误配和页配对错误；没有真值时保留“未知”。
- 只针对真实高频问题安排一轮小改进。参数/算法更新先核对缓存兼容与旧确认失效，再做留出集验证；不为了当前样本命中反复调参。

**完成条件：** 样本来源、标注、误配/漏检及边界有据可查。仍不把视觉建议变成自动无码判断、自动保留或批量删除。
