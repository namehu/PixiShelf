# F03：视觉检索分批与续跑

本批将特征准备之后的一次性内存匹配改成持久分段处理。沿用原算法、F02 缓存、现有检查页面和人工删除流程；不增加新服务、管理向导或移动适配。基线为 `261993af`，仅在独立 worktree 开发，真实开发库和用户 Worker 不在本批变更范围。

## 第六批：新任务候选查询计划稳定性

基线为 `7ccd4948`。本批只处理历史 posting 很多、新 run 尚未进入数据库统计时的候选读取退化。改进查询形状以利用已有 `(runId, key, imageId)` 主键；不把人工 `ANALYZE`、关闭自动维护或全局 planner 设置作为产品修复，不新增搜索服务。

- 同一查询必须保留完整候选、posting 的重复次数及原预算加一哨兵；超预算仍为 `INCOMPLETE`，不能通过提前截断来获得更快的“完成”。查询顺序变化不得影响最终排序后的图片 ID、候选计数、配对证据或续跑游标。
- 最小方案为去重 key 输入与 `LATERAL` 标量等值查询，使用已有主键同时定位 run 与 key。每个子查询及最外层均保留原行数上限加一；外层不加排序，避免为排序先物化所有 key 的结果。未超限时必须返回完整集合；超额集合只用于报预算耗尽，不要求维持旧 ORM 隐含的 posting 顺序。业务使用的候选图片 ID 数值排序保留。须用执行计划证明数据库实际按需读取、没有扩大为 key 数乘以预算的完整物化。
- 查询仍在原读取围栏事务内；比较与提交边界、取消／租约、根／目录／作品源／成员及写入声明校验均不动。生产 10,000 原件及全部现有预算不变。
- 复用第五批保留的历史库及小型预制特征，先记录新 run 的统计与旧查询计划，再在相同输入上比较旧／新查询的完整返回及资源成本。完整小任务按独立 oracle 核对结果，保留冷／热缓存和续跑证据；本批不重跑 100,000 长测，更不以特征测量宣称真实图片或 NAS 吞吐。
- 实施为 Astra / high，测量和独立审查为 Sol 6.1 / xhigh。只运行相关 PostgreSQL 用例、受影响包检查及必要构建；桌面冒烟如有需要由 Sol 6.1 / medium 执行。不重复全量应用验证，验收、提交后暂停，不自动合入主目录。

## 第五批：根身份与目录清单查询优化

第四批基线为 `682fe3fd`，第五批实施前先经独立审查合入 main 的 `73ebb3b7`／`46eacb5b`（合并提交 `2af6ff4a`）。保留第四批固定 100,000 条特征、媒体 ID、输入摘要和独立 oracle。只优化视觉检索中反复从媒体推导根身份／目录清单的数据库成本，不修改匹配规则、公开预算、删除确认、缓存含义或任务版本。主目录、开发库及用户服务不参与。main 修复只对齐历史零版本证据，不改变视觉内核路径；合并后另做历史数据定向验证。

- 可以复用有界的范围描述或改进查询方式；**不能复用“上一次已经校验成功”的结论**。提交仍核对当前执行权／租约、根身份、目录代次、作品源及完整成员快照、写入声明，沿用 catalog → roots → directories → Artwork 锁序。
- 范围描述必须绑定当前 run 的冻结成员及执行上下文；中断／重启能从持久数据重建，旧任务或不同 run 不得错用。根变更、目录变化、成员／来源变化、取消／失租约和事务回滚不能推进过期结果。
- 内存和查询保持有界，不将全部媒体读入内存、不加无界全局缓存；生产每次 10,000 原件及 8 查询／50 候选槽等保护不变。若最小方案需要数据库迁移或跨包协议调整，先修订本节，不临时扩散改动。
- **选定实现**：仅 QUERY 使用执行器内的目录范围 helper，在同一次视觉扫描调用中以 LRU 保存“作品 → 冻结目录快照”描述，最多 128 部作品、2,000 条目录快照及 1 MiB 序列化元数据。键绑定 run、job、executionVersion 和当前 item 的完整冻结身份；零版本是合法值，不能与 null 混淆。miss 有界查询最多 2,001 条目录快照，由同一清单推导根，避免单独根 DISTINCT 与空尾页。任何超限回退原有分页校验，不截断目录。
- 每次提交继续调用现有 `assertArtworkDedupVisualDirectories` 和 `assertArtworkDedupVisualItems`，核对完整当下状态；全体根须先锁，再分段锁目录／祖先，之后锁作品。INDEX／REUSE／PAIR／PUBLISH 保持原路径，最终发布仍完整复核。调用让行或进程重启丢弃内存清单、重新推导，不增加持久缓存或迁移。测量须说明缓存寿命与测试让行方式，不能把一次长调用内的热命中当作真实 Worker 全链吞吐。
- 安全定向用例覆盖正常冷热结果、复用范围后根／目录／源变化、写入声明、取消／失租约、回滚及新执行上下文续跑。只在新的专属测试库操作，正式迁移；保留的规模库由测量负责人独占。
- 性能复用第四批已完成基线，不再重跑旧版长测；优化版在同一输入上各完成一次冷轮和热轮，按原 oracle 核对所有候选／负证据及发布结果。先做有界探针，生产源码冻结且独立审查后再启动长测；不与其他压测争用数据库。
- 记录 SQL 总量、根／目录查询成本、事务、写语句、内核耗时、驻留内存、比较／复用和结果摘要。旧基线的单条 COMMIT 归因缺口继续明确；预制特征测量不冒充原图解码、NAS 或严格受控多轮性能实验。
- Astra / high 负责复杂实现，Sol 6.1 / xhigh 负责测量与独立审查，Sol 6.1 / medium 仅做必要桌面冒烟；只跑相关测试、受影响包 typecheck 和一次必要 Worker 构建，不重复全量应用验证。通过后提交并暂停，不自动合并或发布。用户已取消额度监控。

## 第四批验证范围

第四批从主线 `912f7e73` 在独立分支验证现有内核，包含用户最新预览器改动。生产每次 10,000 原件等全部默认预算保持不变，不新增迁移、公开参数或删除行为。结果与覆盖边界记录在[第四批验收](../../records/artwork-deduplication-scale-f03-2026-10-27.md)。

- **100,000 条预制特征**：隔离 PostgreSQL 中有界生成，包含相距较远批次的已知匹配作品及不匹配对照；不读取用户原件，不把特征记录数当成已解码图片数。仅独占测试文件覆盖内核预算；正式迁移后，只在已核验的专属规模库同步提高比较计数 CHECK 的两项额度，保留其他约束并记录原定义及恢复条件。报告与生产默认值的差异，禁止将测试配置或该库用作生产入口。
- **冷／热与完整核对**：小规模探针之后只跑一轮完整冷检索与一轮热复用；冷轮在明确检查点重建上下文并继续。按独立候选索引核对完整匹配边、配对证据及计数，避免为了比较中断再重复一轮 10 万冷检查。连续／中断逐项等价用单独的小型密集 fixture 证明。
- **密集候选**：跨 50 个候选槽及 8 个查询边界，检查合法前缀、查询内游标、恢复后的边与计数；触及 posting、候选、比较或作品对硬预算时必须为 `INCOMPLETE`，不暴露未完成视觉结果。内部阶段 `DONE` 可表示本轮已收口，不等于视觉检查完整成功。
- **续跑边界**：时间片、主动暂停、Worker 正常退出后的原范围续跑，与硬预算耗尽是不同语义。硬预算耗尽不承诺原样继续即可完成，不自动升额；本批核验并报告现有边界，不引入新预算续行协议。
- **测量与隔离**：记录 SQL、事务、写语句、候选比较、缓存复用、耗时、采样 heap、进程峰值 RSS、数据库大小、原件读取与解码数。生成与审计成本分开记录；真实媒体、开发库和用户服务不参与。各专属库完成正式迁移，规模长测与其他测试错开。
- **完成顺序**：相关测试与测量 → 独立 Sol 6.1 / xhigh 审查 → 修复必要问题 → Sol 6.1 / medium 桌面验证密集未完成提示与正常控制 → 记录证据、提交、暂停。本轮不重跑全量应用验证或上一批 10,001 条 A/B，不做实际删除。

## 范围及门槛

- 对外仍保留每次 10,000 登记原件上限，单作品 2,000、索引 posting 1,600,000、单查询 posting 20,000／候选 2,000、运行候选比较 200,000 和作品对 1,000 等保护。生产入口不暴露任意预算参数。
- 用隔离测试受控覆盖 10,000 和略超 10,000，证明分批算法能工作，不将合成特征结果冒充真实解码性能。10 万、50 万、多业务争用及公开上限调整另批交付。
- 本批的“续跑”指时间切片让行、用户暂停／继续、Worker 重启后的原范围续跑。固有索引／候选／配对预算超限仍明确 `INCOMPLETE`，不新增提高预算或截断后强行完成的入口。
- 保留单文件受控解码超时、退出确认和读取失败语义；不要把单图超时改成可无限重复的让行。

## 执行和持久边界

1. **准备特征**：继续每页最多 50 条，优先自身缓存，其次同 SHA／大小／版本的完整特征，最后受控解码。目标媒体身份核验、特征与游标在同一围栏事务提交。
2. **构建索引**：按完整作品加载不超过 2,000 条特征，保存作品签名及当前 run 的 posting。posting 含原索引的重复计数，不能因为数据库去重使预算语义改变。所有批次完成索引后才进入检索。
3. **检索候选**：按下文第三批边界，最多 8 个查询媒体共享一组读取／提交事务，合计处理最多 50 个候选槽；posting 仍逐查询有界读取。分别持久化查询媒体游标及查询内候选游标；本次查询的 posting／候选预算只核算一次，已提交块的比较计数和匹配边不重复累计。批内合法前缀的计数、边及末尾游标原子提交；失败只重做未提交批，尾块与查询完成游标共同提交。暂停后不能重新算已提交前缀或漏掉后缀。
4. **作品配对**：一次最多加载两个作品的完整特征和本对匹配边。沿用原文件相同优先、视觉唯一边、一对一配对及 80% 阈值，输出与一次性匹配器等价。已完成配对与配对游标共同提交。
5. **完成与发布**：分页读取核验数据，避免载入全图库特征；最终仍在同一发布事务内按既有锁序核对目录、源、完整成员与执行租约。未完整结束的中间视觉对不得作为已完成检测结果暴露；原精确、包含、部分重复优先级不变。

使用现有数据库保存本 run 工作索引、边及检查点，配套加法 migration；迁移不扫描媒体、不推断旧运行已完成的新阶段。索引生命周期跟随 run，重试清除本 run 工作状态，不能清除持久文件／视觉缓存。跨批次、进程重启均从数据库接续，不依赖留在内存里的全局数组。

F02 的关系复用保留：固定兼容历史 run，按有界候选块取得其共享锁，验证签名、代表资格和完成状态，将必要旧候选及配对证据物化成本 run 的独立工作数据；每块与复用游标一起提交，可在 REUSE 阶段让行、暂停和重启。全部物化完成后才能启用完整负证据并进入 QUERY，不能在一个事务里加载全部历史候选。中途历史清理使固定来源消失时，撤销本次不完整复用资格及复用候选，用已完成的当前索引正常计算，不依赖旧行继续存在。新增作品仍查当前全局索引，复用项继续参与当前预算计数。`FULL` 绕过自身、共享和关系缓存。

新增检查点协议须与扫描任务版本和 Worker 能力一致；旧任务按明确兼容路径处理，旧 Worker 不得领取依赖新协议的任务。任务版本变化不改变视觉特征算法版本或原删除确认协议。重试、取消、原范围恢复及历史清理都要覆盖新工作状态。

## 异常和不变量

- 当前目标的源／目录／根／成员或写入声明变化，取消、失租约、事务回滚都不得推进检查点或发布过期证据。
- 中间结果不复制用户的保留选择或删除授权；视觉建议继续要求人工单对核对、确认，删除前仍完整验证双方原件。
- 单查询／单对计算内部有取消及租约检查，阶段之间按时间片让行；总量增加不放大单次内存装载。最终事务仍可能随作品数增加，本批记录该限制，不宣称全部数据库工作为常数成本。
- 高频公共封面／模板超预算不得静默丢候选；输出未完成原因，保留精确检测结果。

## 第二批：QUERY 数据库往返优化

本批只合并 QUERY 内紧邻的读取事务与重复执行围栏，不修改数据库结构、任务版本、checkpoint version 1、匹配规则或任何公开预算。

- 主循环读取并验证 run、解析检查点，与读取当前查询媒体、posting／恢复候选游标、最多 50 条候选特征共用一个读取事务。验证后的 run 仅在持有同一事务行锁时复用，不作为跨事务授权。
- 视觉比较仍在事务外完成。保留取消检查和事件循环让出，让出后再次检查取消，再进入独立提交事务。
- 提交事务重新验证当前执行状态，并保留完整 catalog → roots → directories → Artwork 锁序和当前源、目录、写入声明校验；边、计数和游标仍原子提交。无需为紧邻的同一提交再开一笔空校验事务。
- 不把多个查询媒体或多个候选块合为一笔长事务；INDEX、REUSE、PAIR、PUBLISH 保持原路径。默认上限、让行和恢复边界不扩大，旧 v5 检查点继续可读。
- 同样本 A/B 先执行 `ea0a140b` 的基线实现，再清理同一个合成 run 的工作结果并重置计数，以相同媒体 ID、SHA、特征、目录和源快照执行优化版。基线源码只作为临时测试输入；不在产品中保留第二套旧引擎。以 10,001 条的同 fixture 比较为本批规模依据，不重复上一批两档长测。

非空 QUERY 块由 5 笔事务减为 2 笔；同 fixture 的 SQL、耗时、结果等价和覆盖限制见[第二批记录](../../records/artwork-deduplication-roundtrips-f03-2026-10-27.md)。该优化不构成大图库性能达标或上限开放依据。

## 第三批：SQL 归因与有界批处理

基线为 `b4943c80`。先按阶段和归一化 SQL 统计次数及数据库报告耗时，识别读取、执行围栏、目录／作品校验、结果及游标写入、事务控制的主要成本，再确定批处理边界。统计不记录参数、私有路径或连接秘密；数据库语句耗时与应用端总耗时分别报告。

- 仅优化当前视觉检索内核；不调整匹配规则、公开预算、删除流程或缓存身份，不增加数据库迁移。本批不运行 10 万／50 万长测。
- 有界批次共用读取与提交校验；比较仍在事务外，提交时重新验证执行权与本批全部涉及的作品／目录／源状态。同一事务已持有的校验可复用，跨事务的旧检查结果不能代替提交时校验。
- 批次受查询数、候选总数、涉及作品数及时间切片约束；不得把全部图片或全部候选一次载入内存。匹配边、计数和检查点原子提交；失败仅重做本批，旧 v5 检查点继续可读。
- 沿用第二批的确定性 10,001 条预制特征，同一 fixture 顺序运行本批基线与优化版，逐项核对结果及输入摘要。只跑一组完整 A/B，定向测试负责取消、失租约、源／目录／写入声明变化和回滚；不将预制特征吞吐当作原图解码或 NAS 性能。
- 桌面在独立数据库、媒体、App 和 Worker 下补验运行中暂停／继续及 Worker 重启续跑，必须记录真实运行与持久检查点。不得用排队态暂停或直接修改任务状态替代。此次不实际删除作品。

120 条、两个作品的前置测量中，QUERY 占 95.4% SQL；其中目录状态读／写占 31.5%、run 锁／读取占 15.8%，事务控制占 10.6%。Prisma 单语句毫秒值大量为零，不能以此认定它们没有成本。优先把多个查询共用一次提交围栏，不修改共享目录 helper。

### 本批固定边界

- 每批最多 **8 个查询媒体、50 个候选槽、51 部不同作品**；同一候选用于不同查询时分别占槽。候选特征按唯一 ID 一次读取，最多 50 条；总驻留查询／候选特征最多 58 条。posting 仍逐查询受原预算约束，不保留八份 posting 集合。
- 组装采用 **100 ms 软时间预算**，在查询之间检查；不承诺中断单次 SQL。每轮至少推进一个合法候选块，超批大小、作品数或时间预算时停止组装前缀，不跳过未处理候选。比较仍在事务外，最多 50 个候选槽，并检查取消。
- 批次末尾若有未完成查询，沿用检查点 version 1 的 `queryImageId/queryCandidates/candidateAfter`；完整查询更新 `queryAfter`。从旧版单查询检查点恢复不重复前缀。读取后续查询发现固有预算问题时，不得丢掉本批此前已合法处理的前缀或把整个任务误报完成。
- 同一批涉及的全部查询与候选作品共用一次原有完整提交校验，锁序不变。边按作品对汇总，批量读取已有候选对、批量插入新对；同一已有对每批至多更新一次。没有新增候选对时不重复统计全 run 对数；新增时仍在 run 锁内核对原作品对预算。
- 暂停／取消／失租约、源代次、目录身份／代次或写入声明变化不能提交过时批次；异常和事务回滚后重做未提交批次。INDEX、REUSE、PAIR、PUBLISH 与共享数据库 helper 不改。

沿用 Astra / high 实施、Sol 6.1 / xhigh 独立审查、Sol 6.1 / medium 浏览器验收；一次必要 Worker 构建，验收及提交后暂停。主目录、开发库及用户运行服务不在本批范围内。具体测量、恢复验收及限制见[第三批记录](../../records/artwork-deduplication-query-batching-f03-2026-10-27.md)。
