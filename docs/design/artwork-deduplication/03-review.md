# 第三阶段：结果审核与清理预览

本文是尚未实现的开发规格，依赖[第二阶段](./02-detection.md)的持久检测结果。交互布局、桌面与手机状态见[页面设计](./ui-design.md)；公共接口与阶段门槛见[总计划](../artwork-deduplication.md)。本阶段开放查看、审核和准备清理计划，实际隔离/恢复/永久清理由后续阶段开放。

## 职责与查询契约

界面 agent 负责艺术家入口、结果/隔离区页面、组详情与确认流程；数据 agent 负责分页结果、跨账户保护聚合、持久审核与计划证据；执行器 agent 实现 PREPARE；主 agent 固定 API/任务注册和账户边界。

`/admin/duplicates?artistId=…` 默认显示该艺术家最近一次有效检查结果，运行中可切回上一份完整结果并显示其检查时间。无 artistId 时先选择艺术家，不隐式发起全库检测。检测结果属于管理事实，审核选择按当前账户保存；更换账户清空前端缓存与未提交选择，迟到响应不能污染新会话。

| 接口             | 契约                                                                                                                                           |
| ---------------- | ---------------------------------------------------------------------------------------------------------------------------------------------- |
| `listGroups`     | runId、expectedUserId、组游标；返回受限组页和每组最多 3 个预览成员。指定 groupId 时返回该组的成员游标页，不为列表加载全部成员                  |
| `saveReview`     | runId、groupId、keeperArtworkId、expectedReviewVersion、expectedUserId、幂等键；验证保留者属于该完整组，持久化该账户选择并递增版本             |
| `prepareCleanup` | runId、明确组 ID 集合或“全部建议”、冻结结果/审核版本、expectedUserId、幂等键；返回 BUILDING 的稳定 operationId，不在 HTTP 请求内枚举几十万文件 |
| `getOperation`   | operationId、expectedUserId；返回 BUILDING/READY/STALE/FAILED、聚合进度、选中/排除计数及分页预览；阶段四后沿用同一业务 ID                      |

组列表与组详情均默认每页 20 项，服务端上限均为 100；UI 固定按每页 20 项请求。排序键及游标包含稳定 ID，限定到当前 run/版本；客户端不能用其他 run 的游标或组 ID 扩大范围。完整组详情由同一 listGroups 查询的 groupId 和 memberCursor 参数分页，未知或不属于该 run 的 groupId 返回受控错误。

## 保留建议与影响说明

保护查询覆盖所有账户，但返回给浏览器的他人信息仅为“有其他账户整理记录”的资格提示，不能返回他人分数、标记类型/内容、数量或时间。当前账户可查看自己的评分、有效/失效书签和喜欢计数及阅读影响；没有个人数据合并功能。

1. 仅一部作品存在任意账户评分或媒体书签/喜欢时，推荐保留它；失效 MediaMark 仍是整理记录，不能因 mediaId 为空忽略。
2. 多部具有这些手工整理记录时，标为需明确选择，不默认选中移除。用户选择保留者后仍需在清理预览明确确认会移除的整理记录影响。
3. 无此类手工整理记录时，按本账户最近真实阅读时间、最早入库时间、稳定 Artwork ID 推荐。不能把自动进度修正或 lastActiveAt 当真实阅读，也不以他人的私有阅读时间生成可反推的排序。
4. 标题、来源、标签、系列、人工顺序、章节及历史归档差异按需展开；普通阅读历史影响推荐和摘要，不使整批已读作品失去选择资格。

每组默认推荐一部保留，其余是候选副本，不把算法建议等同清理授权。“全部建议”由服务端遍历当前冻结 run 的所有组，使用本账户已保存选择或无歧义建议，跳过尚需人工选择/不具执行资格的项目；返回包括未加载页的实际范围和跳过原因。个人选择与全部建议在结果页只形成选择范围，预览确认仍是后续步骤。

## PREPARE 与冻结文件范围

阶段三注册 `ARTWORK_DEDUP_MAINTENANCE@1` 的 PREPARE 模式，使用 BACKGROUND_WRITER、SYSTEM/900 及第二阶段的分页/reader/让行预算。阶段四才开放 ISOLATE/RESTORE，阶段五才开放 PURGE；未开放模式在服务端拒绝，不能仅隐藏按钮。

PREPARE 冻结结果版本、审核版本、组集合、保留者和副本，分批准备数据库清单。准备中不持有全组维护声明、不隐藏作品、不移动媒体，也不意味着用户已同意实际隔离。根/来源/成员或审核版本变化时标为 STALE；重复请求沿用同一 operationId，新的选择生成新计划版本。准备失败保留诊断与已冻结范围，可按版本重试；不自动扩大选择。

每个候选清单区分：登记原媒体、Image 引用的章节文件、已验证 metaSource/来源快照、已明确审核归属的附属文件。独立目录只在确认独占后有界枚举以发现遗漏；Pixiv 平铺目录按作品身份与精确已知路径建立清单，不能把同艺术家的邻居或整个目录纳入。未知归属文件保持原位，涉及待移除作品的未知内容使该项待人工处理，不能默认勾选。

共享路径、硬链接、符号链接、跨文件系统、来源身份不可靠及未审核的旧归档 revision 返回不可自动执行原因；本版不提供“强制忽略安全条件”按钮。已知独有附属文件可在明确影响审核后纳入，但不表述为已由内容哈希证明存在副本。

最终 READY 计划保存源身份、文件角色、原位置、版本/属性、原媒体内容证据及整理影响快照，服务端按计划内唯一规范路径汇总逻辑字节；不承诺等于释放磁盘空间。计划不设“过了几分钟就自动执行”的机制。隔离提交必须重新核验源、审核与整理状态、认领全局声明并完整重读所选媒体；READY 只说明预览准备完毕。

## 页面状态与验收

正文遵循页面设计稿，不把诊断字段、所有操作或全部媒体缩略图平铺。首次加载使用稳定布局占位；无结果区分尚未检查与已检查无重复；运行中显示一行进度；失败保留已有结果并给重试入口。组详情有加载/重试，跨页选择在底部操作栏显示实际范围。BUILDING 预览可离开页面，重新进入仍从持久状态恢复；READY 提供明确影响预览，STALE 引导重新准备。

| D3-02  | 唯一/多个带评分和标记的副本、失效标记、无标记及真实阅读排序符合规则                  | 服务单元 + 数据库        |
| D3-03  | 其他账户保护生效但不泄漏细节，切换账户与迟到请求不串数据                             | 鉴权 + 组件测试          |

完成相关测试、独立代码审查、修复复审并记录后进入[第四阶段](./04-isolation.md)。浏览器案例留到最终统一验收；设计稿与实际布局不一致时修订或修复并记录原因，不因功能可点就跳过视觉验收。
