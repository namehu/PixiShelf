# 第一阶段：指纹缓存与内容一致性

本文规定第一阶段的开发与验收要求；实际完成情况见[阶段记录](../../records/artwork-deduplication-phase-1-2026-10-23.md)。业务边界、权限、总体流程、角色和阶段门槛以[总计划](../artwork-deduplication.md)为准。本文交付供第二阶段调用的缓存与一致性基础，不提供清理能力。阶段开始前必须完成文档阶段验收。

[共享技术契约](./phase-1-contracts.md)固定核心表与恢复授权、分页接口、根命名空间和上传回执协议。

## 交付与职责

数据 agent 负责正式 migration、缓存/源状态数据访问和事务内守卫；执行器 agent 负责稳定文件读取与作品指纹计算。主 agent 统一接入 App、扫描与归档发布等既有写入口，并检查包依赖：共享数据库能力放 DB 包，契约放 job-contracts，执行器不能导入 Next.js App。

新增表采用延迟填充，不扫描文件、不批量回填哈希。现有 `Image.size` 可为空，`updatedAt` 不是文件版本，`Artwork.mediaRevision` 不能单独表示所有媒体增删。不得复用视觉摘要、阅读分组或视频章节哈希代替原文件 SHA-256。

| 持久对象     | 必须表达的语义                                                                                                        |
| ------------ | --------------------------------------------------------------------------------------------------------------------- |
| 媒体源状态   | 按 Image 唯一保存内容代次和写入状态；即使未生成缓存也可阻止旧证据发布                                                 |
| 文件指纹缓存 | 按 Image 保存当前算法版本、根身份、规范路径、源代次、大小、可用的高精度 mtime/ctime/dev/inode、SHA-256 和实际读取时间 |
| 作品源状态   | 按 Artwork 保存成员代次和写入状态；媒体增删、路径/内容变更或完整替换递增，纯排序/标题修改不递增                       |
| 作品指纹缓存 | 按 Artwork 保存算法版本、完整成员快照签名、文件数量、内容指纹和完成时间；只有完整有效结果能写入                       |

作品源状态另外保存 `mediaEpoch`：整作替换只推进作品 revision 与 epoch，不在一个事务内更新全部媒体；文件缓存绑定本次 epoch。单图写仅推进受影响媒体及作品 revision，其余媒体缓存继续可用。作品缓存保存常数大小的指纹/成员签名/数量，规范多重集合从有效文件缓存按 `(size, sha256, imageId)` 有界读取，不保存无界 JSON 清单。

作品快照只冻结作品版本、epoch 和成员总数；成员页最多 500 条、文件缓存提交最多 100 条。每页及最终发布复核同一作品版本，所有媒体源代次变更必须同事务推进作品版本，因此不能混合不同页版本。新观察与已有缓存的根/路径/属性或 SHA 不一致时，显式 observe 操作 CAS 推进媒体/作品代次并使旧作品结果过期；执行器明确重启该作品聚合，可复用已验证的新文件结果。普通 publish 不隐式更换快照。

文件缓存与作品缓存是可重建派生数据，随所属媒体/作品删除清理；未来清理操作的独立证据不引用它们作为唯一恢复依据。大小、文件属性与代次使用整数安全的数据库与序列化类型，不经 JavaScript `Number` 损失精度。属性缺失显式为空；不能把未知写为零再当相等证据。

## 指纹与读取协议

1. 从服务端媒体根解析已登记 Image 的规范路径；检查根范围、普通文件和符号链接边界。原文件包含 APNG、视频等全部登记成员，不使用阅读器合并后的代表项。
2. 获取实际属性。缓存复用要求算法、根身份、路径、源代次、大小及所有可用身份/时间属性一致，且媒体与作品均非写入中。缓存命中不逐行更新访问时间。
3. 内容读取使用同一只读文件句柄分块 SHA-256，检查实际读取长度、读前后句柄属性，并以最终路径的高精度 `lstat` 与句柄核对 dev/inode 和属性。`realpath` 未变化本身不足以证明未发生原子替换。
4. 非普通文件、零字节、越界、缺失、不可读、属性变化或超出可安全表示的读取范围，均返回明确的未完成原因。不得截断文件后计算摘要，也不得为失败文件生成空哈希。
5. 文件缓存提交在短事务中同时核对执行租约围栏、媒体源代次、路径和所属作品源状态；失效条件影响行数为零时丢弃结果，不降级为无条件 upsert。不能持有数据库事务读取文件。
6. 作品内容编码使用版本化域标识、文件数及按固定字节规则排序的 `(十进制文件大小, 32 字节 SHA-256)` 多重集合，以显式长度编码消除连接歧义。重复成员逐次保留，不用 Set；大小、摘要相同的成员仍计入次数。
7. 完整成员快照另外包含 Image ID、规范路径、源代次和所属关系。发布作品结果前，在统一作品锁顺序下重查完整成员、写入状态和执行围栏；任何增删/替换使本次结果过期。零媒体作品不发布有效指纹。

作品分组以内容指纹筛选后，还需核对规范化多重集合，不建立作品两两比较表。分组内容不含文件名、顺序、标题和用户数据；这些信息用于后续审核。重命名可导致文件缓存重算，但相同内容仍得到相同作品指纹。

属性匹配是增量检测依据，不能识别保留全部可观察属性的任意外部覆盖。完整检查绕过内容缓存。Pixiv 根复用已有持久身份；其他来源由已有受信根配置及本次根属性绑定，不自动创建/确认根身份。根变化后的既有缓存不得静默重绑。

## 写入与回滚衔接

主 agent 建立并审查写入口清单：上传/追加、单图删除、章节媒体删除、整作删除、同 ID 覆写、完整替换、普通扫描及审计发布、本地导入、归档发布、流式优化/无损封装和恢复。任何改变原文件字节或媒体成员的路径都必须接入，不能因为无损封装保留阅读/标记就保留旧字节哈希。

- 写入开始：先取得现有作品锁，在数据库中置写入状态并更新代次，然后才触碰文件；已读到旧文件的任务无法提交。
- 写入成功：完成现有文件/数据库发布协议后，更新受影响媒体和作品状态、使旧缓存不可用，再解除写入状态。未修改的其他媒体缓存仍可复用。
- 已验证回滚：保留原内容和个人数据；源代次保持单调，不倒退，清除写入状态。允许下次安全重算，不承诺复用回滚前缓存。
- 未确认回滚或旧执行未退出：保持不可用状态，进入既有恢复流程；禁止超时自动解锁。
- 纯排序/标题变化：不失效内容缓存。艺术家归属变化由检测 run 的范围核验处理，不把标题和归属塞进原媒体摘要。

既有视频无损重新封装的 finalizer 保留少量同文件系统 rename 与失败 rollback，以维持当前执行围栏和晚到取消协议；持久写入声明必须在进入该 finalizer 及旧产物恢复之前建立。此处不假设文件系统与数据库原子提交，提交失败或恢复不确定时保留声明。哈希、ffprobe、转码和目录遍历仍在事务外，新去重代码不沿用事务内长时间媒体读取。

### App 同步删除的原意图重试

非归档整作删除、单媒体物理删除及章节物理删除使用同账户稳定 `operationId`。首个 unlink 前必须将原选择、成员快照、根身份和逐文件精确身份持久到扫描与 HTTP 排除的恢复区，并持久化对应目录/source gate。失败保留原意图；重新打开既有预览或确认框展示原范围，用户显式重试该 operationId。重试只执行冻结清单，不重新递归加入文件，也不允许改选或账户接管。

每项记录 dev/inode/size/mtimeNs/ctimeNs 和删除状态。未回执但路径已缺失可确认删除；已确认缺失后路径重新出现、文件身份不符、成员变化或无法确认时停止并保留 gate。目录只按冻结目录表尝试 rmdir，后来新增内容自然保留。业务删除与 gate 终结同事务；事务失败可仅重试原数据库提交，完成响应丢失从持久 gate 终态确认，绝不再次 unlink。首次 manifest 与 gate 之间失败使用同一 operationId 补齐，不自动清除遗留文件锁。精确字段和顺序见[共享契约](./phase-1-contracts.md#app-同步删除恢复契约)。

### 尚未入库路径与分块上传

只有 Image/Artwork gate 不足以保护新路径：现有上传直接写正式文件名，块间释放 `.replace-write-lock`，新路径可能尚无 Image；Local/Pixiv 扫描可把暂停中的半文件发布。不得依赖文件属性稳定或仅检查锁目录来证明上传完成。

新增独立于 Image 的目录源状态与逐路径写入声明，按实例受管媒体根命名空间及规范相对目录/路径定位。首字节写入前持久化 token；跨块、失败与进程重启保留，字节与业务发布均确认完成，或已验证回滚后 CAS 结束。一个目录可有多个路径声明，不能由一个文件结束清除其他文件的写入状态；不得通过超时自动解除。现有目录文件锁继续负责实际写操作互斥。分块协议携带稳定上传 session ID，后续块验证所属账户、路径、会话 token、块序号/offset 和声明大小；不得只按路径读取当前 token 就认领其他会话。开始与续传分开，失败后只有同会话续传或经验证恢复可以结束声明。

目录 generation 在写入开始与结束时推进。扫描发现前捕获 generation，所有 Local/Pixiv/App/Worker 扫描与 reconcile 发布在共享锁下复核 generation 未变且相关目录无活动 writer；不把写入中成员过滤后继续 reconcile，否则会误删旧成员。去重捕获、读取与证据发布同样核对独立路径状态。声明持有者自己的发布走独立入口：在目录共享锁下核对自身 token、路径声明版本、会话/执行版本与原声明范围，仅拒绝范围重叠的其他 writer。不相交路径可以独立完成，不能要求 owner 的目录 generation 仍等于开始值；目录 generation 专用于使扫描和读取快照失效。目录范围声明与其内所有路径声明冲突。业务成员提交与结束自身声明在同一短事务完成，不能先解锁再提交。整组替换使用目录范围声明，保护持续至 commit 或已验证 rollback，不能在单个上传文件结束时解除。中断状态使用既有停写核对流程恢复，不自动猜测完成。

上传协议在“字节接收完成”和“业务发布完成”之间保留明确检查点：

- 普通新增路径：最后块只验证实际长度和媒体元信息，记录上传完成 checkpoint，并返回绑定账户、会话、规范路径、声明大小和完成版本的 upload receipt；此时 PATH 声明仍保持活动。随后 `addImage` 或 `batchRegisterImages` 在同一短事务内验证 receipt、登记成员、结束自身声明，不能先释放路径再由另一个请求无条件登记。登记失败可按原 receipt 重试，不能因为浏览器断开而自动解锁。服务端不把客户端返回的尺寸或路径当作完成证据。
- 同 ID 覆写：在最终字节及元信息验证成功后，按自身声明版本提交受影响媒体状态和现有标记失效语义，再完成自身声明。失败或不确定提交继续保持不可用，不能把最后块收到当作旧标记已安全退休的依据。
- 全量替换：`init` 创建 DIRECTORY 声明并返回会话授权；该目录内的并行子上传携带这一授权，为每个规范子路径独立保存 chunk/offset/声明大小及完成 checkpoint。子上传不创建与父声明冲突的独立 PATH 声明，完成任何一个子文件也不结束 DIRECTORY 声明。仅 `commit` 成功原子登记全部成员，或核验原件完整恢复的 `rollback`，才能结束父声明。提交验证每个被纳入成员的子上传 receipt；部分失败时仅明确选定、已经完整验证的子文件可进入现有“忽略失败并提交”流程。所有未纳入或未完成的子路径，在释放 DIRECTORY 声明前必须依据持久子路径清单及文件身份逐项核验，优先移入扫描排除的恢复区并记录移动结果；仅已证明可清理的上传残留允许按精确清单清理，禁止按文件名猜测删除。不能确认残留已安全处置时保留声明并停止 commit，不能在正式目录遗留半文件后解除保护，也不能把残留当作已发布成员。
- 块重试与续传：客户端持有稳定 session ID 和上传凭据；查询 checkpoint 必须验证 Session 所属账户及原凭据，不再根据任意路径的现存文件长度认领续传。每块仅在预期序号、offset、声明大小匹配时写入，完成后持久化实际接收长度。响应丢失时可查询已确认块的 receipt，不能重放写入已完成文件。未确认写入的部分块只有同一会话可以从最后已确认边界重试；保持声明、限制写入范围，不能将磁盘长度直接提升为已确认进度。不同路径各自确认不会结束别的路径声明；目录内出现另一 owner 的重叠声明时拒绝操作。
- 客户端恢复：账户隔离的本机凭据在发起写入前持久化；刷新或组件卸载后仍能用原 session/token 查询自己的检查点。重新选择文件续传时，本机按已保存的逐块 SHA-256 核验已确认前缀，块记录在发送前写入；本机哈希仅用于防止误选文件，不替代服务端 receipt/CAS 或宣称验证服务器全部前缀。缺失本机凭据/前缀记录时禁止通过路径接管。父替换凭据及完成前提交清单持久化，重新打开弹窗可显式接回原会话或请求原会话回滚；提交/回滚响应丢失按原声明版本和持久业务结果幂等返回。终态确认后才删除本机恢复凭据。
- 普通顶层 PATH 的不确定字节写入提供显式“重新上传该文件”，不称为回滚：同账户原 session/token 与当前 declarationVersion 精确 CAS，取得原目录文件锁确认上次写入已退出后，重置 checkpoint 到 0 并推进声明版本，原 PATH/source gate 持续有效。迟到块必须在打开文件前携带并通过新版本校验；不得用缺失授权的请求读取当前版本接管。重写仍限原路径、声明大小与块数，成功登记后才失效原标记并解锁；再次失败保留 RECOVERY_REQUIRED。父 DIRECTORY 子上传不使用该入口，沿用显式整体回滚。锁不会按超时自动抢占，未知存活写入先停止后再恢复。

不在此阶段新增对原媒体的修改行为。失效协议只覆盖现有受控写入；外部写入的边界必须在 UI 与后续清理预检中如实表达。

通过相关静态/单元/数据库检查后，交给未参与实现的子 agent 审查，再修复复审。记录迁移版本、测试提交、样本、结果和限制后，进入[第二阶段](./02-detection.md)。按总计划最新门槛，D1-B01 留到最终统一浏览器验收；其结果不代替 D1-01 至 D1-07。
