# 去重页面设计

本文是[总计划](../artwork-deduplication.md)的界面约束，描述未来行为，不代表功能已经实现。首屏结构和交互可打开[独立原型](./prototype.html)查看。原型使用合成占位封面与示例数据，不读取真实媒体，不连接后端，不持久化修改；原型顶部的场景与主题控制不进入产品页面。

## 设计方向

使用场景是整理大量同艺术家作品。页面只帮助用户完成三个判断：哪些内容相同、保留哪部、其余副本是否进入隔离区。沿用 PixiShelf 的系统字体、蓝色操作和留白；视觉重点是作品行中的保留选择，而非大数字、缩略图墙或统计卡墙。

页面采用 `AdminWorkbench` 与 `PageHeader`，不额外设置装饰性 eyebrow。标题为“检查重复”；艺术家上下文是可返回的链接。信息分三级：页面显示组与当前选择；侧栏显示完整成员和个人整理差异；诊断进一步折叠。常见操作不需要阅读技术字段。

桌面布局：

```text

检查重复
检查结果 3    隔离区 1
─────────────────────────────────────────────────────────
3 组内容相同                         选择全部推荐（2 组）
□ 雨后的沿街散步              3 部 · 每部 500 张    查看差异
  ● [小封面] 雨后的沿街散步       Pixiv       推荐保留
  ○ [小封面] 雨后的沿街散步 副本  本地导入
  ○ [小封面] 雨后的沿街散步 备份  本地导入
─────────────────────────────────────────────────────────
□ 夏日写生                   4 部 · 每部 128 张    查看差异
  有多份整理记录，请先选保留项
  ○ [小封面] 夏日写生             喜欢 3 张
  ○ [小封面] 夏日写生 备份        评分 4
  ○ [小封面] 夏日写生 重复导入

                         上一页   1 / 2   下一页

[ 已选 2 组 · 3 部副本            清除选择    预览隔离 ]
```

手机保留同一顺序：返回、标题及主操作、两个标签、组列表。组内三行按“选择 / 封面 / 标题与摘要”排列；来源和整理提示在标题下合并显示。组操作单独占行，不通过横向滚动隐藏。差异面板和清理预览占满屏幕，操作固定于面板底部。

## 视觉与组件约束

| 项目       | 来源及使用方式                                                                                                                                                                                     |
| ---------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 字体       | `--app-font-sans` 用于标题、正文、按钮；`--app-font-mono` 仅用于操作 ID 和必要的脱敏诊断；不展示真实绝对路径或完整 hash 清单。数量用 tabular-nums，不为页面营造技术外观而全局等宽。                |
| 主色与表面 | `--primary: #006fbe`、`--background: #ffffff`、`--foreground: #333333`、`--muted-foreground: #66727d`、`--accent: #edf8ff`、`--border: #e4e9ed`。正式实现必须引用 token，深色使用既有 `.dark` 值。 |
| 语义色     | 成功 `--success`、需审核 `--warning`、不可恢复操作 `--destructive`；颜色总是伴随文字，不单独表达状态。                                                                                             |
| 字号       | 标题桌面 24/32、手机 22/30；组标题 15/22；正文与按钮 14/22；辅助信息 12/18。常规内容不使用小于 12px 的字号。                                                                                       |
| 尺度       | 内容主要阅读宽度约 1040px，宽屏左右留白；桌面间距 24–32px、组内 12–16px；手机外边距 16px。封面桌面 44×56、手机 40×52，不拉伸原图。                                                                 |
| 容器       | 组列表用细分隔线形成结构，不在每行套卡片。选中组仅作浅蓝底提示；保留单选和标签明确指出保留项。沿用 control/surface radius。                                                                        |
| 图标       | 正式实现使用 lucide-react；原型仅使用同一 1.7px 线宽的内联 SVG。图标按钮有可读名称。                                                                                                               |
| 浮层       | 复用 Sheet、AlertDialog、Tabs、Button 等既有组件。桌面差异侧栏约 480px，清理预览约 520px；手机使用全屏面板和独立滚动区域。                                                                         |

正文不出现 SHA、lease、WAL、根 UUID 等诊断。标题与相对文件名省略时保留完整无障碍名称，详情中允许换行。不得向页面返回真实绝对路径或完整 hash 清单，诊断与复制内容也要脱敏。来源未知写“来源未知”，不虚构来源或导入时间。隐私显示沿用全局隐私偏好，媒体及只读作品名均标记为敏感内容。

## 交互与业务映射

| 用户行为                      | 界面行为                                                                                                                                                                               | 接口与限制                                                                                                                                             |
| ----------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 艺术家页“检查重复”            | 打开 `/admin/duplicates?artistId=…`，沿用艺术家上下文                                                                                                                                  | `getRun`；无有效结果时显示开始入口，不自动读取全部媒体                                                                                                 |
| 开始 / 重新检查               | 主按钮进入检查；更多菜单中提供“完整检查”并简述会重新读取内容                                                                                                                           | `start`，明确普通检查或绕过缓存；同艺术家已有活动任务则回到该任务                                                                                      |
| 查看检查进度                  | 顶部一行“正在检查 320 / 1,000 部”，下方细进度条；无可靠总量时只显示已处理量                                                                                                            | `getRun`；进度与完成均来自服务端，不用定时器伪造百分比                                                                                                 |
| 暂停 / 继续 / 取消 / 失败重试 | 主要控制在进度行；取消放更多菜单，错误显示原因和重试                                                                                                                                   | `control`；处理中等待服务器确认，关闭页面不等于取消                                                                                                    |
| 选择保留作品                  | 每组一个 radio group；只改变保留对象，不隐式选中待隔离范围                                                                                                                             | `saveReview`；保存中只锁该组；失败保留用户选择并标“未保存”，禁止使用该组生成计划，提供重试                                                             |
| 选择隔离组                    | 组标题复选框明确选中整组副本；保留项未确定时禁用并解释原因                                                                                                                             | 选择状态不改变服务端文件；多个有手工整理记录的副本不自动决定保留者                                                                                     |
| 查看全部成员                  | 组分页与组内成员分页各固定 20 项；原型每页仅展示 3 个成员示例，正式面板始终展示当前保留者摘要                                                                                          | `listGroups` 的组成员查询；切页保留选择，不能把未加载成员当不存在                                                                                      |
| 选择全部推荐                  | 明确显示服务端全部推荐组数；不只选当前页，新增结果不会悄悄进入已冻结范围                                                                                                               | `prepareCleanup` 使用结果版本与服务端选择范围，返回组数、副本数和排除项                                                                                |
| 预览隔离                      | 先显示“正在准备清单”；可以关闭，返回后继续查询。准备完成后显示保留和隔离数量、所选作品、整理影响、排除原因；在同一“恢复准备”区域填写备份检查点引用，确认适用于本批次及外部停写后可继续 | `prepareCleanup` 异步返回 `BUILDING` 的 plan/operation ID，使用 `getOperation` 查询；只有 `READY` 版本可隔离，不能在 HTTP 请求内等待全部 manifest 建完 |
| 预览过期或准备失败            | 过期显示“清单已过期”，确认按钮移除，提供“重新准备”；失败保留批次和选定范围，提供重试，不创建重复操作                                                                                   | `getOperation` 返回状态；重建必须重新展示服务器范围和影响，旧停写确认不沿用；作品检测证据也过期时转为重新检查                                          |
| 确认隔离                      | 首版第三阶段只显示预览，第四阶段验收通过后才开放提交                                                                                                                                   | `isolate` 附带计划版本绑定的 `backupCheckpointRef`、批次适用确认及外部停写确认；以稳定 operation ID 展示结果，网络超时先查询同一操作，不重新创建批次   |
| 查看隔离区                    | 按批次列日期、作品数量和当前状态；保留至手动清理，不显示倒计时或“将释放空间”承诺                                                                                                       | `listOperations`、`getOperation`；活动批次独立于最新检测结果                                                                                           |
| 恢复                          | 批次主按钮“恢复”，查看作品与相对文件名等安全位置摘要和冲突；整批结束前保留进行中状态                                                                                                   | `restore`；冲突只提供查看与重新尝试，不提供覆盖现有文件                                                                                                |
| 处理未完成操作                | 按 `originalAction` 显示原动作：隔离失败可继续隔离或安全恢复；恢复失败继续恢复；清理失败显示已清理/未清理，只可复核后继续原授权清理                                                    | `retryOperation` 绑定 operation ID、原动作、版本和冻结范围；不能变为新 purge，不能恢复已删除文件                                                       |
| 允许重新导入                  | 已永久清理批次的详情提供次级入口，明确“允许以后重新导入，不会恢复已删除文件”；确认所选来源后完成                                                                                       | `allowReimport` 仅解除选定来源抑制并推进代次，旧任务不能复活；无源文件时仍需用户重新提供来源                                                           |
| 永久删除                      | 只对完整 `ISOLATED` 批次提供入口；先复核保留作品和隔离清单，通过后显示具体副本与不可恢复后果；通过明确的作品范围、后果说明与单独确认按钮完成确认，不要求输入确认口令                   | `purge`；绑定版本的明确确认，不触发到期自动删除；按钮提交后不可重复创建                                                                                |

全部写接口绑定当前账户与 `expectedUserId`；账户变化立即清除本地选择与详情缓存并重新加载。当前账户的评分、书签、喜欢可具体展示；其他账户只显示“还有整理记录”，不展示人员、数量或内容。

隔离预览的“恢复准备”只维护一处：备份检查点字段接受可识别名称或 ID（原型默认是明确标注的示例引用），不上传备份、不读取 URL，也不宣称应用验证过备份。检查点适用确认和外部停写确认默认不勾选；只有 `READY`、版本一致、引用非空且两项确认完成，才能隔离。重新准备或计划版本变化须清空确认，重新核对范围；引用随确认一同记录为审计证据，不替代备份恢复验证。

“有整理记录”是保护提示，不等于该作品必然不能清理。多个有整理记录的副本必须明确选择保留项，并在预览中确认所选副本的整理数据不会自动合并；隔离中保留这些数据，只有永久清理后才随作品删除。

## 状态与文案

| 状态                  | 最少信息和下一步                                                                                                                                                             |
| --------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 首次进入              | “还未检查”，主按钮“开始检查”。                                                                                                                                               |
| 加载                  | 保持标题与标签稳定，用 2 组骨架占位；区域 `aria-busy`，文字“正在加载检查结果”。                                                                                              |
| 检查中 / 已暂停       | 一行进度、暂停或继续、取消入口；继续显示上一份结果时注明“上次结果”，进行中结果不可直接用于清理。                                                                             |
| 完成无重复            | “没有找到重复作品”；补充“已检查 1,000 部作品”，保留重新检查入口。                                                                                                            |
| 检查失败              | “检查中断”，显示可操作的原因，例如“媒体目录暂时无法读取”；主操作“重试”，诊断折叠。                                                                                           |
| 需审核                | 组内“有多份整理记录，请先选保留项”；显示具体己方整理提示。                                                                                                                   |
| 清单准备中 / 准备失败 | “正在准备清单”，不能隔离；失败显示“清单准备失败”及重试入口。关闭面板后任务仍可查询。                                                                                         |
| 清单过期              | “清单已过期”，重新准备后再次审核范围与停写确认，不能自动提交。                                                                                                               |
| 结果过期              | “作品已变化，请重新检查”；禁用隔离，不让确认按钮变成自动接受新范围。                                                                                                         |
| 已隔离                | “已隔离 · 2 部作品”，主操作“恢复”，批次详情提供永久删除。                                                                                                                    |
| 隔离 / 恢复 / 清理中  | 显示动作与已处理数；禁止并发再次操作，离开页面不打断后台执行。                                                                                                               |
| 恢复冲突              | “原位置已有文件”；冲突列表放详情，只提供继续恢复和诊断，不覆盖、不发起新永久清理。                                                                                           |
| 需要恢复处理          | `RECOVERY_REQUIRED` 必须结合 `originalAction`：ISOLATE 可继续原隔离或安全恢复；RESTORE 继续原恢复；PURGE 展示已清理/未清理，只可复核后重试原授权清理，不提供恢复或新 purge。 |
| 网络失败              | 保留已加载内容、选择和滚动位置，局部显示“加载失败，重试”。                                                                                                                   |

原型场景选择器覆盖结果、首次、空列表、加载、检查中、暂停、失败、需审核、结果过期、清单准备中/失败/过期、已隔离、恢复冲突、隔离失败、恢复失败、清理部分失败及保留作品变化；顶部明确注明全部数值是示例。

### 未完成操作的动作矩阵

| 原动作    | 主要操作                                                      | 可选操作                                       | 禁止                                 |
| --------- | ------------------------------------------------------------- | ---------------------------------------------- | ------------------------------------ |
| `ISOLATE` | 继续原隔离                                                    | 在未发生清理且服务端确认可恢复时安全恢复、诊断 | 新建 purge、忽略未完成文件步骤       |
| `RESTORE` | 继续原恢复；路径冲突保持停止                                  | 诊断                                           | 覆盖文件、新建 purge                 |
| `PURGE`   | 复核原授权、保留者和未清理文件后，`retryOperation` 继续原清理 | 查看已清理/未清理及诊断                        | 恢复已删除文件、扩大范围、新建 purge |

清理失败不能复用“恢复冲突”页面。它明确展示不可恢复的已清理项，未清理项保留原约束；主按钮为“复核并重试原清理”。入口、详情页、诊断页和最终确认均使用同一动作矩阵。原型分别提供这三类失败场景，按钮与最终确认同时检查原动作、状态、版本及原授权范围。

## 键盘、手机和性能

- Tab 按阅读顺序移动；radio 使用原生键盘方向键；Tabs 支持左右键切换。所有操作可由键盘完成，有可见焦点。
- Sheet/Dialog 约束焦点；Tab/Shift+Tab 在可见且可用的控件间首尾环绕，不把焦点送往浏览器工具栏，跳过隐藏、禁用和未选中的同组 radio。Escape 保留关闭行为，关闭后回到触发器；清理确认页默认聚焦标题或取消，不默认聚焦破坏性按钮。
- 图标按钮、复选框所在标签、单选所在标签、分页按钮实际命中区域至少 44×44px；不靠放大 16px 图标伪装触控区域。
- 手机全屏面板使用 `100dvh`，正文独立滚动；底栏留出 `env(safe-area-inset-bottom)`。产品页浮动操作栏在 `--app-mobile-navigation-offset` 之上，底部内容增加等高留白，防止遮挡分页。
- 组和成员分开分页，列表不预加载原媒体、不绘制全部 500 张内容；封面只请求现有缩略图。长列表控件不通过嵌套滚动形成滑动陷阱。
- 默认无装饰性动效；面板沿用 180ms 动效，减少动态效果时关闭。状态通过 live region 简短宣告，不每秒打断读屏。
- 浏览器原型验证与业务代码验证分别记录。原型的暂停、恢复、清理只切换内存示例状态，不作为后端功能证据。预检示例包含未检查、检查中、通过和失败；“保留作品已变化”场景必须阻断确认，不能固定显示复核通过。
