# PixiShelf 产品基线

PixiShelf 是面向个人重度媒体收藏者的本地优先、自托管归档、整理、检索与浏览系统。外部站点提供输入和来源证据；本地数据及用户整理结果应在来源失效、刷新或系统升级后仍可理解、可维护、可恢复。

本文只维护长期能力和约束。具体交互与验收条件见[领域功能目录](../features/README.md)，实现机制见[当前架构](../architecture/current-architecture.md)，发布日期和验证结果见各功能链接的记录。`current` 表示反映当前代码，不等于生产已部署。

去重专用直接删除的开发分支流程为：同艺术家四种作品来源及混合组在完整登记原媒体一致时，经服务端冻结预览和一次不可恢复确认后逐文件原地删除，整理不合并；不提供隔离或撤销。普通 URL 归档删除继续回收。现行能力与验收状态统一见[作品去重](../features/artwork-deduplication.md)，不能由开发分支实现推定生产已部署。

## 用户与核心工作

首要用户是长期收藏图片、动画和视频，并愿意维护 Linux/NAS/单机 Docker Compose 服务的个人收藏者。桌面优先承载复杂管理，移动端优先保证浏览和轻量整理。

当前部署是单一信任域：可以有多个账户，但已登录账户均具有实例管理员能力；账户阅读记录、评分和偏好独立，并不代表提供不可信用户或租户间的权限隔离。认证边界以[权限与接口边界](../security/access-control.md)为准。

核心工作依次是：发现并导入 → 建立本地目录 → 浏览与整理 → 核对和更新来源 → 维护、删除与恢复。维护工具必须帮助用户解释每一步的状态和结果，不能要求浏览器持续在线才能完成工作。

浏览体验的性能改进不能改变阅读事实：预加载不算阅读，手工完成不增加真实访问，来源外链不计入本地阅读。完整替换或重建媒体使旧阅读状态失效，普通增删和排序保留仍存在的媒体记录。

[作品评分](../features/artwork-rating.md)是个人整理数据，与爱心和“我的喜欢”共用一个状态；来源刷新、同作品内媒体替换及回收不清除个人评分，不提供公开平均分。

[单图书签与喜欢](../features/media-marks.md)是独立的账户媒体标记，不改变作品评分或阅读事实。书签和单图喜欢可同时存在；媒体删除或替换保留可清理的失效条目，作品永久删除时清除对应标记。

## 产品不变量与取舍

1. 外部站点 ID 只有结合 Provider 才有意义，不能作为全局本地 Artwork 身份；创建方式不能证明来源。
2. 原媒体、来源映射、本地覆盖及用户整理属于不可轻易替代的数据；来源刷新只更新有证据属于该来源的内容，不静默覆盖人工决定。
3. 未完整验证的归档 revision 或派生媒体 generation 不得暴露给正常浏览；文件存在不等于已发布。
4. 删除、替换、迁移与恢复须有明确意图、审计及恢复依据。数据库、文件、配置和镜像按兼容检查点共同恢复。
5. 长任务不得依赖浏览器连接或 App 进程内临时 promise。当前生产稳态只有一个通用 Worker，解析、归档下载、正式发布/维护分三条通道，各自有效并发 1；下载仅写隔离 staging，正式发布与其他媒体任务在 writer lane 内串行。此约束不覆盖 App 的直接文件写入，文件变更也不受数据库执行围栏或回滚保护；维护停写须覆盖全部写入者。
6. 可重建的缩略图和派生媒体不得成为原媒体唯一副本。
7. 当前事实、未来设计和历史证据明确分开；实现核验与生产验收各自记录。

发生冲突时依次优先：数据完整与恢复 → 身份、来源与整理语义 → 可观察及可控任务 → 浏览和管理可用 → 性能 → 视觉体验 → 新来源及功能数量。性能和 UI 改造均不得绕过身份、权限、事务和发布规则。

## 支持与演进边界

当前支持单实例、单一信任域，使用 Docker Compose/NAS/Linux、PostgreSQL、宿主文件系统、ImgProxy 和单通用 Worker，经受控反向代理与 HTTPS 供现代浏览器访问。

现阶段不承诺多租户与复杂角色、公开社区与内容分发、稳定完整开放 API、Kubernetes 或并行消费者集群、底层备份系统替代品、所有外站永久抓取兼容，或原生移动和桌面客户端。扩展这些边界须先更新本基线，并对架构和数据影响建立规格或 ADR。

用户数据与可恢复性高于旧内部接口兼容。数据库变更使用正式 migration；扩展、切换、观察与清理分阶段进行，破坏性清理不与新功能切换绑在同一个不可回退发布中。

改变用户流程、跨包契约、数据生命周期、异步并发或恢复机制的工作，应先明确正常与异常路径、数据／权限／任务影响、迁移与回滚、可执行验收。普通样式、文案和边界明确的局部修复不需要另写 PRD。交付时更新对应当前章节，验证过程写入记录，不在本基线追加迭代日志。
