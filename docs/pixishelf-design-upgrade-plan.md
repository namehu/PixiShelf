# 界面升级候选计划

此文保留尚未逐页重新核验的视觉改造方向，不充当当前路由、组件或交互规范。旧提案的阶段清单不能证明某个页面仍未改造；启动下一阶段前先查当前代码和功能规格。[原始提案](./archive/design/ui-upgrade-plan.md)保留完整配色、布局取舍和当时的工作分解。

## 保留方向

- 保持蓝白主色、内容优先的个人收藏界面，作品提供主要视觉信息；强调色用于操作、选择和焦点。
- 浏览区以内容、留白和分隔组织信息；管理区保留紧凑表格、表单与必要面板。
- 桌面优先复杂管理，手机优先浏览、导航、筛选和轻量编辑。
- 文字默认可选择；真正控件和拖动把手按需要禁选，ID、路径和日志提供明确复制入口。
- 使用现有组件及语义 token，先审查定制差异，不以视觉统一为由改动业务、认证或媒体生命周期。

## 下一次实施如何切片

1. 核验实际页面与当前规格，选择一个具体用户流程，记录改造前问题和验收标准。
2. 先统一该流程依赖的基础 token、导航与共享控件，再改页面，避免全站同时重排。
3. 浏览流程校验图片、动画、视频、阅读和隐私状态；管理流程校验分页、选择、冻结预览和持久任务恢复。
4. 同步真实改动涉及的功能规格；已完成事项退出计划，测量与发布证据进入 records。

全站深色模式、原生客户端和业务契约改造不由本视觉计划授权。测试层级按[测试策略](./development/testing-strategy.md)，产品约束按[产品基线](./product/product-baseline.md)。
