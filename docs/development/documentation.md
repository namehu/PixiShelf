# 文档维护

文档服务于下一次理解、修改和恢复。已有主题优先更新对应章节；只有独立职责或复杂流程确实需要时才新增文档。阅读入口见[文档索引](../README.md)。

## 内容放在哪里

| 内容                               | 维护位置               | 不在此重复维护                 |
| ---------------------------------- | ---------------------- | ------------------------------ |
| 用户、能力、非目标、不变量         | 产品基线               | 页面参数、任务清单、发布结果   |
| 统一业务词汇                       | 根 CONTEXT             | 产品承诺、详细数据库字段       |
| 组件、依赖、数据流、事务与恢复机制 | 当前架构及子系统架构   | 调试流水账、完整接口定义       |
| 用户行为、业务异常、验收条件       | 功能目录中的领域规格   | 所有公共安全和部署规则         |
| 鉴权、信任头、媒体与基础设施权限   | 安全边界               | 完整业务接口实现               |
| 标准部署、备份、恢复               | 运维基线和专项 runbook | 某次生产事故现场               |
| 为什么选择此方案、代价及替代关系   | ADR                    | 持续更新的实施状态             |
| 某版本在某环境得到什么结果         | records                | 没有环境、版本或证据的“已通过” |
| 已退役设计与切换过程               | archive                | 当前操作指令                   |

一个事实只维护一份详细正文。其他文档保留必要摘要和链接。字段、类型、默认值、任务能力数量首先链接 Schema、契约或注册表；确有必要展示的稳定业务阈值必须指明代码依据。

根 TODO 只留未完成行动。已完成过程移到记录，局部样式和明确的小修复不需要创建长设计稿。包级、组件和工具用法继续与实现共置。

## 状态与核验

当前正文使用 `status`、`scope`、`last-verified` 和 `sources`。`last-verified` 表示实际核验范围内的日期，不能因格式化就刷新。局部改动注明局部核验范围，避免暗示全文重新审计。

- `current`：描述已经核对的当前实现，不承诺特定实例已部署。
- `draft`：未来方案或尚未足够核验的内容；把已确认事实与待定部分分开。
- `historical`：当时的设计或证据，保留适用日期、版本与限制。
- `deprecated`：短兼容入口，提供当前正文与必要的历史去向。

ADR 保留原决策及历史背景，用新 ADR 或明确的局部替代关系说明演进，不把旧决策中的版本和数字全量改成今日值。

代码已实施且已核对，但缺少生产验收时，正文可以是 `current`；生产状态交给对应记录。用户确认上线、原始审计输出、隔离数据库通过和浏览器测试通过是不同证据，不能互相替代。缺失生产材料只能写“尚未登记/未核验”，不能据此认定部署失败或成功。

## 正文与证据模板

功能或子系统正文按以下顺序组织，可按主题省略不适用部分：

1. 本文负责什么、关联的权威文档是什么。
2. 当前概念、参与者、正常流程与业务不变量。
3. 并发、失败、取消、恢复及权限差异。
4. 验收条件与代码/测试入口。
5. 发布、实验、迁移证据的链接。

记录至少说明：**日期与适用版本、验证环境与样本、执行内容、结果、限制、证据位置**。沿用旧记录时不得补造缺失的提交或镜像 digest。路径、哈希、计数和失败输出在确有诊断价值时保留；不复制密钥、环境文件正文或私人媒体。

迁移手册首屏说明源版本/数据库状态、目标、停止条件和恢复单位。历史手册不能成为当前正常启动的必读步骤；仍适用的门禁必须提炼到当前 runbook。

## 图示

- 每张图回答一个问题：组件图表达职责，类图表达关系，时序图表达调用和事务，状态图表达转换，泳道图表达责任交接。
- 当前独立图源存放于 `docs/diagrams/`，以 `.mmd` 为编辑源，SVG 由渲染命令生成。正文同时提供图片与源链接；入口见[图示导航](../diagrams/README.md)。
- 图与权威正文绑定，图旁提供代码依据。其他正文引用，不复制另一套图源。
- 图中注明系统/进程边界、异步任务和失败路径；不能把文件存在等同发布成功，不能把浏览器 Worker 等同后台 Worker。
- 不画全量数据库字段或硬编码易变任务数量。历史内嵌 Mermaid 保留历史语义，不充当当前图。

## 修改后的检查

从仓库根目录执行：

```bash
pnpm docs:check
pnpm docs:diagrams
pnpm docs:diagrams:check
git diff --check
```

`docs:check` 检查 Git 管理及未忽略的新 Markdown 的本地文件链接、标题锚点、大小写和代码围栏，忽略代码示例与外部 URL；不验证外部网站或自动判断事实正确性。技能及编辑器规则目录不在检查范围。

图示命令复用 WebP 包已有的 Mermaid、esbuild 与 Playwright；Windows 默认使用 Edge，其他平台使用已安装的 Chromium，可用 `WEBP_BROWSER_CHANNEL` 选择已有浏览器。`docs:diagrams:check` 解析图源并检查 SVG 中的源哈希，内嵌 Mermaid 只检查语法；视觉可读性仍需打开成图检查。无浏览器时明确记录未完成，不能把纯文本检查说成渲染成功。

仅对本次变更的 Markdown/脚本运行 Prettier，不运行全仓库格式化。文档路径调整后用 `rg` 检查代码、测试、脚本和图源对旧路径的引用，运行受影响测试；操作命令变化须核对脚本或解析 Compose，不能通过实际生产操作“验证文档”。验证范围遵循[测试策略](./testing-strategy.md)。

多人并行时先约定文件归属，公共入口由统筹者维护。汇总后统一核对跨领域事实、内部链接和图示；任何人都不覆盖别人的未协调修改。
