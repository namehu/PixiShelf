# 去重直接删除运维

本文描述已实现后端所需的部署和故障处置，不代表某个实例已经部署或新删除已开放。交付状态见[第三批记录](../../records/artwork-deduplication-direct-delete-batch3-2026-10-24.md)及[总计划](../../design/artwork-deduplication.md)。功能只删除已确认的精确文件，保留空目录；普通归档回收流程不受替代。

## 升级与开放

1. 按[备份基线](../backup-and-recovery.md#发布前一致性检查点)建立数据库、原媒体、派生媒体、Pixiv数据和配置的同点检查点。记录旧/目标版本及可验证的恢复依据；删除日志不能恢复媒体。
2. 停止旧 App 和 Worker 的写入与外部同步，使用目标版本的正式 `db:generate`、`db:deploy` 流程。禁止 `db:push`。直接删除的原增量迁移为 015–018；完整包含另有 `20261025000100` 至 `20261025000500` 五个迁移，新增关系与约束、统一结果视图及扫描 v2 能力，并保留原任务状态保护。迁移不扫描媒体；旧预览保留旧目的及空授权字段，不会自动获得新权限。
3. 疑似版本另需 `20261025000600_artwork_dedup_visual` 正式迁移，新增视觉缓存、作品对/页证据及协议约束，不在迁移中读取媒体。部署目标 Worker，核对健康、READY 与 `audit:capabilities`：F01 部分重复另需 `20261026000100_artwork_dedup_partial`，为既有配对增加关系类型（旧行为 VISUAL）、扩展统一结果视图与约束，不重读媒体。扫描任务保留 v1/v2/v3/v4/v5，维护任务保留 v1/v2/v3/v4/v5。新 App 开始或重试要求 READY 扫描 v5（F03 分段协议），新维护使用 v5；精确确认协议 1、包含协议 2、疑似版本协议 3、部分重复协议 4。旧 Worker 不能通过更改任务版本代为执行。
4. 再部署配套 App，核对新的服务端能力状态和真实 Session。独立开关 `ARTWORK_DEDUP_DIRECT_DELETE_ENABLED` 是版本级开放决定，不是客户端参数；原 release stage 不授予新删除权限。未通过最终验收的版本保持关闭。
5. 使用可销毁的小样本走完检查、预览、一次确认、删除记录。验证保留者可读、选定副本不可读、文件与记录相符，再由实例管理员按实际备份和停写条件使用真实图库。开发合成库的迁移证据不代替生产备份演练。

F02 关系复用另需 `20261026000200_artwork_dedup_relation_cache`：只为已有检测表增加可空摘要、候选证据与默认零计数，旧结果不回填，也不读取媒体。先部署迁移，再生成／部署与 Schema 一致的 App 和 Worker；不要让新 Prisma 客户端连接未迁移的旧库。该优化不新增扫描任务或删除确认协议。兼容性检查仍按上述任务／删除协议执行；历史关系缓存缺失或版本不符时重新比较，不通过手填摘要或完成标记“修复”缓存。

F02 相同内容共享视觉特征另需 `20261027000100_artwork_dedup_shared_visual_cache`，为既有媒体视觉缓存增加可空内容 SHA、大小及索引。不新增业务表、不扫描或回填媒体，旧缓存仍能按自身身份命中。遵循同样的先迁移、后生成／部署 App 和 Worker 顺序；检测及删除协议不变。不要手填内容键：只有成功且已核验的特征才能成为共享供体。缓存不兼容或供体缺失时正常重算；完整检查绕过全部视觉复用。本批为加法迁移，回退程序时保留新增列与索引，不为撤回优化去删缓存字段；删除维护中的版本约束仍适用。

F03 分段检索另需 `20261027000200_artwork_dedup_visual_batches`：新增 run 检查点、item 复用摘要、run 所属 posting／候选工作表及媒体查询索引。不读取原媒体，不改旧检测结论或删除授权。先迁移，再部署支持扫描 v5 的 Worker，最后开放配套 App。活动 v5 任务不能交给旧 Worker，也不能手改为 v4；需暂停时通过原领域入口，保留检查点、工作表和配套执行器。加法字段和表保留至正式退役迁移，不为回退程序直接删表。正常历史清理只级联该 run 的工作状态；不要把永久视觉缓存或删除证据当临时工作表清理。1 万原件的公开上限保持不变，10 万／50 万验收另行完成。

命令及部署配置以[部署基线](../deployment.md)和目标版本包脚本为准。App 与 Worker 必须连接同一目标数据库及对应媒体根；不要为使检查通过而修改根身份、执行版本或删除保护行。

初始版本审核兼容修复需要 `20261027000300_artwork_dedup_legacy_review`：通过正式 `db:deploy` 替换审核查询函数，不改表、不回填源记录或历史结果，也不授予删除权限。仍须先完成迁移，再部署配套 App 与 Worker；只更新镜像而未迁移会继续显示旧审核误判。已完成且指纹仍有效的历史结果刷新即可重新校验，已标记 `CHANGED` 的旧检查需重新发起。回退应用时保留已应用迁移及历史证据，旧代码可能再次拒绝初始版本作品；不要手改完成状态、补造版本记录或跳过删除复核。具体验证和限制见[初始版本上下游修复记录](../../records/artwork-deduplication-legacy-review-2026-10-27.md)。

## 每次删除的外部停写前提

用户确认前停止所选目录的同步、下载器及其他外部编辑，并持续到操作终结。应用内部声明会阻止冲突写入，但不能控制主机上的其他程序。原生文件操作固定目录句柄、核验身份并同步回执；POSIX不提供同一目录内文件名与inode的条件删除原子操作，不能承诺抵御违反停写前提的外部换名。

预览阻断的共享文件、硬链接、符号链接、未知附件和未验证归档历史原件，不应通过手改manifest或删除证据来放行。处理实际来源/文件问题后重新检查和准备新预览，重新确认范围。

## 停止、失败与重试

| 现象                         | 处置                                                                                                                             |
| ---------------------------- | -------------------------------------------------------------------------------------------------------------------------------- |
| 尚未产生删除意图             | 页面请求取消；等待Worker完成退出与取消收口，不把请求已发送当作已完成。                                                           |
| 已开始删除或部分失败         | 请求停止只在安全边界停下；已删文件不可撤销。副本保持隐藏，声明和原清单保留。排除故障后只能复核保留者并继续原范围。               |
| 保留者内容变化、丢失或损坏   | 不继续删除，不手动放宽校验；保全剩余文件和日志，由管理员核对备份及实际内容。                                                     |
| 文件已删但回执未提交         | 保留原意图。兼容Worker重试会按原身份、范围和目录同步证明对齐；不要手动把文件标为成功，也不要重建不同范围的新删除任务。           |
| 读取进程遗留或退出未确认     | 沿[读取进程恢复手册](./media-content-recovery.md#去重读取进程遗留占用)确认进程实际退出。租约超时、任务失败或kill请求不等于退出。 |
| 历史归档任务缺少原始来源证明 | 保留原任务和检查点，按错误提示发起新的导入意图；不要给旧任务手工补签当前来源代次，或把旧任务改成新版本强行重放。                 |
| Worker离线或版本不兼容       | 恢复配套Worker和能力注册，再使用领域入口；不能在通用任务中心直接重放或修改payload。                                              |
| 新文件占用了原路径           | 保留现场并停止；不覆盖、不吞掉新占用。检查确认范围和外部停写是否仍成立。                                                         |

删除完成后来源墓碑继续阻止重扫与旧发布复活。详情中的“允许重新导入”只允许未来的新输入，会推进来源代次；不恢复原文件，不允许旧任务继续发布。本地手工作品没有可发现来源时，不提供伪造的来源解除项。

## 降级与证据保留

存在未终结的直接删除操作时，不得降级为不理解其维护任务版本、确认协议、声明或原意图的旧 Worker；包含操作需要兼容协议 2，历史疑似版本需要维护 v4 与确认协议 3，新维护为 v5，部分重复需要维护 v5 与确认协议 4。停止业务推进后保留兼容执行器、数据库和日志，按原操作处置。旧扫描 v1 不含包含关系，v2 不含视觉检查，v1/v2/v3 均不含部分重复，未开启的能力不能视为已排除。已 unlink 的文件不能通过换镜像或数据库事务回滚恢复，只能走独立、经验证的备份恢复流程。

视觉预算耗尽属于疑似阶段未完成，不通过放宽 SQL 条件或强改状态绕过。首版每次最多 10,000 个登记原件、每作品/配对最多 2,000 个文件，并有索引与比较预算；完整检查会重新读取有效原图。疑似结果是人工取舍工具，不提供无码判定、无损承诺或批量授权；没有真实版本样本的验证不能当作生产识别率。

操作快照、逐文件意图和回执、必要审计及来源墓碑必须独立保留。禁止随作品删除、普通检测历史清理或普通归档到期清理一起移除。诊断对用户只给必要状态和脱敏原因，不在公开记录中写入绝对媒体路径、凭据或他人的私人整理内容。
